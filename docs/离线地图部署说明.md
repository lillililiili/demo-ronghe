# 离线地图部署与更新

## 当前实现

MapLibre GL JS + PMTiles 本地矢量底图，浅色、二维、北向上。主站和 `#/bigscreen` 共用 `MapView`，保留 Canvas 业务绘制与现有 Mock，不需要业务后端、数据库、高德 Key 或公网连接。天气标为演示数据。

“离线”指资源在内网，不代表地图简陋。若出现黄色提示，则是详细底图加载失败，当前仅为简化示意图，可点击重试；示意边界不能作为精确行政边界使用。

初次打开和点击复位时，按容器宽高及 PMTiles 包内覆盖范围自动调整缩放，使视口始终落在有数据的范围内。缩小到最大可视范围后不能再缩小，平移也被限制在该范围内，避免露出范围外的灰色空白；未操作地图时，窗口大小变化也会重新适配。

## 本地启动

1. 仓库已包含 `map-data\dongying-dev`，正常 `git clone` 会取得地图包、样式、完整字体、图标、许可证和校验清单。
2. 进入 `dongying-vue/` 执行 `npm install`、`npm run dev`；修改 Vite 配置后重启开发服务，避免仍访问旧进程。
3. 开发服务优先使用仓库根目录的 `map-data/`，并兼容仓库同级的旧外置目录。换目录时在启动终端设置 `$env:MAP_DATA_DIR='D:\map-data'`，然后启动。它是进程环境变量，不注入浏览器，不读取 `.env.local` 中的密钥。
4. 在 `dongying-vue/` 下 `npm run build` 仅构建前端，引擎及 Worker 随包发布；地图数据不进入 `dist`。`npm run preview` 也支持上述外置目录。

## 内网部署（只需静态服务器）

- 前端：将 `dist` 放到站点根目录。
- 地图：将独立 `map-data` 文件夹映射到同一站点 `/map-data/`。
- 配置：`dist/map-config.json` 指向 `/map-data/dongying-dev/manifest.json`。换地图地址可直接修改此文件，无需重新构建；跨主机资源请由同源静态代理提供。
- Nginx 示例：`deploy/nginx-offline-map.conf.example`。
- IIS：启用 Static Content，新增名为 `map-data` 的虚拟目录，指向外置目录；使用 `deploy/iis-map-data.web.config.example`。若父站点锁定配置项，请管理员在父级配置，不要放宽整个站点权限。
- 地图目录只需读取权限。禁止目录浏览；地图缺失必须返回 404，不能落入 SPA 的 `index.html`。PMTiles 禁用传输压缩，必须返回正确的 Range / HTTP 206。
- 浏览器需支持 WebGL2、Worker 与现代 JavaScript。严格 CSP 环境需允许同源脚本/样式/字体/图片/连接及 Worker；部署到非 localhost 内网地址时建议 HTTPS，并在甲方目标浏览器实测。

验收服务器：

```powershell
curl.exe -I http://站点/map-data/dongying-dev/manifest.json
curl.exe -s -D - -o NUL -H "Range: bytes=0-126" http://站点/map-data/dongying-dev/dongying-20260902.pmtiles
```

第二条应返回 `206`、`Content-Range: bytes 0-126/21956009`、`Content-Length: 127`。若返回 200、HTML 或 404，先修正静态目录配置。不要使用 `file://` 双击打开项目。若 `localhost` 与 `127.0.0.1` 表现不同，检查是否有两个新旧 Vite 进程分别监听 IPv6 和 IPv4。

## 开发数据与更新

- Protomaps 2026-09-02 数据，tileset 4.15.2；官方 basemaps 5.7.2 浅色中文样式及 v4 图标。
- 范围 `[117.914, 36.737, 119.508, 38.356]`，WGS-84，Z0–Z15。允许放大至 Z18，但不会增加地物细节。低级别瓦片可能含范围外概览，精细区域以裁剪范围为准。
- 主包 `dongying-20260902.pmtiles`：21,956,009 字节。加上完整简体中文字体后资源约 42 MB，精确文件尺寸与 SHA-256 见外置 `checksums.json`。
- 许可、来源及版本见 `SOURCES.txt`、`sources/` 和 `fonts/OFL.txt`。保留 OSM/Protomaps 署名。仅为开发数据，生产数据授权、审图及甲方环境适配仍需确认。
- 更新时使用新目录/新文件名，先校验后切换 `map-config.json`，保留前一目录可快速回退，不要覆盖正在读取的 PMTiles。

重新准备同版本：从官方 `go-pmtiles` releases 下载 CLI，下载 `basemaps-assets` ZIP 并解压，用官方样式导出接口获得 `5.7.2 / light / zh-Hans` JSON。还需把 Noto CJK `Sans2.004` 发布版的 `Sans/SubsetOTF/SC/NotoSansSC-Regular.otf` 放入新包的 `fonts/`，保存其许可证到 `sources/`，再运行：

```powershell
node dongying-vue/tools/extract-map.mjs C:\tools\pmtiles.exe D:\map-data\dongying-new\dongying-20260902.pmtiles
node dongying-vue/tools/package-map.mjs C:\tools\pmtiles.exe D:\map-data\dongying-new\dongying-20260902.pmtiles C:\tools\basemaps-assets-main C:\tools\style-original.json
```

提取工具固定官方版本，只做东营范围 Range 请求，含临时错误重试，不下载全球包。更新版本需同步核对脚本内版本、样式兼容性及来源清单；字体/图标许可证也应保存到 `sources`。备图工具不需要部署到甲方服务器。

## 业务后端接入边界

继续由页面将业务数据传给 `MapView.setData({ devices, targets, airspaces, alarms })`。地图和业务接口独立：后续仅替换业务数据来源，保留 WGS-84、原数据结构与状态机。地图包不是业务 JSON，行政区 GeoJSON 也不能替代含道路、建筑等信息的 PMTiles。

现有高德配置和旧图片瓦片仅保留，不再运行。历史高德文档描述旧方案，本说明描述本次实际实现。
