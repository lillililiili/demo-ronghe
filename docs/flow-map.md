## 手动反制入口（2026-09-17 后续确认）

当前未配置自动反制规则，告警详情 → 处置进度 → 反制授权统一提供“手动反制”。读取当前事件、授权及急停状态，依据后端 `can_direct_counter` / `can_request_counter` 决定进入直接反制确认或申请审批；不从通知送达、自动移送或风险评分推定反制许可。

后端要求补充联系或现场事实且 `can_write` 允许时，从同一按钮打开按需依据表单：现场核查、已发生的人工联系或紧急处置依据。目标情况与危险度不预填为高风险；紧急处置需明确选择并说明依据。保存沿用事件版本与幂等键，只追加事实，回读最新资格后由人工再次发起。联系、观察、授权与设备执行保持独立事实，不恢复已删除的现场记录整块，不触发手动处罚移送。

未核实、无权限、已有活动授权、急停未确认或读取异常保留原因与授权查看入口。保存版本冲突先回读；结果未知保留原提交内容及幂等键；切换事件、退出或更换登录会话时阻止旧表单继续提交。刷新与重新登录只读取服务端记录，不自动反制。真实设备执行与回执仍使用既有后端流程，本轮没有新增自动反制策略。

## 处罚部门通知（2026-09-17）

已提交处罚交接 → 查看“处罚部门通知” → 未发送或明确失败且后端允许时确认通知 → 同一交接追加一次投递及接收资料 → 分别显示送达、签收回执和时间。已提交但结果未确认、已经送达或签收时仅查询，不重复发送。查询不催回执，不等于处罚办结；案件结果继续独立展示。 列表、详情分别呈现送达与签收，筛选传递各自后端状态；“已送达 / 回执超时”可以同时成立。当前本地处罚接收方已配置明确标识的模拟渠道，真实通道仍未接通。

发送前核对交接及来源权限、原材料、接收方、通道、原尝试次数和幂等键；原冻结材料与历史通知不回写。超时、退出或服务重启不制造成功，保留原尝试供查询。当前仅支持明确标识的本地模拟通道，真实通道仍未接通。接口与迁移见[交接契约](backend-stage5/workbench-handoff-api-contract.md)。

## 合法性研判：复核筛选（2026-09-18）

复核下拉统一为“全部、待复核、已确认、已驳回、已改判”。“待复核”仅请求 `needs_review=true`，即后端判定仍需人工处理；不以数据库初始 `PENDING_REVIEW` 代替，系统已可靠自动判定的记录不得因此混入。旧“未人工复核”入口合并到“待复核”，兼容旧页面保留值；已完成复核继续按真实复核状态查询。

下拉与当前页签、区域、计划取交集，列表、分页与统计同源；“全部”仅清除复核条件，不清除其他筛选。“待处理”页签仍是不可判定或实际待复核的并集。切换选项重置首分页并重读列表和详情，空结果不沿用上个对象；所有筛选只读，不改业务记录或复核历史。

## 合法性研判：无人机范围（2026-09-17）

本轮自动分流：后台每次研判在同一事务内执行规则计算与 `EVIDENCE_SUFFICIENCY_V1`，保存算法版本、充分性与原因 → 列表/详情读取 `decision_assurance` → 依据充分的合法或非法结果直接展示，右侧不要求人工复核；依据不足或旧记录算法结果未知时显示“核对信息缺口”。是否需复核与是否有提交权限分开；主按钮受原有权限/版本校验，复核记录追加后退出待处理队列，原算法事实不变。

“信息待核对”使用 `needs_review=true`，后端先按保存的充分性、适用性及复核状态筛选再计数/分页，不再限定只有不可判定标签才需要处理。可靠结果可在更多操作中自愿纠错；刷新、切换记录和重新登录重新读取服务端结果。旧历史不补写算法结果，重新研判产生新记录。规则算法不提供未经样本验证的准确率百分比，真实参数与模拟来源边界见[自动判定 Spec](superpowers/specs/2026-09-17-legality-auto-decision-design.md)。

打开合法性页、切换筛选或由目标/计划进入 → 列表、分页、各状态统计及目标定位统一请求 `GET /legality-evaluations?object_type_code=UAV` → 服务端按可见目标当前明确类别筛选，再计数、排序与分页 → 展示无人机实际飞行与计划、航线相关研判。无匹配计划的无人机保留，鸟类、气球、风筝和类别未知目标排除；无观测目标的计划不据此认定已起飞。过滤仅影响此页读取范围，不改规则结论、风险、通知、回执和历史记录。

选择研判或动作后回读 → 详情返回当前目标类别 → 仍为 UAV 时继续展示依据、轨迹、历史和服务端允许的动作；类别已变化或无法明确时清空原详情并说明，不继续请求该条轨迹或复核历史，同时回到首分页重读队列与统计，保留说明而不自动选中其他目标。旧目标深链无可见无人机研判时保持提示，不自动选中无关对象。刷新和重新进入重新读取；权限、网络与后端错误如实显示，不回退全类型列表或把缺失记录视为合法。

接口需配套后端新增筛选及详情字段，具体契约见[规则引擎接口](backend-stage7/rule-engine-api-contract.md)。

统计在列表读取完成后依次查询，避免首次进入时六路最新研判查询同时争用资源；筛选变化或退出后丢弃过期统计，退出后不继续排队。此安排仅调整读取顺序，不改变系统自动研判或通知流程。

## 飞行计划：通知摘要与设备再次通知（2026-09-17）

当前附近设备检查发现异常或未关闭告警 → 前台先读取同一计划/设备的运维待办 → 无待办时“通知设备异常”创建待办及首次通知记录；已有待办显示最近发送结果和回执 → 后台允许时“再次通知”或“重试通知”在同一待办下追加发送记录。服务端按权限、对象范围、当前检查、发送间隔及原通知结果校验，并锁定同一设备、核对通知次数和提交编号，防止双入口或并发点击重复发送。

地图卡片与列表共用结果和提交状态，完整记录按需展开；每次接收资料、发送/送达/回执时间、失败原因独立保存。最近一次失败不覆盖过去送达，运维处理不等于设备恢复。明确模拟通道持续标识，未接通真实通道不回退模拟成功。网络超时保留原提交编号，先刷新读取；原结果未确认时只能重试原提交，不能另起一次通知。刷新、重新登录和切换对象分别回读，读取失败不当作未通知，旧账号迟到结果不进入新账号状态。

计划报送单位的“历史检查与通知”与设备运维保持两条独立链路：历史检查卡默认显示完整结论、已保存的摘要/来源及发送/回执/处理反馈状态；展开后保留全文与原接收快照。不从当前设备检查补造历史数量。未通知且仍适用的报送单位通知入口继续保留。

再次通知接口与追加记录迁移见[设备运维契约](设备运维接口契约.md)。前台需与含该迁移的后台配套运行；隔离测试不等于真实通道验收。

## 合法性研判：地图目标轨迹（2026-09-16）

选择研判 → `GET /legality-evaluations/{id}/trajectory` 钉住同一研判的目标、航线版本及数据截止时间 → 后台读取最近一条 FUSED 轨迹的实测点并按已有走廊计算分段关系 → 地图显示绿色符合段、红色偏离段、灰色计划底线，关系未知显示黄色。没有融合轨迹时，只使用该研判引用且确属同一目标的原始轨迹，不借计划最新研判换成其他目标。原研判结论与证据引用不变。

实测点按时序绘制；跨轨迹、缺点、时间倒序、超过研判版本的间隔参数时断开，不补点、不平滑成虚构路径。弥合、预测不混充已飞实测；参数缺失仅显示点。灰色底线保留规划参考，没有轨迹不等于未起飞。目标位置另行读取；无轨迹和读取失败分别提示。切换目标、证据页签或退出页面后丢弃迟到响应，刷新重新读取。接口继续校验研判、目标、航线权限与范围，只读，不改业务状态。

## 告警事件：目标轨迹可见性（2026-09-16）

选择告警 → 按服务端返回的关联目标读取详情、最新一条轨迹及全部点位分页 → 地图按可信轨迹点和目标位置自适应缩放；“定位”恢复同一范围。光电任务查询不阻塞已读取轨迹的显示。轨迹仍为该目标最新轨迹，不冒充告警发生时的历史快照；来源明确标注，未提供走廊比对的点保持关系未知，连续性沿用共享轨迹绘制规则。

无关联目标、无轨迹、单点、目标读取失败与轨迹读取失败分别提示，不生成模拟补点。切换告警和退出页面后丢弃旧请求结果；刷新重读标准接口。此链路只读，不修改告警、目标、轨迹或处置状态。

## 自动短信与融合感知同步（2026-09-16）

2026-09-21 起，告警事件建立后后台自动发送一条飞手短信，不再检查核实、研判、时效或目标类型。没有已核验的执行飞手时不发送短信，也不拨打电话。同一事件只自动发送一次；已送达或失败的记录保持原事实。本地演示环境把模拟、回放和实时来源都记为模拟送达，生产环境不发送。告警与融合感知显示同一事件通知状态。正常发送无需点击，失败后可人工重试；浏览器关闭仍运行。2026-09-22 起改为：待核实期间不发短信。核实属实后自动短信，观察 10 秒，仍在则自动电话，再观察 10 秒，仍未撤离则待反制并显示发起反制。没有飞手时核实后直接待反制。已离开或无法确认不进入待反制。电话不改变核实状态。反制和处罚继续各自条件。接口见[无人机劝离处置](backend-stage19/uav-advisory-workflow.md)。本节替代此前“必须有明确违规研判或近期人工确认才发送”的规则，也替代历史流程中的首次手动短信步骤。

已有模拟发送及送达记录属于历史结果，不随当前观测过期变成“未发送”。追加历史演示数据按[跨模块配套规范](演示数据跨模块配套规范.md)补齐通知任务、发送记录、模拟回执、事件版本和审计；明确标注“模拟历史补录”及实际补录时间，不能据补录声称当时实际运行过策略。迟补记录作为补充材料关联事件/案件，原交接快照不回写。正常实时触发与历史样本补录分别验收。

## 历史阶段：短信劝离、观察与事后处罚（2026-09-15）

已核实无人机事件 → 短信劝离或记录人工联系 → 记录当前现场观察（仍在违规区域/已确认飞离/无法确认，以及危险度和依据）→ 仍在区域且危险度高时申请反制 → 按既有有效授权审批、执行和核查。新一次联系后必须重新观察；目标失联不等于飞离，风险降低或已飞离不允许继续据旧判断升级。紧急情况可记录充分紧急依据后申请，仍不跳过授权。界面不擅自指定观察时长，不把历史轨迹自动当当前现场结论。

短信预留服务端适配接口，目前只给 local/test 的 mock/replay 事件返回明确标记的模拟接收人和模拟送达；不发送真实短信。真实来源缺少通道时显示待接入，可记录人工电话/现场联系。记录及审计、幂等、事件版本由后端持久化，刷新与跨页重新读取。

处罚移送按已核实事件、材料及接收方权限独立办理，不要求反制完成；模拟短信、联系、观察和已有处置记录一起冻结进交接材料。移送、送达、处罚决定与结案分别表述。告警详情证据链下方的处置进度默认展示短信和电话各自结果，详细记录按需展开；告警详情“查看本次授权”进入相同授权，“查看处罚交接”进入相同材料。独立的融合感知模拟目标没有业务告警 ID 时只提供告警列表入口并说明未关联，不再用本地状态伪装反制执行或处罚移送。

本节替代旧无人机演示主线中“必须完成反制/干扰再移送”的要求。其他风险、设备流程保持各自原有状态。接口与页面说明见 [无人机劝离处置](backend-stage19/uav-advisory-workflow.md)。

## 空域监测：普通目标光电追踪（2026-09-15）

## 协作者 B：飞行计划、空域事实与已保存合法性研判

本节描述阶段 3A 的只读检查点：服务端提供航线版本、飞行计划、空域版本、空间冲突事实和已保存研判，现有飞行计划页与合法性页只做标准 API 接线。该检查点不包含生产规则计算、自动审批、处置写操作或研判重算，不得称为完整生产合法性能力。

### 前置条件与边界

- 用户必须拥有页面对应的动作权限：计划 `flight:read`、航线 `route:read`、空域 `airspace:read`、研判 `assessment:read`；冲突事实同时要求计划与空域权限，研判历史同时要求计划与研判权限。

- GET 只读取已有事实和研判，不创建规则版本、不生成结论，也不修改计划、空域或研判记录。

### 反制与关联干扰急停（2026-09-14）

- 入口：告警详情、处置授权详情，复用 `EmergencyStopPanel`；独立工作台入口已移除，不恢复。正在执行显示“急停本次处置”，尚未执行显示“撤销本次处置”。
- 点击直接调用 `POST /uav-events/{eventId}/emergency-stop`，无需事前填原因；服务端校验 `disposal:stop` 与事件范围，持久化本轮停止记录、逐设备任务、授权中止及审计。
- 停止范围是本轮活动反制/干扰和显式关联父反制，保留其他历史；共用设备无法保证单事件全关范围时明确拒绝。旧启动/重投不能在急停后重新启动。
- 页面通过同一路径 GET 回读平台记录和设备反馈。全关 ACK 只显示“已收到全关确认”，现场核查需填写依据；未执行任务显示无需停止设备。超时或网络结果未知先查询，未证实后可使用原幂等键重试同一请求。
- 原因事后追加；逐设备提供查询、允许时重试和现场核查。未确认项留在事件详情跟进。切换事件/账号丢弃旧响应，刷新和跨页重新读取服务端记录。
- 停止不解除告警、不恢复旧授权；所有设备核查完成后，新处置仍走申请审批流程。上次原因待补不能覆盖新一轮正在执行的状态。

接口字段、实际测试和设备能力边界见 [阶段19急停接口](backend-stage19/countermeasure-emergency-stop-api.md)。
