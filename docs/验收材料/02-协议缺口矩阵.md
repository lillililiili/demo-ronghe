# 协议缺口矩阵

2026-09-09。以仓库源码与已提交/工作区契约为准，不扩融合目录、不发明厂家字段。页面原文必须能在界面上找到；找不到就标「运维/API 仅」。

列含义：

- **资料**：厂家协议是否定义该能力
- **实现**：本仓库是否发送或接收
- **页面**：值班员看见什么（原话优先）
- **补救方**：谁能把它变成「能用」

## 1. 凌云协议 A — 探测 MQTT（`LINGYUN_MQTT_V8_6`）

登记缩写：`radar` / `5ga` / `tdoa` / `aoa` / `dcd` / `rid`。工参主题 `bridge/.../device/...` 只更新在线态；SenseData `device_data` 进 `inbox_message`，`source=lingyun:<缩写>:<内部设备ID>`，融合领取后才出目标。`workState=0` 不是离线；30 秒无有效工参才离线。

| 能力 | 资料 | 实现 | 页面 | 补救方 |
| --- | --- | --- | --- | --- |
| 工参 / 在线态 | 有 | 有 | 设备详情连接/工作状态 | — |
| SenseData 目标观测 | 有 | 写入 inbox，语义由融合映射 | 融合感知目标；inbox 仍为 `RECEIVED` 不等于已出目标 | 开融合领取；高度仍不比较 |
| `dec`/`ifr`/`bsc` 工参 | 附录有 | 可登记，**不写** `lingyun:` inbox，`source_type` NULL | 设备台账有诱骗/干扰/驱鸟炮 | 控制走协议 B，不是探测 |
| MQTT 登记 `oe` | 附录有光电 | **不登记**；光电走协议 C | 接入协议选「凌云协议 C 光电边端」 | 不要用协议 A 登记光电 |
| MQTT 登记 `cm` | 附录有反制 | **不登记**；四通道走厂家 TCP | 接入协议选「固定式四通道网络控制器」 | 不要用协议 B 驱动四通道 |
| MQTT 登记 `isrs` | 附录有察打一体 | **不登记** | 无该类型选项 | 厂家+产品确认后再开 |

## 2. 凌云协议 B — 控制 MQTT

`POST /api/v1/devices/{id}/commands/lingyun-control`。白名单与 `LingyunControlEnvelope.COMMANDS` / `family()` 一致。须已登记 MQTT、类型同族、设备启用且 `ONLINE`。停止用 `operationType=0`。控制回执 `control-resp:`，**不进**融合领取前缀。

| 指令码 | 族 | 资料 | 实现 | 页面 / API | 补救方 |
| --- | --- | --- | --- | --- | --- |
| 10000 | radar | 有 | 可下发 | 探测模式；须绑雷达 | 运维登记 `S85R1` 类设备 |
| 30000–30003 | oe | 有 | 码在白名单 | 光电 **不走** MQTT 登记，绑不上 oe 则 400/409 | 跟踪用手点协议 C，不要用这些码当跟踪入口 |
| 50002 / 50003 / 50005 / 50100 / 50101 | dec | 有 | 可下发 | 处置 DECOY 演示映射 50002；须绑诱骗 | 类型不符 400「指令码与设备类型不匹配」 |
| 60002 / 60003 / 60100 / 60101 | ifr | 有 | 可下发 | 处置 JAMMING→60002、COUNTERMEASURE→60003 | 须绑干扰 `S85F1` |
| 70001 | bsc | 有 | 可下发 | 处置 DISPERSAL→70001 | 须绑驱鸟炮 `S85B1` |
| 90000 | aoa | 有 | 可下发 | 侦测模式 | 须绑 AOA |
| 100000 | tdoa | 有 | 可下发 | 侦测模式 | 须绑 TDOA |
| 50000 / 50001 / 50004 / 50006 / 50007 等 | — | 协议标明未有真实设备或未映射 | **不在白名单** | 400 `PROTOCOL_UNSUPPORTED`；处置 `PROTOCOL_NOT_OPENED`「该类指令码尚未开放（等厂家确认设备类型）」 | 厂家确认缩写后由 A 加白名单 |
| 急停 URL | 无 | 固定拒绝 | `409 CONTROL_NOT_ENABLED`「急停：设备协议未提供」 | 不要当缺陷；停止用 `operationType=0` 或四通道全关 |

处置通道 `LINGYUN_B` 还须 `devices.op`。未绑定 → `DEVICE_NOT_BOUND`；离线 → `DEVICE_OFFLINE`。

## 3. 凌云协议 C — 光电边端（`EO_EDGE_MQTT_20250826`）

平台当边缘中心。手点：`POST /api/v1/targets/{id}/eo-tracking-tasks`。自动跟踪 `app.eo-edge.auto-track.enabled` **默认关**。无任务的跟踪上报 `TRACK_NOT_OPEN`。

| 事件 / 能力 | 资料 | 实现 | 页面 | 补救方 |
| --- | --- | --- | --- | --- |
| HeartBeat | 有 | 有；3 秒无心跳离线；`workState` 0 空闲 / 1 工作 / 2 自主探测 | 设备在线、工作状态 | — |
| BeginTracking / EndTracking | 有 | 有；仅 BeginTracking+`codeStatus` 写 inbox | 态势/告警「光电跟踪」 | 目标须有经纬度 |
| CameraStatus | 有 | 有 | 设备详情可显示相机状态 JSON | — |
| AdjustDeviceInfo | 标暂不支持 | 不实现 | 「角度移动 / home / 辅助识别：设备协议未提供」 | 厂家提供协议后再做 |
| DetectToggle | 标暂不支持 | 不实现 | 同上 | 厂家 |
| TrackToggle | 标暂不支持 | 不实现 | 接入表单「设备协议未提供」 | 厂家 |
| SetHome | 标暂不支持 | 不实现 | 同上 | 厂家 |
| MoveHome | 标暂不支持 | 不实现 | 同上 | 厂家 |
| AbsMoveByAngle | 标暂不支持 | 不实现 | 同上 | 厂家 |
| 实时视频 | 无本平台通道 | 无 | 态势「实时视频（未接入）」title「尚未接入」 | 外部视频系统 |
| 无经纬度引导 | — | 422 `TARGET_POSITION_UNAVAILABLE` | 「目标没有可用经纬度，无法引导光电跟踪」 | 换有位置的目标 |
| 无空闲光电 | — | 422 `EO_DEVICE_UNAVAILABLE` | 「当前范围没有空闲光电」 | 等光电空闲或换范围 |

## 4. T02 / 兼容机扫雷达 TCP（`RADAR_TCP_V3_0_0`）

资料：低空监视雷达网络通信协议 v3.0.0。只读。

| 能力 | 资料 | 实现 | 页面 | 补救方 |
| --- | --- | --- | --- | --- |
| TCP 连接、DATA 登录、心跳 | 有 | 有 | 调测分项；协议状态 | 现场网络与识别码 `env:` |
| 点迹 / 航迹 / RTK | 有 | 接收；航迹可提升 inbox（开关默认关） | 监测、融合（提升打开后） | `app.fusion.live-promotion.enabled` |
| 启停 / 写寄存器 | 资料有控制类 | **不实现** | 无按钮；重启 `DEVICE_NOT_OPERABLE`「该设备协议未声明重启能力」 | 厂家+产品确认 |
| 待机无航迹调测 | — | `UNTESTABLE` | 调测「不可判定」；警示「雷达待机无航迹时结论可为不可判定」 | 不是失败 |
| 调试 CRC `0xCCCC` | 调试用 | 生产拒绝 | 适配器失败 | 关闭调试 CRC |

## 5. 四通道网络控制器 TCP（`COUNTERMEASURE_TCP_4CH_V2_0`）

资料：《网络控制器通信协议 v2.0》《四通道打击数据协议》。厂家现场例 `192.168.0.7:10006` **不是**种子地址。本机 `CM4-LOCAL` = `127.0.0.1:10006`。

| 能力 | 资料 | 实现 | 页面 | 补救方 |
| --- | --- | --- | --- | --- |
| `0x10` 状态查询 | 有；金样 `55 01 10 00 00 00 01 67` | 调测/轮询只发这个 | 监测四频段 ON/OFF；调测「四通道状态查询」 | — |
| `0x11` 关一路 / `0x12` 开一路 | 有 | REST `CHANNEL_OFF` / `CHANNEL_ON` | 无独立设备页按钮；经 API 或处置 | `devices.op` + 在线 |
| `0x13` 组合 | 有；全开 `0x0F`、驱离 `0x0D`、全关 `0x00` | REST `SET_MASK` 只允许 0/13/15 | 处置 COUNTERMEASURE→全开、JAMMING→驱离、停止→全关 | 通道须选四通道且设备是该协议 |
| `0x14` 及之后、无回码连发 | 打击协议有 | **不实现** | 无入口 | 本期不做 |
| 广播地址 245 | 禁止 | 拒绝 | API 400 | 地址 1–244 |
| 急停 | 无 | 不提供 | 急停 URL 仍「设备协议未提供」 | 用全关 |
| DECOY / DISPERSAL 走四通道 | 设备不是诱骗/驱鸟炮 | 400 `VALIDATION_ERROR` | 「四通道网络控制器不能执行驱离或诱骗…」 | 改凌云诱骗/驱鸟炮 |
| 重启 | 未声明 | `DEVICE_NOT_OPERABLE` | 与雷达相同 | — |

回码成功 **不代表射频已发射**。

## 6. 页面上常见「不能用」且不是协议缺口

| 现象 | 原因 | 补救 |
| --- | --- | --- |
| 实时视频（未接入） | 无视频通道 | 外部系统 |
| 通知机场/周边（未接入） | 机场通报通道未接 | 客户+阶段 9 明确不做 |
| 飞行计划「导出（尚未接入）」 | 契约只有告警/风险导出 | 不要当设备缺陷 |
| 合法性「转入处置（尚未接入）」 | 该按钮未接线 | 从告警/工作台发起处置 |
| 驱鸟处置（尚未接入） | 空域页设备作业未接 | 处置走驱鸟炮 70001 或人工 |
| 刷新后登录页 | 会话过期 | 再登录 |
