# 协作会话工作流

本文约束两名开发者使用多个 Codex 会话协作时的调度、分支、审查和合流方式。业务边界与 12 周顺序仍以[后端双人协作开发计划](后端双人协作开发计划.md)为准。

## 1. 单一调度入口

同一开发波次只设一个“总协调”会话。只有总协调可以下发实现、修复、复审、合流和下一刀任务；通知、实现和审查会话不得互相派工。

| 角色 | 可执行事项 | 禁止事项 |
| --- | --- | --- |
| 总协调 | 冻结契约、分配文件所有权、选择基线、收集证据、发起复审和合流 | 直接承担已分配给实现会话的大块业务代码 |
| 实现甲 | 在独立分支完成被分配切片、测试、自审和提交 | 修改实现乙独占文件、改变公共契约或自行合并 |
| 实现乙 | 在另一独立分支完成不冲突切片、测试、自审和提交 | 修改实现甲独占文件、改变公共契约或自行合并 |
| 独立审查 | 对指定 Base/Head 做只读审查，给出阻断项和验证证据 | 直接修复被审分支、代替实现者提交 |
| 定时汇总 | 在约定时间读取总协调结论并汇总待确认事项 | 下发技术任务、修改代码或改变验收结论 |

明早 9:00 的持续开发与汇总安排保持不变；该时间只控制本轮运行周期，不改变上述职责。

## 2. 派工前置条件

总协调下发任务前必须固定以下信息：

1. 可追踪的任务说明：使用已提交文档、Issue 或 PR 描述，不引用其他工作区中的未跟踪文件作为唯一依据。
2. Base 提交、目标分支和独立 worktree 路径。
3. 允许修改和禁止修改的文件范围。
4. 请求/响应、错误码、状态语义和兼容边界。
5. 最小测试、全量门禁、验收出口和待确认事项。

任务说明变更后，由总协调更新已跟踪依据并通知所有消费者；实现会话不得仅根据聊天记忆改变公共字段语义。

## 3. 分支与所有权

- `main` 只跟踪 `origin/main`，禁止在本地主分支堆放仅供其他功能分支依赖的未推送提交。
- 公共工程调整单独使用短生命周期分支和 PR；合并后，功能分支再 rebase 或 merge 最新 `main`。
- 两个实现会话不得同时修改同一 DTO、迁移、状态机、公共组件或页面。
- 开发 A 主责认证/RBAC、设备、指令、证据和归档；开发 B 主责态势、飞行、告警、风险、工作台、统计和大屏。
- 公共组件由总协调指定唯一实现者，另一人只审查。临时需要跨所有权修改时，必须在任务说明中显式交接。

## 4. 标准交付链

```text
总协调冻结任务说明与 Base
  → 实现会话在独立分支开发
  → 最小测试 + 规定门禁 + 自审
  → 独立审查会话检查 Base/Head
  → 有阻断项：原实现会话追加修复提交
  → 同一审查会话复审
  → 总协调核验工作树、提交、测试与所有权
  → PR 审批和 CI 通过后合并 main
```

以下任一条件不满足时不得合并：

- 存在 Critical/Important 阻断项；
- 没有新鲜测试或构建证据；
- 越过任务文件范围或另一开发者所有权；
- 生产能力未实现却显示成功提示；
- 分支依赖未进入 `origin/main` 的本地主分支提交；
- PR 未通过至少一位非作者审查与 CI。

## 5. 当前 B 侧两刀边界

### B1：真实认证与统一 API 客户端

- 登录、会话恢复、退出必须调用 `/api/v1/auth/*`，失败不得回退为 Mock 成功。
- 成功响应必须校验认证契约；任意业务 API 的 `401` 必须同步清除 token、响应式会话和用户摘要。
- 修复提交完成后由独立审查会话复审，通过后才可提交 PR。
- 当期 API 契约跟随功能分支提交在 `dongying-vue/docs/api-contract-current.md`。

### B2：页面加载、空态、错态与分页规范

- 本刀只允许修改公共页面状态组件、分页 hook 和开发 B 所有权页面。
- 首个示范页面使用统计页；不得修改开发 A 所有权的归档页。
- 分页必须直接驱动页面展示集合和页码状态，不能只计算未被模板消费的数据。
- 导出、月报等真实能力未接入时必须禁用并说明原因，不得用成功 Toast 伪装完成。
- 完成后必须经过与 B1 相同的独立审查、修复和复审流程。

## 6. 汇总格式

总协调和明早 9:00 汇总只报告可验证事实：

- 分支、Base/Head 和提交号；
- 已修改文件与所有权；
- 实际运行的命令及结果；
- 审查结论和仍未解决的阻断项；
- 真正需要用户确认的事项及推荐选择。

未执行的检查必须明确写“未执行”，不得用计划中的门禁替代实际结果。
