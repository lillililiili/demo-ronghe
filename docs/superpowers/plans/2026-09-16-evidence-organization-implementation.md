# 证据预览与单位通知关联实施计划

> 按本次用户批准的修正方案执行，并行子任务按文件域分工，根任务统一接口、浏览器验证和交付。风险通知固定“通知上级”，不区分单位、区域或风险类型。

目标：证据从业务入口直接预览；后台可维护完整单位和联系人，计划主体及各用途通知读取明确关联，并保留历史。

技术：既有 Vue 3、Naive UI／Element Plus、Spring Boot、PostgreSQL/PostGIS，禁止新依赖。仅本地 main，保留用户未提交文件及删除状态。

## 工作线与接口约束

- [x] A 证据切片：前台 `EvidencePage.vue`、`ui/evidenceChainView.js`、`ui/evidenceFileDetail.js`、`services/evidenceApi.js` 及共享预览组件；后台 evidence 模块、独立 preview 权限、访问审计与迁移 `V202609160003__evidence_preview.sql`。图片/PDF/可播录像/文本/JSON 受控读取，32 MiB 上限，临时 URL 清理，来源未知不补造。
- [x] B 组织后端：扩展单位资料、联系人、来源/计划明确关联和通知设置 API；迁移 `V202609160004__organization_contact_notification.sql`。接口采用现有 `/api/v1`、snake_case、字符串 ID、Bearer 和版本/幂等契约。通知保留原状态机、recipient_id 含义与逐检查防重；风险固定上级，处罚明确选择，飞手无可信身份不以单位联系人兜底。
- [x] C 管理前端：系统管理下单位档案、联系人、来源/计划关联及通知设置；消费 B 的确定契约。单位不增加停用操作；联系人/绑定可管理有效性。没有区域或风险类型分发配置；技术通道显示接通情况，保存设置不发送通知。
- [x] D 业务前台：计划资料呈现报备单位档案关联、原始名称与飞手关联；检查通知呈现当前对象和历史快照；风险页面统一“上级”。每个读取均隔离计划/事项切换及迟到响应。
- [x] E 总验收：新接口权限/事务/幂等/历史回归、隔离 PostgreSQL 迁移、前后台构建、现有六旧地址回归及真实浏览器检查；交付按页面位置和操作说明。

## 核心验收输入与结果

| 输入/操作 | 预期 |
| --- | --- |
| 预览有权、下载无权；跨范围读取；假 MIME；缺件和损坏 | 独立授权，失败原因明确；拒绝审计回滚后保留 |
| JSON 证据、可辨识图像、有效 PDF/录像 | 直接显示真实内容；不能吞掉 JSON 或用占位图片当成功 |
| 一单位多联系人、来源系统报两家单位 | 稳定 ID 明确关联；姓名不作自动合并键 |
| 单位改名、联系人调岗、已发对象变化 | 当前资料变化，原通知快照与材料保留 |
| 同计划两次检查反馈、超时重试 | 逐 verification_id 关联；本次幂等，不吞下一次通知 |
| 风险通知 | 仅“通知上级”，不出现职责单位选择或区域/类型分发 |
| 切换计划/证据、刷新、重新登录 | 不串对象；数据与历史一致 |
