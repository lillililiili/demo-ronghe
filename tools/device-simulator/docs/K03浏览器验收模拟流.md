# K03 浏览器验收模拟输入

此流程仅生成输入并复用现有模拟器，不使用业务种子、数据库写入、预制预测／告警或特殊设备判断。首次生成使用随机场景包标识；同包三份场景复用同两台逻辑设备及同禁飞区，重复导入保存的 JSON 可保留身份。不要反复生成新包替代同包重跑。

## 准备与入口

本机既有入口是 `http://127.0.0.1:8766/`，运行脚本为 `tools/device-simulator/server.py`。本次不启动、重启或连接任何服务。统一启动验收后使用已有登录会话，核对后端为本次 `8081`、业务前台为 `5173`，保持 `local,qa` 与 `app.dev-seed.enabled=false`。

在业务仓库执行以下离线命令可以另生成一包。经纬度是禁飞区西侧边界中点，可换到本次验收可见范围，须先检查其他有效空域和正在运行的场景，避免混入其他风险。命令不向平台发送数据。

```powershell
python tools/device-simulator/k03_scenario.py --output-dir tools/device-simulator/scenarios/k03-new-run --longitude 118.62 --latitude 37.45
```

本次已提供 `scenarios/k03-prediction/avoid.json`、`silence.json`、`enter.json`。页面“场景工具 → 导入场景”选择一份文件；确认设备、航线、禁飞区及运行时长，然后通过已有“开始模拟”及开始前检查启动。导入不启动，启动准备完成不等于 K03 已通过。运行中的场景不能直接替换；完成当前项后按既有停止流程再导入下一项。

主雷达通过已登记且关联真实模拟设备的规范化输入上报明确 AMSL 100 m、AGL 80 m，辅助 TDOA 经 MQTT 协议 A 上报同一模拟 SN 和当前位置。每秒一帧，显式 WGS84；设备、来源、接入身份、`replay`／`simulated` 由现有受控登记和平台事实保留。并非两路都冒称现场实测；界面应明确为模拟数据。后端须从实际接收的观测形成 MEAS、轨迹和预测，不能把发送计数当作接收证据。

配套航线与 AMSL 0–300 m 的 PROHIBITED 由现有授权 API 下发，`fullchain.enabled=true`，没有 `observationSourceCount` 虚构多源和风险结果输入。通知行为为 `none`，不让短信或电话改变预设航迹。只验收预测显示时，可在既有收发设置关闭通知／反制接收端；核实与通知、反制的验收另按后端资格办理。

## 默认运行时序

三份均运行 180 秒，20 m/s 从禁飞区西侧 1,800 m 处开始匀速向东，若不转向将在约第 90 秒接触西边界。有效预测需实际收到至少 5 个独立实测点；本输入先连续直飞超过 10 秒。准确启用时刻仍取决于实际接收、融合、当前参数、误差与稳定性判断，不能硬编码为第几秒必出警。

| 场景 | 输入变化 | 浏览器观察与判据 |
| --- | --- | --- |
| avoid.json | 约第 80 秒在边界外 200 m 处向北转弯，持续新实测 | 先 READY 三点和稳定预测预警；转弯阶段可暂 UNKNOWN；新实测确认未来 30 秒不再入区后 WITHDRAWN，首次快照和历史仍可查 |
| silence.json | 第 80 秒起两路目标观测均停止，设备心跳与场景继续 | 先有稳定预测预警；实测到期后 UNKNOWN，地图未来线／入区点隐藏，事项仍在且不能因失联撤销 |
| enter.json | 持续直行；约第 90 秒越过边界 | 先预测，之后由有效实测形成 ENTERED，实测告警承接；不能把预测菱形当作已经进入 |

**断流项不要点击“停止场景上报”来代替 `silenceWindows`。** 正常停止或到期会按既有流程撤回本批模拟空域，混入空域撤销变量。应在第 80–170 秒、场景仍运行且空域仍有效时观察 UNKNOWN；设备继续心跳说明停的是目标观测。

默认计划随本批处于当前时段，降低无计划噪声；其他已发布规则仍可能产生独立告警。按目标的真实 SN／平台返回 target_id、空域 ID 和 `origin_kind=PREDICTED_AIRSPACE_ENTRY` 关联，不能仅凭名称或序号认定通过。

## 回读与记录

1. 在模拟器“回读平台数据”核对实际批次、设备来源、目标 ID、观测时间及空域接收情况。
2. 融合感知选中目标，检查未来预测开关、实测线与虚线空心点区分、+10／20／30 秒、方向及 PROHIBITED；未稳定时只在详情显示接近提示。
3. 用 `GET /api/v1/targets/{id}/prediction` 记录 prediction_id、generated_at、based_on_observed_at、valid_until、reason_codes、warning.version 和空域版本；不要通过刷新制造新观测次数。
4. 告警列表选择预测类别，验证地图和列表对应事件，当前预测与首次冻结快照分开；撤销、未知、已进入按实际 history 记录。
5. 如无法得到 READY 或 ACTIVE，记录原因、MEAS 接收时间、来源和误差版本；不要修改阈值、补库、补种子或把 UNKNOWN 记通过。转向后应等新窗口稳定与解除连续观测条件满足，不以一次安全点判断撤销。

## 离线验证

```powershell
python -B -m unittest discover -s tools/device-simulator/tests -p test_k03_scenario.py -v
```

测试涵盖更换位置、编号和速度后的同类输入；验证实际场景编译、WGS84、两路实际报文分工、转弯几何、断流期间不发目标而仍有心跳。它只验证输入能力，不能替代真实浏览器、后端算法、设备或通知渠道验收。
