## 1. 客户关于空域说过的全部原话

1. "我有个空域，哪些地方是禁飞区，哪些地方是可飞的。**那些空域数据你们给我们就行了**。"
2. "这些数据其实**只是一个显示或者一个 demo**，和咱这个软件不直接相连。"
3. "我放在东营是这些数据，放在济南就不是这个数据了——地图不一样，禁飞区不一样，各种点位不一样。但你扫还是一样的扫，**界面样式是一样的，数据不一样**。"
4. "省里会开发一套平台……咱这个平台再往管服平台对接。管服平台会有各种接口、各种权限、账号。**哪个县来的，就管哪个县来的**，对应账号。"
5. "无人机和飞行人员是合法的，但这个行为不合法——**我批准你这个线路是从这儿的，你从这儿往那儿走了，也是不合法的**。"
6. "地图、融合算法、设备安装、**监测区**这些常规的数据，包括地图的下载，这些都不能用他们的。"
7. 纪要：空域与航线规则 = "管理或接收禁飞区、限飞区、限高区、许可空域、临时管制区、合法航线等规则，**为合法性判定提供依据**"；"外部管服平台把合法飞行计划、许可空域、合法航线、飞行时间窗口等信息**同步给我们**"。

## 2. 从这些话里读出来的四件事

| 客户的话 | 意思 |
|---|---|
| "数据你们给我们就行了" "只是一个显示" | 空域规则不是在这个软件里"编"出来的，是**拿来的**：上级管服平台同步下发，或客户交一份数据包。页面主要是**看**，不是画。 |
| "东营一套数据、济南一套数据，界面一样" | 空域是**可整包替换的数据**。换城市 = 换地图 + 换空域包 + 换设备点位，页面不动。 |
| "哪个县管哪个县" | 按区县分账号看、分账号管。垦利的公安登录只关心垦利。 |
| "批了这条线，你走了别的线，不合法" | 空域和航线的用处是**给合法性研判当尺子**。这页本身不判合法，但要能让人看见"这条规则正被哪些计划/航线用着"。 |
| "监测区" 和空域并列 | 客户脑子里这张图上还有一层：**我的设备能看到哪一片**。禁飞区和雷达覆盖区放在同一张图上，公安才知道"这片禁飞区有没有人盯着"。 |

一句话：客户要的空域管理是"**一张能换数据的图**"——上面画着禁飞/限高/可飞/临时管制/合法航线/设备覆盖，公安按自己的县看，偶尔临时划一片管制区；规则本体从上级来，本地不折腾。

## 3. v1 里做错方向的

| v1 | 问题 | v2 |
|---|---|---|
| 版本时间线、与上一版差异 | 这是给"编规则的人"看的。公安不关心 v3 和 v2 差在哪，只关心现在哪里不能飞 | 去掉；改动历史缩成详情里一行"最近更新 时间 · 来源" |
| 新建空域 = 贴一段 GeoJSON | 没有公安会贴 GeoJSON | 本地只划**临时管制区**，在地图上点几个点画多边形，填名称/时间/高度/单位 |
| 导入 = 暂存 → 校验清单 → 确认 | 这是开发者流程 | 改成"**加载数据包**"：选文件 → 显示这包里有多少条、覆盖哪个城市、和当前差多少 → 替换 |
| 管理单位/区域是文本框填标识 | 客户是按县用的 | 区县是一等公民：顶部选区县，图和清单都跟着切；账号绑了县就默认锁定 |
| 只画空域 | 客户把"监测区"和空域放一起说 | 加一层"设备覆盖"可开关 |

### 4.1 操作员在这页看什么

- 我这个县，哪里不能飞、哪里限多高、哪里可以飞、这周有没有临时管制。
- 批过的航线走哪儿（绿虚线），和禁飞区挨不挨着。
- 我的雷达/光电盖住了哪一片——禁飞区在不在覆盖里。
- 点一片：谁管的、什么时候生效、从哪来的、现在有几条计划在用它、最近触发了几起告警。

### 4.2 操作员在这页做什么

| 操作 | 谁做 | 怎么做 |
|---|---|---|
| 划临时管制区 | 公安（本县） | 图上点顶点 → 填名称、起止时间、限高、管理单位 → 保存。到期自动变"已失效"，可提前停用 |
| 停用本地临管区 | 划它的人 | 详情里一键，留记录 |
| 加载数据包 | 管理员 | 选文件 → 预览"东营市 · 24 条 · 新增 3 改动 2 移除 1" → 确认替换。上级同步来的规则不能在本地改 |
| 换区县视角 | 所有人 | 顶部下拉；账号绑县的锁死 |
| 开关图层 | 所有人 | 顶部图例即开关 |

**不做**：新建/编辑上级下发的规则（只读，"如需变更须由上级发起"）、版本差异对比、GeoJSON 手贴、删除。

### 4.3 数据从哪来

| 层 | 来源 | 本地能改吗 |
|---|---|---|
| 禁飞 / 限飞 / 限高 / 可飞 | 管服平台同步；对接之前用客户给的数据包 | 不能 |
| 临时管制区 | 本地划 + 管服平台同步 | 本地划的能 |
| 合法航线 | 飞行计划带进来的航线 | 不能（在飞行计划里改） |
| 设备覆盖 | 设备管理里的安装位置 + 探测半径 | 不能（在设备管理里改） |
| "正在使用它的" | 飞行计划里引用了这片空域的计划数 + 告警里命中这片空域的告警数 | 只读统计 |

## 5. 和现有代码的关系

现有后端已有：空域表、版本表、`GET /airspaces`、`GET /airspaces/{id}`、新建、追加版本、差异、GeoJSON 导入批次、`source_mode`（人工/导入/演示）。

v2 不推翻，只换用法：

- "上级同步（只读）" = `source_mode` 为导入/同步的记录，前端不给编辑入口，后端加一条校验。
- "本地划临管区" = 现有新建接口，`kind_code=TEMPORARY_CONTROL`，边界由地图画出来生成而不是手贴。
- "停用" = 追加一版 `valid_to=现在`。
- "加载数据包" = 现有导入批次接口，前端把"暂存→确认"包成一步预览。
- "换城市" = 数据包 + 离线地图包一起换，页面无感。
- 需要新加的：清单接口带 `current_version` 摘要（v1 §5 已提）；"正在使用它的"两个计数接口；设备覆盖需要设备表有探测半径字段。

## 7. 空域风险（2026-09-13 已接线）

- 页面下方为“空域列表 / 空域风险”页签，风险按区县、等级、核验与通知状态筛选；风险独立于计划，读取风险接口时不强制关联计划。
- 地图使用风险 `space_fact.longitude/latitude` 的发现位置快照，按等级着色，已排除灰显。同点优先显示选中事件，其次为更高等级；所有记录仍可从列表访问。
- 点击风险点联动列表，列表“定位”显示发现位置及周边；“查看详情”进入既有飞行风险详情，并用 URL 保存事件 ID，刷新仍打开同一条风险。
- 选中空域可查看其当前平面范围内（含边界）的风险。匹配支持 MultiPolygon 和洞；边界注明归属待确认。该筛选不判断高度、生效时间、入侵或合法性，也不是风险与空域的后端关联事实。
- 缺少可信位置的风险保留在区县列表，显示未定位数量并禁用定位。权限不足、加载失败与真实空列表分别提示，接口失败不回退 Mock。
- 详情核验、通知与回执复用已有流程。“已通知 / 已回执”不代表现场风险解除。本次未新增自动检测、自动归档、驱离、设备覆盖或规则冲突计算能力。

## 8. 临时管制区来源修正（2026-09-13 用户确认）

- 已移除页面本地划设入口及画点、撤销、完成、建区表单和提交逻辑。
- 已移除详情“调整 / 提前结束”入口与提交版本逻辑，展示“规则变更由上级下发”。不在本地改写上级规则的范围、有效期或状态。
- 保留现有数据包导入供对接前加载数据；该能力不等于上级接口接收。刷新仍只重读本平台已存数据。
- 当前查询、版本与导入 API 继续使用；本次未实现上级接收适配器，也未修改后端通用写接口。对接方接口协议、鉴权、外部编号、变更/撤销语义及幂等约定仍需对方资料支持。

## 9. 从航线视角修正为区域监测（2026-09-14）

### 9.1 页面定位与边界

已确认方向：空域管理回答“这片区域有没有异常”，不以已有航线或正在执行的飞行任务作为查看前提。航线风险回答特定飞行会受到什么影响；飞行合规判定依据实际飞行。三个概念不能互相替代。

当前实现：默认进入“空域监测”，另有“风险记录 / 空域列表”。复用目标、风险和空域只读接口；没有新增自动入侵判定、空域安全评分、气象风险识别、设备覆盖计算或后端风险生产规则。上级下发空域规则及数据包加载仍沿用 §8。

### 9.2 上下游与生命周期

监测设备或已有接入源 → 感知目标及最近状态 → 本页“空域监测” → 查看目标 → 融合感知页目标详情。
既有风险生产链 → 风险记录及发现位置 → 本页“风险记录” → 飞行监管风险详情的核验、通知与回执。
上级下发或已加载的空域 → 空域列表/地图 → 选中区域 → 近期目标与历史风险分别按平面范围筛选。

### 9.4 逐模块逻辑

- M01：区县变化清空旧监测结果再读取；目标与风险使用同一区县，服务端继续限制权限范围。规则种类/名称过滤只控制规则显示，不代表目标类型或风险过滤。
- M02：监测页签使用蓝色方点表示近期目标位置；风险页签使用既有等级色圆点表示发现位置。两类点不同时显示，避免把历史风险点当成实时目标。选中空域后详情分别报告近期目标和已记录风险，不输出“空域安全”。
- M03：默认最近 5 分钟，可选 15/60 分钟，每 10 秒重读；时间窗口是展示条件，不是风险阈值。依据 `last_seen_at` 纳入列表，另外检查 `latest_state.observed_at` 是否在同一时间窗口内，过期或无效坐标不定位、不参与空域匹配。人员、车辆、船只、遥控器不列为空中目标；未分类目标保留且不自动定性。页签切换仍保留本页监测，离开整个页面清理轮询和权限监听。
- M04：继续读取全部可见风险，不强制关联计划；仅把关联计划视为附加信息。选中空域默认筛到范围内，可手动切回当前区县。没有位置的风险留在区县列表，已通知/已回执不是现场解除。
- M05：选中记录把当前边界交给 M02/M03/M04；没有当前边界时提示无法匹配，不能显示为零风险。关闭详情恢复区县视角。
- M06：无新增写操作；保留原实现。

### 9.8 按钮与副作用

新增动作均为本页筛选、图层开关、定位、重试或既有详情跳转，无数据写入、通知、审计命令或自动处置。登录失效和无权限时不提供无效重试。数据包确认仍按原流程执行，本次不扩大权限。

### 9.9 状态与传播

监测加载/读取成功/读取失败/无权限/缺少边界分别显示。首次加载清空旧视图，定时重读期间保留上次读取时间；失败清空目标，不继续展示为最新。换区县、权限变化及卸载使旧请求失效。目标离开展示时间窗口后从列表与地图同步移除，这不等于风险解除。风险业务状态没有改变。

### 9.10 AI 边界

本次不新增 AI。目标分类及风险结论仅展示已有服务端数据；未分类不是非法，存在目标不是危险，暂无记录不是安全。

### 9.11 权限

M03 请求需 `target:read`，下游“查看目标”需融合感知菜单可达；M04 保持 `risk:read`。服务端目标与风险查询执行组织/区县范围限制。权限不足分别提示，不使用 Mock 补齐。

### 9.14 验收场景

1. 没有关联计划的近期目标仍能展示；地面人员/车辆等不进入空域目标列表。
2. 选中空域后，内部与边界目标可见，洞内/外部目标不纳入；历史风险独立显示。
3. 最近发现但坐标过期的目标保留在区县列表，不能定位；未知或未来时间也不伪造定位。
4. 目标在列表定位与地图选中一致；查看目标使用现有上下文进入融合感知详情。
5. 零条记录、无权限、读取失败、缺少边界分别显示，均不宣称安全。
6. 换区县、时间窗口、离开页面后旧请求不覆盖新视图；离开页面停止监测轮询。
7. 本页未重新判断入侵、合法性或现场风险解除。
