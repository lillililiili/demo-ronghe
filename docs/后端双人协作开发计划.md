# 后端双人协作开发计划

## 1. 计划定位

本计划用于两名全职 Java 开发人员在 12 周内完成后端基础平台、三条核心业务闭环和现有前端业务入口的 API 切换。两人都需承担自己业务域的少量 Vue/JavaScript 改造；如果两人只负责 Java，需增加一名前端开发人员或将工期延长 2–3 周。

本计划以以下文档为当前事实和约束来源：

- [后端开发基线](后端开发基线.md)
- [数据库设计文档](数据库设计文档.md)
- [事件驱动业务流程梳理](事件驱动业务流程梳理.md)
- [协作开发环境](协作开发环境.md)

文档中的开发路线和数据库设计不等于已实现能力。真实设备、生产权限和外部通知只能根据已验证的代码、协议和联调结果改变实现状态。

## 2. 目标与范围

### 2.1 本期目标

- 完成身份权限、数据范围、审计、幂等、Inbox/Outbox 和设备适配器基础。
- 完成设备事件、无人机告警和飞行风险三条相互独立的状态机。
- 完成目标轨迹、航线空域、飞行计划、规则评估、证据、工作台、统计和大屏所需服务端能力。
- 登录后的现有 15 个业务入口不再直接读写 `window.MOCK`，不通过浏览器计时器伪造服务端或设备成功。
- 真实设备协议不完整时，使用显式启用的 Mock/Replay 适配器联调；Live 模式不得静默回退为 Mock。

### 2.2 本期不承诺

- 完整处罚案件、任务派发/SLA、AI 识别或多源融合算法。
- 未提供协议的真实反制、真实视频、外部飞行计划和外部通知系统联调。
- Redis、MQ、WebSocket、高可用集群、生产容量和容灾建设。
- 未经格式和依赖确认的正式 PDF/Excel 报表；本期可先提供 CSV/ZIP 导出。

## 3. 技术与环境决策

### 3.1 总体架构

```text
Vue 页面
  → /api/v1 REST API
  → 领域服务与独立状态机
  → PostgreSQL/PostGIS
  → Outbox 异步指令
  → DeviceAdapter
       ├─ MockAdapter
       ├─ ReplayAdapter
       └─ LiveAdapter（按型号和已确认协议启用）
  ← Inbox/设备回执
```

- 保持 JDK 17、Node.js 22、Spring Boot 3.4.5、MyBatis、Flyway、PostgreSQL 16/PostGIS 3.5、Vue 3 和原生 JavaScript/CSS。
- 不新增生产依赖；不引入 JWT、Redis、MQ 或 WebSocket。
- 页面通过 REST 轮询查询异步指令状态。
- 工作台、大屏和统计直接聚合领域表或受控视图，不建立第二套可修改的业务状态真相。
- 地图继续使用 MapLibre + PMTiles 静态资源，后端只输出已确认为 WGS84 的业务数据。未知坐标基准不得伪装为 WGS84 或 `(0,0)`。

### 3.2 数据源安全默认值

| 环境 | 账号 Seeder | 业务 Fixture | 设备数据源 |
| --- | --- | --- | --- |
| `local` | 允许显式启用合成账号 | 显式导入 | 可明确设为 `mock`/`replay` |
| `test` | 允许合成账号 | 测试夹具 | 由测试明确指定 |
| `integration` | 默认关闭 | 必须显式导入 | `APP_SOURCE_MODE` 必填，不得默认 `mock` |
| 生产 | 禁止 | 禁止 | 只启用已验收的 LiveAdapter |

第一个基础设施 PR 必须同时完成：

- 取消 `MockAdapter` 的 `matchIfMissing=true`。
- 将 `application-integration.yml` 中的 `APP_SOURCE_MODE` 改为无默认值的必填环境变量。
- 在共享联调部署记录中写明本次显式选择的数据源模式。
- 当配置的模式没有可用适配器时启动失败，而不是切换到 Mock。

### 3.3 两人协作拓扑

```text
开发者 A：个人分支/worktree + 个人 PostgreSQL ─┐
                                                 ├─ PR/交叉审核 → main → 共享联调环境
开发者 B：个人分支/worktree + 个人 PostgreSQL ─┘
```

- 两人不共享工作目录，不连接对方的本地数据库。
- 从最新 `main` 创建 `feature/<主题>` 或 `fix/<主题>` 短分支。
- 共享联调环境只部署已合并代码；不把个人功能分支直接连到共享库做日常调试。
- 一个 PR 只交付一条可验收的纵向切片，必须由另一人审核后合并。
- 共享契约、数据库迁移和状态枚举由单一负责人提交，禁止两人同时改同一个迁移或公共 DTO。
- 跨域交互只调用对方已公开的应用服务/API 或发布 Outbox 事件，不直接使用对方 Mapper 写表。

## 4. 数据库迁移策略

不使用预先固定的 V3–V8 迁移号。下列 A–D 是业务实施阶段，不是 Flyway 版本号。

每个迁移在开发时按 `VyyyyMMddHHmm__description.sql` 命名。创建前必须拉取最新 `main`、检查迁移目录并在 PR 中确认版本唯一。已提交或已应用的 V1/V2 及后续迁移不得修改、删除或通过 `flyway repair` 掩盖冲突。

| 阶段 | 负责人 | 数据库对象 | 顺序约束 |
| --- | --- | --- | --- |
| A：身份权限 | 开发 A | 组织、行政区、角色、权限、用户角色、角色权限、数据范围、权限变更记录 | 先补目录和回填，再收紧约束；未知归属不默认全域 |
| B：设备最小闭环 | 开发 A | 来源、设备、状态历史、设备事件、恢复验证、投运、授权、指令、尝试、回执、初版事件索引 | 初版事件索引只引用已建立的设备事件 |
| C：感知、计划、告警与风险 | 开发 B | 目标轨迹、航线、空域版本、飞行计划、规则评估、无人机事件、告警、风险、移交和通知 | 按被引用表到引用表建立；领域表建立后再扩展事件索引 |
| D：证据与查询 | 开发 A 主责、开发 B 提交查询需求 | 证据文件、业务关联、访问、保全及查询索引 | 最小证据底座随阶段 B 提前建立；只在目标业务表存在后增加对应关联 |

所有迁移都必须从空 PostgreSQL/PostGIS 库按顺序执行，并在包含脱敏 V1/V2 基线结构的个人测试库执行升级验证。不使用共享联调库代替迁移测试。

## 5. 接口与状态机契约

### 5.1 公共接口约定

- 保持 `/api/v1`、统一 `ApiResponse`、`snake_case` 字段和字符串 ID。
- 列表统一使用 `page`、`size`、`items`、`total`。
- 新增业务时间统一返回 RFC 3339 UTC；现有认证 `expire_at` 继续使用毫秒时间戳。
- 控制类请求必须携带 `Idempotency-Key` 请求头和 `expected_version` 请求字段。
- 异步指令创建返回 `202 Accepted`，通过 `GET /api/v1/commands/{id}` 轮询状态。
- 参数错误返回 `400`，未认证 `401`，越权 `403`，未找到 `404`，版本/幂等/状态冲突 `409`，能力不支持 `422`，来源或下游不可用 `503`。
- 每个公共契约变更先单独提交契约 PR，再由两个业务分支同步后实现。

### 5.2 指令处理顺序

1. 同一本地数据库事务中校验认证、权限、数据范围、幂等键、业务版本和设备能力。
2. 创建授权、指令、Outbox 和审计记录，然后提交事务。
3. API 返回 `202`，Worker 在事务外调用已配置适配器。
4. 适配器结果或设备回执先按来源唯一键写入 Inbox，再由领域服务执行合法状态迁移。
5. 重复、过期和乱序回执保留可追溯记录，但不重复推进状态。
6. 超时、失败和不支持保留为可重试或人工处理状态，不向前端生成伪成功。

### 5.3 三条独立状态机

- 无人机事件：告警 → 人工核验 → 一次关联反制授权 → 设备回执 → 通知处罚部门。误报分支不生成处置；通知仅表示交接，不表示处罚案件办结。
- 飞行风险：待核验 → 待通知 → 已通知，或核验后排除。点击“通知”不能直接作为成功，必须等待外部结果或已确认的人工成功规则。
- 设备事件：原因与确认 → 下发重启 → 等待设备回执 → 平台恢复验证 → 关闭。指令已接收、指令已执行、设备在线和事件已恢复是不同事实。

三条状态机只能由各自领域服务迁移，Controller、Worker、Mapper 和前端不得直接修改状态字段。

## 6. 人员分工与共享文件所有权

### 6.1 固定业务边界

| 开发者 | 后端主责 | 同步负责的前端入口 |
| --- | --- | --- |
| A：平台与设备 | 认证/RBAC/数据范围、审计、幂等、Inbox/Outbox、适配器、设备、设备事件、指令、投运、证据 | 登录、用户、角色、设备、监控、投运、证据、归档 |
| B：业务与事件 | 目标/轨迹、航线/空域/计划、规则评估、无人机告警、飞行风险、移交通知、事件池、工作台、统计与大屏 | 工作台、态势、飞行计划、合法性、告警、处罚交接、统计、大屏 |

### 6.2 共享文件规则

| 共享区域 | 唯一修改负责人 | 协作方式 |
| --- | --- | --- |
| 认证上下文、`ApiResponse`、公共异常映射 | A | B 通过契约 PR 提需求，不在业务 PR 中顺手修改 |
| 指令、幂等、Outbox/Inbox 公共能力 | A | B 只调用公共应用服务或 API |
| 统一事件索引 | B | A 先提交 DEVICE 初版契约，B 在相关业务表建立后扩展 |
| 前端 `apiClient`、路由守卫和公共页面状态 | B | A 使用已稳定的接口，变更时单独提契约 PR |
| 证据存储与权限 | A | B 通过证据关联服务关联业务对象 |
| Flyway 迁移 | 每个文件只有一位负责人 | 新建前检查 `main`，不修改对方已提交迁移 |

## 7. 12 周实施顺序

### 第 1–2 周：安全基线与公共契约

**开发 A**

- 固定 Java 17 构建门禁，完成数据源安全默认值修正。
- 将 `AuthApiIT` 重命名为普通测试可发现的 `AuthApiTest`，并在同一 PR 同步修改 CI、PR 模板、`server/README.md`、后端基线和相关命令。
- 先写失败登录计数与审计实际落库的回归测试，再修正事务边界。
- 实现阶段 A 迁移、RBAC、数据范围和用户/角色/权限管理接口。

**开发 B**

- 建立统一 `apiClient`、路由守卫、加载/空态/错误/分页规范。
- 将 `scripts/bootstrap-dev.ps1` 的锁定依赖安装与 CI 统一为 `npm ci`。
- 建立当期 API 契约清单和显式 Fixture/Replay 导入入口。
- 切换登录、用户和角色页面，保留前端无权限、接口失败和会话过期恢复路径。

**验收出口**

- `./mvnw test` 实际发现并执行认证测试，CI 不再依赖旧的 `AuthApiIT` 类名。
- 登录、用户、角色和权限管理前后端贯通。
- 未配置 `APP_SOURCE_MODE` 的 `integration` 实例拒绝启动；显式 Mock 不得被对外宣称为真实设备能力。

### 第 3–4 周：可靠消息、设备基础与感知计划

**开发 A**

- 完成 Inbox/Outbox 租约、幂等、来源能力注册、MockAdapter 和 ReplayAdapter。
- 实现阶段 B 的设备、状态历史和初版 DEVICE 事件索引。
- 提前实现共享指令创建、状态查询、幂等和回执接口，供后续设备和反制流程复用。
- 建立最小证据底座：文件元数据、哈希和通用业务关联服务，不在本阶段实现完整归档。

**开发 B**

- 实现阶段 C 中的目标、轨迹、轨迹点、航线、空域版本、飞行计划、规则和评估基础。
- 提供态势、飞行计划和合法性页面所需的只读查询和地图 DTO。
- 仅对坐标基准已知的轨迹输出 WGS84 空间字段；未知值显式返回不可绘制原因。

**验收出口**

- 设备、目标、轨迹和计划数据从后端查询，不从页面私有 Mock 生成。
- 共享指令契约已稳定；后续告警切片无需等待新的指令框架。
- 最小证据底座可关联指令，但完整访问、保全和归档尚未对外宣称完成。

### 第 5–6 周：设备闭环与飞行评估

**开发 A**

- 实现设备事件确认、重启指令、回执处理、平台恢复验证和投运流程。
- 切换设备、监控和投运页面；先将 monitor 模块加载期的随机数据副作用移入统一数据层。

**开发 B**

- 完成规则评估、飞行风险查询与读模型。
- 切换态势、飞行计划、合法性和大屏核心查询。

**验收出口**

- 回放模式可验证设备事件完整闭环，重启指令成功不会直接关闭事件。
- 态势、飞行计划和合法性页面组完成 API 化。

### 第 7–8 周：告警、反制与风险闭环

**开发 A**

- 在已稳定的共享指令框架上增加关联反制授权、设备能力检查、失败/超时处理和指令证据关联。
- 协助 B 以应用服务契约接入反制指令，不允许告警域直接写指令表。

**开发 B**

- 完成无人机事件、告警、核验、误报、处置、飞行风险核验、排除、移交和通知表及状态机。
- 扩展统一事件索引以关联 UAV/RISK，切换告警、处罚交接、风险和工作台操作。

**验收出口**

- 三条主流程在 Mock/Replay 模式下完整执行，且非法迁移、失败或超时不推进成功状态。
- 误报不产生处置，未授权不调用适配器，通知成功不被显示为处罚案件办结。

### 第 9–10 周：完整证据、聚合查询与全量切换

**开发 A**

- 补齐证据访问记录、保全标记、归档、下载授权和清理阻断。
- 完成证据、归档、身份管理页面及 CSV/ZIP 导出。

**开发 B**

- 完成事件池、工作台、统计、报表和大屏聚合查询，统一列表、详情、统计卡和地图口径。
- 切换剩余页面，生产构建不再加载业务 Mock 脚本。

**验收出口**

- 登录后 15 个业务入口均通过 API 读写数据。
- 不支持的操作显示明确原因并禁用，不保留“成功 Toast + 无服务端副作用”。

### 第 11–12 周：迁移、共享联调与发布验收

**开发 A**

- 在个人 PostgreSQL/PostGIS 中验证空库安装和 V1/V2 升级。
- 测试 Worker 租约、并发、服务重启、超时、迟到回执和重复回执。
- 完成部署配置，仅在特性开关后进行雷达 LiveAdapter 试接。

**开发 B**

- 完成全路由、全角色、跨页面状态一致性和浏览器 E2E 验证。
- 整理甲方验收用例、协议缺口矩阵、联调日志和操作说明。

**共享联调升级顺序**

1. 个人环境完成测试和迁移验证。
2. PR 由另一人审核且 CI 通过后合并。
3. 备份共享数据库及文件对象目录。
4. 记录待部署 Git 提交和当前 Flyway 版本。
5. 部署已合并代码，由 Flyway 执行升级，记录结果。
6. 执行关键链路冒烟和回归；失败时停止后续迁移和功能启用。

**验收出口**

- PostgreSQL/PostGIS 迁移、共享联调和前后端回归都有对应的提交、版本和执行记录。
- 雷达试接结果可追溯；反制 LiveAdapter 在协议未满足时保持禁用。

## 8. PR 节奏与冲突防护

- 每周一先合并当周公共契约 PR，再开始两个业务分支；周中变更公共语义时必须新建契约 PR。
- 每天进行 15 分钟同步，只讨论接口变更、迁移顺序、共享阻塞和当天可合并项。
- 每周五演示一条已连接数据库的纵向切片；每两周形成一个可独立验收里程碑。
- 前端和后端契约、Mapper/DTO 变更必须在同一业务切片中协调，不保留长期只有表没有应用或只有页面没有 API 的分支。
- PR 提交者填写 `.github/pull_request_template.md`，审核者重点阻止跨域写表、非法状态迁移、伪回执、越权和静默 Mock 回退。

## 9. 测试与发布门禁

### 9.1 后端

- H2 只用于快速应用测试；PostgreSQL/PostGIS 约束、锁、空间 SQL 和 Flyway 迁移必须在个人隔离数据库验证。
- 覆盖登录失败计数与审计落库、会话过期/退出/停用、动作权限、数据范围、导出和文件下载越权。
- 覆盖幂等重放、不同载荷复用幂等键、乐观锁冲突、并发核验、重复/迟到/乱序/超时回执和服务重启。
- 覆盖误报、未授权反制、适配器失败、恢复校验失败、通知失败和文件中断/缺失/哈希不匹配/保全阻断。
- 新增业务和缺陷按红—绿—重构循环开发：先运行测试并看到因缺少目标行为而失败，再实现最小代码并重新运行。

### 9.2 前端

- 首次安装依赖使用 `npm ci`，然后运行 `npm run build`。
- 改动 legacy、Mock、业务状态或页面迁移时运行 `node tools/scan.cjs` 和 `node tools/falsify.cjs`。
- 修正 `public/assets/js/map.js` 中用 `Date.now()` 判断拖拽/点击时间差的扫描问题，改用单调时钟；业务时间仍使用项目统一时间服务。
- 覆盖登录、15 个路由入口、不同角色、空数据、接口错误、重试、刷新恢复、跨页面数量一致和卸载清理。
- 浏览器至少检查 1280×720、1366×768、1440×900/1024，涉及地图时确认仅有一个活动地图宿主和 overlay canvas。

### 9.3 每个 PR 的最小验证

```text
后端 Java/资源改动：受影响测试 + ./mvnw test + ./mvnw package
认证/权限改动：额外显式执行认证测试类并核对实际数量

前端改动：npm run build
legacy/Mock/状态机：node tools/scan.cjs + node tools/falsify.cjs

```

检查报告必须写明实际执行的命令、测试用例数、失败、跳过和未运行项，不能只报进程退出码。

## 10. 设备协议处理策略

- 雷达 v3 文档只用于解析器、CRC、登录/心跳和目标/轨迹报文的试验性适配。在没有真实固件、脱敏抓包和现场网络验证前不标记为生产可用。
- 反制资料中的三通道、四通道和频段映射存在差异。本期先完成授权、指令、Mock/Replay 和适配器端口，反制 LiveAdapter 默认禁用。
- 设备规格书、型号核准证和前端 Mock 行为不能替代控制协议或现场回执语义。
- `设备资料/` 原件在保密级别和存储位置确认前保持未跟踪；仓库仅保存获批的脱敏协议差距表和字段映射。

第 1 周向甲方确认以下信息：现场型号和固件、协议版本、TCP 角色/IP/端口/网络区、登录与心跳、端序与时钟、请求及全部结果报文、指令幂等性、回执阶段、迟到/乱序/重复处理、停止/急停/通道互锁、目标 ID 生命周期、坐标与高度基准、脱敏真实抓包、现场联调窗口与回滚责任边界。

## 11. 里程碑完成判定

每个两周里程碑只有同时满足以下条件才可标记完成：

1. 数据库、领域服务、API 和对应前端消费方位于同一个可运行纵向切片。
2. 正常流程和非法迁移、重复提交、下游失败至少有一条可重复的自动化验证。
3. 列表、详情、统计卡、工作台和大屏从同一领域事实推导，数量和状态一致。
4. 认证、权限、数据范围、审计和证据不被前端或 Worker 绕过。
5. 实际验证结果已写入 PR，失败和未运行项也如实记录。
6. 另一名开发者已完成代码审查，共享联调环境只接收已合并代码。
