# 后端开发基线

版本：V1.0；建立日期：2026-09-03。

本文件是当前仓库后端开发的业务与技术起点，不是功能完成报告。配套执行规则见 [server/AGENTS.md](../server/AGENTS.md)，启动与检查入口见 [后端 README](../server/README.md)。本轮仅核查源码和编写文档，未运行构建、应用测试、数据库迁移或设备联调。

数据库字段、表关系、约束与分期迁移的设计细化见[数据库设计文档](数据库设计文档.md)。该文档是拟建设计，不改变本文对“当前仅有 V1/V2 六张表”的事实描述，也不表示已经执行建表或迁移。

## 1. 适用范围与依据

- 在同仓库 `server/` 内渐进开发，前端保留在 `dongying-vue/`，部署配置保留在 `deploy/`。不另建后端仓库，不重搭框架。
- 首期承接当前已确认的三条业务链；责任人领取、转派、SLA、完整行政处罚审批、多源融合算法研发等不是默认交付内容。
- 当前事实由源码描述，业务口径由已明确确认的需求约束；前端代码是业务资产，不是生产协议。发现冲突必须记录、确认，不静默选择一方。
- [事件驱动业务流程梳理](事件驱动业务流程梳理.md)用于理解方向，其中未确认的路线图能力不能自动成为本期字段或流程。
- 当前工作区已删除的旧后端技术方案和整体改造方案不作为依赖，不恢复它们；不依赖仓库中不存在的编号文档。

全文使用以下四种状态，可同时标记同一模块的不同能力：

| 标记 | 含义 | 使用限制 |
| --- | --- | --- |
| A：已有代码 | 仓库可定位到实现 | 本基线中的 A 均仅经静态核查，未执行运行验证；不得等同生产可用 |
| B：已确认待开发 | 现有业务边界已确认，后端能力待实现 | 进入具体开发前补齐该切片的接口、数据和验收设计 |
| C：演示实现 | Mock、浏览器内存、模拟回执或演示文件台账 | 只作流程参考或隔离测试夹具，不作真实执行证据 |
| D：待确认 | 业务规则、来源协议或部署条件缺少确认 | 记录问题和影响；不得用虚构数据填补 |

依据：[AuthController](../server/src/main/java/com/uav/lowaltitude/modules/identity/api/AuthController.java)、[AlarmController](../server/src/main/java/com/uav/lowaltitude/modules/alarm/api/AlarmController.java)、[DeviceController](../server/src/main/java/com/uav/lowaltitude/modules/device/api/DeviceController.java)。

- 保留 `/api/v1` 和 `Authorization: Bearer <session_id>`；当前 token 是持久化会话 ID，不是 JWT。不得把前端用户 ID 当后端登录凭证。
- 保留 [ApiResponse](../server/src/main/java/com/uav/lowaltitude/platform/api/ApiResponse.java) 的 `ok/data/error` 结构，错误内含 `code/message`；错误应使用匹配的 HTTP 状态，不能把失败包装成业务成功。
- 当前 [Jackson 配置](../server/src/main/resources/application.yml)为 snake_case 和忽略 null；既有接口不得全局改名或更改空值表现。新接口须明确缺失、未知、不适用的区别，需要显式 null 时在对应 DTO/契约中处理，不能默认当前配置会保留它。
- 列表当前返回 `items/page/size/total`，默认第 1 页、每页 20 条，页码至少 1、每页 1–100 条。新增列表复用结构，筛选排序等在具体接口中明确。
- 现有 ID 为字符串，登录过期时刻为 epoch 毫秒；不擅自转换既有线格式。新增接口明确时间单位、时区及状态字典，不混用秒与毫秒。
- 本轮只列接口能力，不定义全部新 URL、字段级 OpenAPI 或建表 SQL；这些随业务切片设计，不一次性猜出整套契约。

## 5. 业务状态与数据边界

### 5.1 三条流程独立建模

1. 无人机：告警触发 → 人工核实 → 一次人工发起联动反制 → 系统自动执行信号干扰 → 通知处罚部门。保留误报分支；联动是同一共享用例，实际下发和推进必须满足确认后的授权条件并依赖真实回执。交接完成不等于处罚办结，不增加手工归档环节，也不把 Mock `cases` 全量认作正式行政案件。
2. 飞行风险：`待核验 → 待通知 → 已通知`；待核验可转 `已排除`。`已通知/已排除` 保留现有终态语义；发送受理、送达、回执是独立通知记录的状态。真实渠道中何种结果允许进入“已通知”须在 Q4 确认，不能点击按钮即判成功，也不擅自增加“处置完成”风险终态。
3. 设备异常：原因与确认 → 下发重启 → 等待设备回执 → 平台恢复校验 → 关闭异常。前端摘要为 `待处理/处理中/待验证/已恢复`；设备在线、重启指令完成、异常恢复是不同事实，回执成功不直接等于平台恢复。

工作台可发起上述模块的动作，但不另建状态机。每个用例由后端统一检查当前状态、权限、前置条件及并发版本，成功后同步关联记录与审计；失败不得推进成功状态。

### 5.2 标识、来源与规则

- 平台业务主键、外部来源编号、展示编号、前端视图 key 分开。`uav:<targetId>/risk:<id>/device:<deviceId>` 不是持久化事件主键；每次设备故障有独立异常实例，历史记录不被下一次故障覆盖。
- 上报保留来源系统、来源 ID、接收时间与原始发生时间；跨来源 ID 不默认全局唯一。同目标告警的合并窗口、跨设备关联策略由 Q2/Q6 确认，不按空间接近自行合并。
- 数据分别标记真实上报、服务端推导、人工录入或演示来源。人工输入也需记录操作者和依据；推导结果留存输入依据和规则版本。
- 未知、不适用、缺失、过期应能区分，不以 0、合法、在线或成功替代未知。前端中的随机序列、固定演示时间、虚构文件哈希不得成为生产数据。
- 保留坐标系及高度基准。当前地图接入边界为 WGS-84，见[离线地图部署说明](离线地图部署说明.md)；业务接口与地图资源独立，不把旧高德代理作为后端建设前提。不明坐标系不静默转换，AGL 与 AMSL 缺少可靠转换依据时不得直接比较。
- 新增时间字段明确单位和时区，区分设备时间、接收时间、业务更新时间；业务时间通过后端统一时钟获取，测试可控。现有 epoch 毫秒字段保持兼容。
- `RISK_RULE` 高度余量、部分 `COMM_TH`、`EVID_RETAIN` 和演示处罚参数等不能未经确认用于生产判断。规则调整需有版本、影响范围及验证证据。

## 6. 开发顺序与基础加固

## 8. 后续开发验收门槛

- 每个切片先明确对象、来源、查询/写入契约、权限、合法迁移与错误场景，再写业务代码；所有 B/D 项保留完成或确认依据。
- 覆盖登录失败留痕及锁定、退出/过期/停用、动作和数据越权、敏感字段/导出控制，不能只测成功请求。
- 覆盖重复提交、并发操作、非法迁移、重复/迟到/超时回执、服务重启、恢复验证失败；确认状态、审计和关联材料一致。
- 覆盖未知数据、单位与基准不一致、证据缺失/哈希异常、外部接口失败；缺失信息不生成成功或合法结论。
- 区分 Mock、回放和真实来源；无真实配置不得悄悄降级或以模拟报告通过实联验收。
- H2 用于快速应用验证，不证明 PostgreSQL/PostGIS 的空间 SQL、约束、锁或迁移兼容。涉及这些能力时使用隔离真实数据库验证，不对生产库跑测试或迁移试验。
- 检查测试实际执行数量与报告，当前认证类显式指定；不得以构建退出成功、空列表或占位日志宣称功能完成。具体命令和按改动范围执行的要求见 [后端规则](../server/AGENTS.md)。
