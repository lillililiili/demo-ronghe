# 口径说明书：界面上"说不了"的几种提示

> 面向验收。本文解释系统在**拿不到某项事实时**给出的几类提示分别代表什么、在什么情况下出现、为什么它们不是缺陷，以及各自在什么条件满足后会消失。
>
> 内部依据见 `docs/交付/内部依据/`。

## 一句话原则

**拿不到就说拿不到，不编结论。**

这套系统在很多地方宁可写"协议未提供""未知""不可判定"，也不显示一个看起来完整、实则猜出来的数字或结论。原因很直接：这些内容会进入告警处置、合法性研判、处置授权和行政处罚的记录，一个编出来的结论事后没有人能解释它从哪来。**因此，看到这几类提示时，应当理解为"系统如实说明它现在拿不到这项事实"，而不是"这里坏了"。**

四类提示的区别——**判断责任方看这张表**：

| 说法 | 含义 | 谁来消除 |
| --- | --- | --- |
| **协议未提供 …** / **未接入** | 外部来源根本没有提供这个能力，或这条链路还没接进来 | 对接方：设备厂商、外部系统、上级单位 |
| **…未知** | 来源接进来了，但**这一条记录**缺这项事实 | 数据本身：该记录补齐后自然变化 |
| **不可判定** | 引擎按现有输入得不出结论 | 数据本身：补齐计划、航线、时间等输入后重新研判即可 |
| **暂不可用 / 校验异常** | 这一段当前取不到，或取到了但校验没通过 | 视具体情况，见第四节 |

另有一个词只出现在**交付材料里、不出现在页面上**：

| 说法 | 含义 | 谁来消除 |
| --- | --- | --- |
| **待确认** | **我们不知道，需要客户或厂家给答案。** 说的是这件事还没有结论，不是系统的状态 | 客户或设备厂家 |

**"协议未提供"与"待确认"最容易被混为一谈，但责任方不同**：前者是"对方的东西没有这个能力，接不进来"；后者是"连该怎么做都还没定，得先有人给答复"。交付材料里凡是写"待确认"的地方，都同时写明了要问谁——看到它请当成一个**待回答的问题**，而不是一条待开发的功能。

## 一、"协议未提供 …" 与 "未接入"

**这一类只有少数几处，而且措辞都指明了具体原因。** 这是有意的：只说"没接入"，看的人无从判断是谁的事、要等什么；说"协议未提供实时视频流"，责任方与条件都在这句话里。

### 1. 实时视频（融合感知页、告警事件页）

目标卡片与告警卡片上的"实时视频"按钮是**灰的、点不动的**，鼠标停上去写**"协议未提供实时视频流"**。告警页底部另有一句说明：**实时视频协议未提供；轨迹回放仅定位已加载轨迹点，不是视频。**

- **代表什么**：设备协议里没有视频流这一项能力，不是本平台少做了一个页面。
- **为什么不是缺陷**：按钮保留是为了让验收方看到完整的处置动线；但**能点的按钮必须真的能用**，所以在协议提供该能力之前一律禁用，不做"点了弹一个假成功"的假象。
- **什么条件满足后消失**：设备方在协议中提供视频流能力并完成对接后。
- **要特别注意**："轨迹回放"不是视频回放，它只是把已经加载的轨迹点重新定位一遍。验收时这两件事不要混。

### 2. 设备的部分控制动作（设备管理页）

设备控制表单中标注 **"设备协议未提供"**：角度移动、home 点、辅助识别与跟踪开关等动作在当前协议里没有定义。

### 3. 我的工作台：联动反制、通知处罚部门

这两项的状态可能显示 **"未接入"**。

**这里有一处必须分清的差别**：同一个位置有三种不同说法，含义完全不同，不可混为一谈——

| 显示 | 含义 |
| --- | --- |
| **尚无授权 / 无记录** | 链路是通的，这个事件确实还没有人申请过、或确实没有记录 |
| **未接入** | 这条链路本身没接进来，系统不知道有没有 |
| **读取失败** | 链路接进来了，这一次没读到 |

把中间那种显示成"尚无授权"，会让人以为"确认过、没有"，从而错过一次本该有的处置。这三种分开，是有意的。

### 4. 处罚案件不会自动外报

处置与处罚页注明：**案件只在本平台内办理，不会自动报送外部处罚系统。**

**代表什么**：立案、裁量、决定书、复核都在平台内完成并留痕，但决定书不会自动报送到外部处罚系统，也不会自动送达。**这一点在验收时需要特别确认**：平台内的记录是完整的，对外的那一步是人工的。

### 5. 设备急停的协议限制

处置授权被撤销时，系统会尝试让设备急停；如果该设备的协议里根本没有急停动作，记录写的是 **"授权已撤销；设备急停未执行（协议未提供）"**，而不是"停止失败"。

**区别很重要**：前者说明协议没有这个能力，后者会让人以为设备抗命。

## 二、"…未知"

这一类是**这一条记录缺某项事实**，而不是能力没接进来。它出现在具体字段上，措辞总是"某某未知"：

| 出现的地方 | 说的是 |
| --- | --- |
| 合法性研判的理由 | 起降点未知、飞手/单位未知、航线几何未知、计划时间未知、位置未知、高度基准或范围未知 |
| 目标与设备状态 | 高度未知、距离未知、状态未知、置信度未知 |
| 空间安全风险 | 异物高度未知、趋势未知 |
| 处置停止结果 | 设备急停结果未知 |

**为什么不是缺陷**：这些字段依赖具体记录里是否带了这项数据。飞行计划里没填起降点，系统就写"起降点未知"，而不是随便填一个位置——**一个编出来的起降点会让整条研判结论失去依据**。

**什么条件满足后消失**：对应记录补齐该字段之后，同一条重新研判即可。

---

## 三、"不可判定"

**这是引擎判不了，不是"等人来确认"。** 两者的区别在验收时很重要：

- 判不了 → 需要补输入（计划、航线几何、时间、设备回报）；
- 等人确认 → 需要有人去点一下。

系统在这两种情况下用的是不同的说法，不会把前者显示成后者。

### 它出现在哪

| 位置 | 这一栏在说什么 |
| --- | --- |
| 合法性研判页 · 研判结论与页签 | 引擎无法判定这次飞行是否合法 |
| 合法性研判页 · 单条规则结果 | 这条规则的输入不足，判不了 |
| 合法性研判页 / 飞行监管页 · 计划匹配 | 无法确定这架飞行器对应哪份计划 |
| 合法性研判页 · 高度关系 | 无法确定实际高度与计划高度带的关系 |
| 飞行监管页 · 计划时间 | 计划的开始或结束时间缺失时，时间关系判不了 |
| 设备接入调测页 · 调测结论 | 这项检查在当前条件下得不出通过或失败的结论 |

### 什么条件满足后消失

对应的输入补齐后，同一条记录重新研判即可得出结论——**不需要改代码**。例如：飞行计划补上起止时间后，时间关系不再是"不可判定"；航线几何提供后，计划匹配可以判定。

---

## 四、"暂不可用"与"校验异常"

这一类来自接口返回的**可用性标记**：接口不是简单地把内容省略，而是明确说明这一段为什么没有内容，页面据此译成中文。**页面不会在拿不到内容时自行猜一个说法。**

| 界面显示 | 含义 | 是不是缺陷 |
| --- | --- | --- |
| **无权限查看** | 当前账号没有查看这一段的权限 | 不是。按角色授权，属于正常 |
| **尚无引擎研判** | 这条记录还没有被研判过 | 不是。研判后自然出现 |
| **暂不可用** | 这一段当前取不到 | 需要看现场情况 |
| **校验异常** | 这份证据文件的完整性校验没有通过 | **需要关注**，见下 |

**"校验异常"要当回事。** 它表示这份证据文件的校验没通过——可能是文件被替换、损坏，或存储介质有问题。证据链区块会把这样的记录数量单独标出来（例如"证据链（8 项 · 1 份校验异常）"）。**验收时若看到这个标记，应当追查那一份文件，而不是当成显示问题。**

---

## 验收时的建议做法

1. **先分清是哪一类**：能力没有（协议未提供 / 未接入）、这条记录缺事实（未知）、引擎判不了（不可判定）、这一段取不到（暂不可用）。四类的责任方不同。
2. **"尚无授权 / 未接入 / 读取失败"三种说法要分开看**，它们不是同义词。
3. **"校验异常"单独追查**，这一项与其他提示性质不同。
4. **禁用的按钮不是没做完的界面**：它们的提示里写明了禁用原因，且一律不做"点了给个假成功"的处理。
5. **"轨迹回放"不是视频回放**，不要把它当成视频能力已经接入的证据。
