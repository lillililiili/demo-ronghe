# 协作开发环境

> 2026-09-16 适用说明：本文环境拓扑和命令保留早期协作背景。唯一后端及管理端现位于同级 `../houtaiguanli`，启动与迁移以[后台 README](../../houtaiguanli/README.md)为准；本仓只维护业务前台。Git 约束已按用户后续决定更新为直接在本地 `main` 工作，不创建分支或工作树，见[根 AGENTS.md](../AGENTS.md)。历史环境说明不证明当前服务器、CI 或分支保护设置。

本项目采用“两套个人本地库 + Flyway 同步结构 + 一套共享联调库 + 脱敏数据集 + PR 审核”。日常开发数据库互相隔离，代码和迁移通过 Git 同步；只有合并后的代码进入共享联调环境。

## 1. 环境拓扑

```text
开发者 A：前端 + 后端 + 本地 uav 数据库 ─┐
                                         ├─ Git/Flyway ─→ 共享 uav_integration 数据库
开发者 B：前端 + 后端 + 本地 uav 数据库 ─┘
```

- 本地数据库只监听 `127.0.0.1`，不能被另一台电脑直接访问。
- 共享联调库部署在内网服务器或 VPN 可达主机，不使用任一开发者的日常数据库。
- `server/src/main/resources/db/migration/` 是数据库结构的唯一真源。
- 脱敏数据包括合成账号、组织区域和设备演示数据；尚未迁移的业务页继续使用明确标识的前端 Mock，不把真实业务数据复制到开发环境。

## 2. 首次启动

准备 Docker Desktop、JDK 17、Node.js 22 和 npm。Windows PowerShell 在仓库根目录执行：

```powershell
.\scripts\bootstrap-dev.ps1
```

脚本启动个人 PostgreSQL/PostGIS，并在缺少 `node_modules` 时安装前端依赖。之后分别打开两个 PowerShell 窗口：

```powershell
cd dongying-vue
npm run dev
```

```powershell
cd server
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```

访问地址：

- 前端：`http://127.0.0.1:5173/`
- 后端健康检查：`http://127.0.0.1:8080/actuator/health`

运行 `.\scripts\verify-dev.ps1` 会检查两个地址、真实登录、`/auth/me` 和 Vite `/api` 代理。后端本地 profile 会显式启用合成账号 Seeder；只创建超级管理员 `admin1`，默认密码 `changeme`，可用 `APP_DEV_SEED_PASSWORD` 覆盖。其他角色和账号由超级管理员按需创建。相同本地账号分别位于两套个人数据库，互不共享会话或数据。

## 3. 日常拉取与数据库结构同步

拉取代码后先查看是否新增迁移，再启动后端。Flyway 会按版本顺序应用尚未执行的迁移。

数据库协作规则：

1. 已提交并应用的 `V1__init.sql`、`V2__outbox_inbox.sql` 以及后续迁移不得修改或删除。
2. 新结构只能新增迁移，推荐名称 `VyyyyMMddHHmm__description.sql`，例如 `V202609031430__add_alarm_status.sql`，降低并行开发重号概率。
3. 每个迁移必须能从空库按顺序执行，并在独立 PostgreSQL/PostGIS 环境验证。
4. 不在共享联调库手工改表，不用 `flyway repair` 掩盖迁移冲突。
5. 破坏性结构变更必须在 PR 中写明数据迁移、应用回退和备份方案。

## 4. 脱敏数据

- 合成账号由 `LocalUserSeeder` 创建，只有 `app.dev-seed.enabled=true` 时才运行。
- 运维模拟设备由 `LocalDeviceSeeder` 创建，且仅在 `test` profile 运行；`local` 不再预置 `DEV-MOCK-*` 台账。
- `local` 与 `test` profile 显式启用账号种子；默认环境和 `integration` profile 默认关闭。
- 新增开发数据必须使用虚构姓名、设备号、坐标和文件，不得从生产库直接复制。
- 可重复的基础字典使用新 Flyway 迁移；大体量演示数据使用独立、幂等的开发 Seeder。
- 临时复现数据使用脱敏后的 `pg_dump` 文件点对点传递，不提交数据库备份、日志、令牌、密码或证据文件。

## 5. 共享联调数据库

在内网服务器上复制配置并填写真实值：

```powershell
Copy-Item deploy/.env.integration.example deploy/.env.integration
docker compose --env-file deploy/.env.integration -f deploy/compose.integration.yml up -d --wait
```

必须把 `INTEGRATION_DB_BIND_ADDRESS` 设置为服务器的内网/VPN 地址，并通过主机防火墙只允许两位开发者或 CI 节点访问。不要使用 `0.0.0.0`，不要把 `5432` 暴露到公网，真实 `.env.integration` 不得提交。

连接共享库的后端使用 `integration` profile，并在进程环境中提供：

```text
DB_URL=jdbc:postgresql://<内网地址>:5432/uav_integration
DB_USER=<联调用户>
DB_PASSWORD=<联调密码>
APP_DEV_SEED_ENABLED=false
APP_BOOTSTRAP_ADMIN_ENABLED=true
APP_SUPER_ADMIN_ACCOUNT=<唯一超级管理员账号>
APP_SUPER_ADMIN_NAME=<超级管理员姓名>
APP_SUPER_ADMIN_PASSWORD=<独立强密码>
```

仅在共享库 `app_user` 为空的首次启动设置 `APP_BOOTSTRAP_ADMIN_ENABLED=true`。服务会一次性创建唯一超级管理员并要求首次登录改密；确认创建成功后删除 `APP_SUPER_ADMIN_PASSWORD`，并把开关改回 `false`。`APP_SUPER_ADMIN_ACCOUNT` 必须继续保留，以便每次启动校验唯一超级管理员。初始化临时密码必须满足 6–32 位复杂度要求，不得写入仓库、启动命令历史或日志；用户首次登录后自行设置的新密码同样为 6–32 位。

若超级管理员忘记密码，只能由有服务器环境权限的运维人员执行一次性恢复：设置 `APP_SUPER_ADMIN_RECOVERY_ENABLED=true` 和 `APP_SUPER_ADMIN_RECOVERY_PASSWORD=<新强密码>`，并以 `--spring.main.web-application-type=none` 启动后端。程序校验并重置指定超级管理员、撤销其全部会话、设置首次改密、写入不含密码的审计后自动退出。完成后立即删除恢复密码并关闭开关；系统不提供网页找回超级管理员密码的入口。

联调环境只在 PR 合并后升级。升级前执行备份，升级人记录 Git 提交、迁移版本、执行时间和结果。共享服务器地址、防火墙、备份位置与凭据需要由项目成员在线下确认，仓库不保存这些真实信息。

## 6. 当前 Git 规则与历史 PR 方案

- 用户已明确只在本地 `main` 修改和提交，不创建分支或工作树；保留已有工作树及改动，不自行清理或搬运。
- 拉取后核对并重新应用本地改动和删除状态；备份未重新应用不等于更新完成。
- 接口变更同时检查业务前台与管理端两个消费者，记录请求、响应和兼容策略。
- 数据库迁移尽早提交或提前约定版本，避免双方修改同一迁移文件。
- 早期“短分支 + PR + 禁止直接 push”为历史方案，不再作为本仓默认工作指令；远端实际保护设置需在提交任务中核对，本文不声称已配置或修改。

CI 执行范围以所属仓库当前工作流为准；本次文档核对未运行 CI 或更改远端设置。提交时如实说明实际验证及未执行项。

## 7. 边界

共享联调环境不是生产环境。系统管理与设备运维已接入后端，其他未迁移业务页仍可能使用明确标识的 Mock；共享数据库只用于已实现能力的联调，不能据此宣称真实设备、生产权限或业务闭环已经完成。
