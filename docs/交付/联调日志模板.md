# 联调日志模板

> 面向联调当天。每一路填一张表，填完就是验收记录。
>
> 内部依据见 `docs/交付/内部依据/`。

联调当天每一路填一张表。**填完就是验收记录**，不用事后回忆。

三条填写规矩：

- 「我们解析出的字段」照抄平台上看到的值，**不要凭印象写**。取法见文末「当天怎么取报文」。
- 结论只有三种：**通过 / 偏差 / 协议未定义**。写「偏差」时必须在「遗留」里写清楚差在哪。
- 拿不准的写「待确认」和要问谁，不要留空——留空的格子事后没人认领。

配套文档：《协议缺口矩阵》（哪些能力协议没定义、我们没实现、页面会显示什么）。

## 九、当天怎么取报文

### 9.1 查平台收到了什么

平台收到的每一条设备报文都原样存在 `inbox_message` 里。**按哈希反查最可靠**，不依赖消息编号的写法：

```sql
SELECT source, source_msg_id, received_at FROM inbox_message WHERE payload_hash = '<你算出的 sha256>';
```

能查到，就说明发出的报文与平台收到的**逐字一致**。

按来源和时间翻最近的报文：

```sql
SELECT source, source_msg_id, received_at, status, CAST(payload AS VARCHAR)
FROM inbox_message
WHERE source LIKE 'lingyun:%' OR source LIKE 'eo-edge:%'
ORDER BY received_at DESC
FETCH FIRST 20 ROWS ONLY;
```

只看没处理成功的：

```sql
SELECT source, source_msg_id, status, last_error, fusion_attempts
FROM inbox_message
WHERE status <> 'PROCESSED'
ORDER BY received_at DESC
FETCH FIRST 20 ROWS ONLY;
```

`last_error` 就是被拒的原因；`fusion_attempts` 是已经重试的次数。

### 9.2 现场设备没到位时，用回放顶上

平台自带一份可发布的报文文件，逐行发布就能复现全部场景，用来先把链路验通：文件与发布方法见 `docs/直连接入计划/凌云回放说明.md`。

**发布时注意**：文件里的 `payload` 已经是设备会发出来的那段文本，**原样发布，不要再序列化一次**——重新序列化会改变键的顺序或空白，平台算出的哈希就和文件对不上，9.1 的反查会失败。
