# 反制急停：改前、改后怎么不一样

2026-09-14 · 第二版设计稿 · 本稿用于确认画面和操作，功能尚未开发。

这次要解决的是：发现反制需要马上停时，操作员能在当前画面直接点击，马上看到处理进度，并知道设备到底停了没有。

## 一眼看懂改了什么

| 看哪里 | 现在 | 改后 |
| --- | --- | --- |
| 在哪儿停 | 在“处置授权”的记录旁点“停止” | 在告警详情和工作台的反制区域，直接看到红色“急停本次处置” |
| 按钮长什么样 | 和其他操作同一类的普通按钮 | 固定在反制卡片右上角，红底白字，带停止图标，与启动操作分开 |
| 点之前要做什么 | 打开弹窗，先填停止原因，再点“停止处置” | 点击一次就发起急停，原因事后补填 |
| 停哪些动作 | 当前选中的一条授权 | 本事件正在执行的反制和关联干扰一起处理；还没开始的关联动作不再启动 |
| 点完看哪里 | 查看该授权的状态和设备停止说明 | 原来的反制区域直接显示处理进度，展开可看每台设备的反馈 |
| 设备还没停怎么办 | 已有说明能区分授权撤销和设备停止，但跟进入口不够集中 | 提示一直留在画面上，显示哪台没确认，并给出查询、重试或现场核查入口 |
| 以后还要继续怎么办 | 本次不改写已有历史记录 | 不自动恢复，需要重新发起处置申请 |

“现在”依据当前代码中的授权列表和停止弹窗整理，画面示意不代表现有页面的逐像素截图。原系统已经有设备停止结果的限定说明，这次是在此基础上把入口和跟进过程做得更直接。

## 画面怎么改

### 1. 反制正在执行：急停放在眼前

告警详情里的反制卡片、工作台打开同一事件后的反制区域，使用同一套布局。

```text
反制与干扰                                 [ ■ 急停本次处置 ]
当前事件：所选事件                           停止本事件反制及关联干扰
──────────────────────────────────────────────────────────
联动反制    执行中
关联干扰    尚未开始
执行设备    当前绑定的设备
```

按钮使用红底白字，高度约 40～44 像素，文字不能省略为单独图标。卡片标题和操作区保持在卡片顶部可见，长内容在下面滚动。较窄画面把操作区排到标题下方，仍然放在内容前面。

启动和急停不要紧挨着，也不要在同一个位置把“启动”突然换成“急停”，避免连续点击误触。当前正在执行时，急停是这个区域最醒目的操作；查询、详情、历史记录使用普通按钮或文字链接。

按钮旁边先把范围写清楚。这版以“当前事件”为范围，不增加全平台急停。若同一台设备还被其他事件共用，而且停止会把整台设备一起关掉，画面必须明确列出受影响事件；不能写“只影响本事件”。共用设备的处理规则需要在接入时核实。

### 2. 点击急停：原地显示进度

点击后不用跳页面，也不先打开原因表单。原按钮立即显示“正在提交…”，防止重复点击。

后台确认已中止本次处置后，卡片变为：

```text
反制与干扰                                      本次处置已中止
──────────────────────────────────────────────────────────
等待设备停止反馈
已发出停止命令，设备是否停止仍需确认。

联动反制    已中止
关联干扰    未启动，已阻止继续执行

[查看设备反馈]   补充急停原因
```

“本次处置已中止”表示平台不再继续这次处置。“等待设备停止反馈”表示设备结果还没拿到，两件事分开写。若命令还在排队，改写“停止命令正在排队”，不能提前显示“已发出”。若连请求是否收到都不确定，则显示“急停请求结果未知，正在核对”，不能显示“已中止”。

这块提示一直保留，不采用弹出几秒就消失的成功提示。切换页面再回来，仍然能看到同一条停止进度。

### 3. 设备没有确认：让人看清下一步做什么

```text
反制与干扰                                      本次处置已中止
──────────────────────────────────────────────────────────
设备停止尚未确认
有设备未返回停止结果，请继续核查。

设备                 当前反馈                    下一步
本次反制设备         等待反馈超时                [查询反馈] [重试停止]

补充急停原因    查看操作记录
```

未确认提示使用醒目的警示样式，并写出设备名称和原因。按钮按实际情况提供：

| 设备情况 | 画面怎么说 | 可以做什么 |
| --- | --- | --- |
| 请求结果未知 | 暂时无法确认是否已收到急停请求 | 先查询当前结果，避免反复发命令 |
| 已发出、还没反馈 | 已发出停止命令，等待设备反馈 | 查询反馈 |
| 等待超时或明确失败 | 设备停止尚未确认 | 查询反馈；符合重试条件时重试停止 |
| 设备离线 | 设备离线，无法确认停止 | 查看设备、登记现场核查 |
| 设备不支持远程停止 | 无法远程停止，请现场处理 | 查看设备、登记现场核查 |
| 控制器确认全关 | 已收到全关确认，实际停机仍需核查 | 查看反馈依据、登记现场核查 |
| 有可信的停机状态或现场确认 | 设备已确认停止 | 查看确认来源和时间 |

四通道设备现有能力叫“全关”。收到全关回执，只能按回执实际能证明的内容展示，不能直接写“急停成功”。现场确认需要留下谁确认、什么时候确认、依据是什么。

### 4. 确认停止后：保留结果，不诱导恢复

```text
反制与干扰                                      本次处置已中止
──────────────────────────────────────────────────────────
设备已确认停止
确认来源：设备状态反馈 / 现场核查（显示实际来源）

[查看停止记录]   补充急停原因
```

确认完成后不再显示执行中的进度效果，也不出现“恢复执行”大按钮。若后续确实需要继续反制，从正常的处置申请入口重新申请。急停不等于告警解除，原事件仍然按实际情况跟进。

## 操作上少了哪几步

**现在：**进入处置授权 → 找到记录 → 点击停止 → 填写原因 → 确认停止 → 查看结果。

**改后：**在当前事件反制区域点击急停 → 直接看到处理进度 → 有未确认设备就跟进 → 事后补原因。

这版采用“一次点击发起”，不加长按或滑动，也不弹第二次确认。通过明确事件、明确范围、固定按钮位置和与启动操作分隔来降低误触。QGroundControl 的滑动确认用于空中停电机；本页面借鉴其动作表达，不照搬那个手势。

原因补填放在停止进度下面，默认收起。点击“补充急停原因”才展开，可选择误操作、目标信息变化、设备异常、现场要求或其他，并填写说明。没填时保留“原因待补充”；填写失败保留输入，不影响已经发起的停止。补原因不能抢走查看设备反馈的注意力。

## 几个容易漏掉的地方

- **反制已经完成，但干扰还在执行：**仍能急停本次处置，停止正在执行的干扰，已完成的反制历史照常保留。
- **已经点击急停：**没开始的关联干扰不能随后又自动启动；网络恢复后也不能把旧启动指令重新执行。
- **授权已结束，设备还没确认停止：**保留设备跟进入口，不能因为授权列表显示“已停止”就把这件事隐藏。
- **有多台设备：**逐台显示结果，哪台未确认就跟进哪台，不能只显示一个总的“成功”。
- **无操作权限：**能按原权限查看状态，按钮显示不可用并说明原因；权限由后台检查。
- **还没有开始执行：**使用“撤销本次处置”；没有执行中的处置时，不摆一个可点击的红色急停按钮。
- **打开了别的事件：**急停对象跟着当前事件，点击时也要核对对象；不能误停上一次查看的事件。

## 其他页面怎样跟着变

| 页面 | 需要同步看到什么 |
| --- | --- |
| 告警详情 | 本次处置已中止、设备停止是否确认；告警本身继续跟进 |
| 工作台的该事件 | 有设备未确认时保留待核查提醒，点开就是对应设备反馈 |
| 处置授权列表和详情 | 对应授权已中止，并能查到这次急停的原因和经过 |
| 设备管理 | 同一台设备的停止指令和真实反馈，与反制页面一致 |
| 操作记录 | 谁点了急停、影响哪些处置、设备怎样反馈、谁补了原因或现场核查 |

不同页面只是看同一件事的不同入口，不能一个写“全部停止”，另一个还写“等待反馈”。

## 这版参考了什么

- [Universal Robots PolyScope X 控制界面](https://www.universal-robots.com/manuals/EN/HTML/SW10_9/Content/prod-usr-man/software/PolyScopeX/polyx-introduction/polyx-basics-falcon.htm)：参考固定控制区与单独查看设备状态的做法。本版把它收敛到反制卡片顶部。

## 做完后，用这几件事检查

1. 正在看告警时，不去授权列表，也能直接找到急停。
2. 没填原因，也能发起停止；点击后不跳页面，马上看到提交进度。
3. 设备还没确认时，画面不会出现笼统的“急停成功”。
4. 急停后，关联干扰不会继续自动启动；已经启动的干扰一起停止。
5. 设备超时、离线、不支持停止时，能看懂原因，也能找到下一步入口。
6. 刷新或换页回来，停止进度和待核查项仍在。
7. 补原因、查询、重试、现场核查都有对应结果和记录；停止后不会自动恢复。
