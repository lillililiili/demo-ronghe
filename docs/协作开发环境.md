# 协作开发环境

本项目采用“两套个人本地库 + Flyway 同步结构 + 一套共享联调库 + 脱敏数据集 + PR 审核”。日常开发数据库互相隔离，代码和迁移通过 Git 同步；只有合并后的代码进入共享联调环境。

## 1. 环境拓扑

```text
开发者 A：前端 + 后端 + 本地 uav 数据库 ─┐
                                         ├─ Git/Flyway ─→ 共享 uav_integration 数据库
开发者 B：前端 + 后端 + 本地 uav 数据库 ─┘
```

- 本地数据库只监听 `127.0.0.1`，不能被另一台电脑直接访问。
- 共享联调库部署在内网服务器或 VPN 可达主机，不使用任一开发者的日常数据库。
- `server/src/main/resources/db/migration/` 是数据库结构的唯一真源。
- 当前脱敏数据只有合成的开发账号；业务演示数据仍由前端 Mock 提供，不把真实业务数据复制到开发环境。

## 2. 首次启动

准备 Docker Desktop、JDK 17、Node.js 22 和 npm。Windows PowerShell 在仓库根目录执行：

```powershell
.\scripts\bootstrap-dev.ps1
```

脚本启动个人 PostgreSQL/PostGIS，并在缺少 `node_modules` 时安装前端依赖。之后分别打开两个 PowerShell 窗口：

```powershell
cd dongying-vue
npm run dev
```

```powershell
cd server
.\mvnw.cmd spring-boot:run "-Dspring-boot.run.profiles=local"
```

访问地址：

- 前端：`http://127.0.0.1:5173/`
- 后端健康检查：`http://127.0.0.1:8080/actuator/health`

运行 `.\scripts\verify-dev.ps1` 可检查两个地址。后端本地 profile 会显式启用合成账号 Seeder；默认账号仅限隔离开发环境，密码可用 `APP_DEV_SEED_PASSWORD` 覆盖。

## 3. 日常拉取与数据库结构同步

拉取代码后先查看是否新增迁移，再启动后端。Flyway 会按版本顺序应用尚未执行的迁移。

数据库协作规则：

1. 已提交并应用的 `V1__init.sql`、`V2__outbox_inbox.sql` 以及后续迁移不得修改或删除。
2. 新结构只能新增迁移，推荐名称 `VyyyyMMddHHmm__description.sql`，例如 `V202609031430__add_alarm_status.sql`，降低并行开发重号概率。
3. 每个迁移必须能从空库按顺序执行，并在独立 PostgreSQL/PostGIS 环境验证。
4. 不在共享联调库手工改表，不用 `flyway repair` 掩盖迁移冲突。
5. 破坏性结构变更必须在 PR 中写明数据迁移、应用回退和备份方案。

## 4. 脱敏数据

- 合成账号由 `LocalUserSeeder` 创建，只有 `app.dev-seed.enabled=true` 时才运行。
- `local` 与 `test` profile 显式启用；默认环境和 `integration` profile 默认关闭。
- 新增开发数据必须使用虚构姓名、设备号、坐标和文件，不得从生产库直接复制。
- 可重复的基础字典使用新 Flyway 迁移；大体量演示数据使用独立、幂等的开发 Seeder。
- 临时复现数据使用脱敏后的 `pg_dump` 文件点对点传递，不提交数据库备份、日志、令牌、密码或证据文件。

## 5. 共享联调数据库

在内网服务器上复制配置并填写真实值：

```powershell
Copy-Item deploy/.env.integration.example deploy/.env.integration
docker compose --env-file deploy/.env.integration -f deploy/compose.integration.yml up -d --wait
```

必须把 `INTEGRATION_DB_BIND_ADDRESS` 设置为服务器的内网/VPN 地址，并通过主机防火墙只允许两位开发者或 CI 节点访问。不要使用 `0.0.0.0`，不要把 `5432` 暴露到公网，真实 `.env.integration` 不得提交。

连接共享库的后端使用 `integration` profile，并在进程环境中提供：

```text
DB_URL=jdbc:postgresql://<内网地址>:5432/uav_integration
DB_USER=<联调用户>
DB_PASSWORD=<联调密码>
APP_DEV_SEED_ENABLED=false
```

联调环境只在 PR 合并后升级。升级前执行备份，升级人记录 Git 提交、迁移版本、执行时间和结果。共享服务器地址、防火墙、备份位置与凭据需要由项目成员在线下确认，仓库不保存这些真实信息。

## 6. 分支与 PR

- 从最新 `main` 创建短生命周期分支：`feature/<主题>`、`fix/<主题>`、`docs/<主题>`。
- 本地 `main` 只跟踪 `origin/main`；不要在 `main` 上创建尚未推送、却被多个功能分支共同依赖的前置提交。
- 公共工程调整使用独立 PR，合并后功能分支再同步最新 `main`。
- 一个 PR 聚焦一个可验收改动；另一位开发者审核后再合并。
- 接口变更同时检查 Vue 与 legacy 消费者，并在 PR 中写清请求、响应和兼容策略。
- 数据库迁移尽早提交或提前约定版本，避免双方修改同一迁移文件。
- 多会话协作必须先固定已跟踪的任务说明、Base 提交、文件所有权和验收门禁；不得把另一工作区中的未跟踪文件作为唯一任务依据。
- 同一波次只有总协调会话可以派工；实现会话只改其独占范围，独立审查会话只读检查，定时汇总会话不发布技术指令。具体见[协作会话工作流](协作会话工作流.md)。
- GitHub 仓库为 `main` 开启分支保护：至少 1 个审批、CI 通过、禁止直接 push。

CI 会执行前端构建、后端普通测试和显式认证集成测试。PR 提交者还需如实填写 `.github/pull_request_template.md` 中的验证结果。

## 7. 边界

共享联调环境不是生产环境。当前前端仍以 Mock 数据为主，后端告警与设备列表仍为空实现；共享数据库只用于已实现能力的联调，不能据此宣称真实设备、生产权限或业务闭环已经完成。
