## 0. 先建立正确坐标系

这个项目不是 UOM，也不是行政处罚办案系统。

| 系统 | 谁建 | 干什么 |
| --- | --- | --- |
| 国家 UOM（民用无人驾驶航空器综合管理平台） | 民航局 | 实名登记、执照、运营合格证、空域查询、飞行活动申请 |
| 上级管服 / 空管服务平台 | 空管或地方低空服务 | 下发权威计划、空域、规则 |
| **本平台** | 山东融瓴 / 东营值班室私有化部署 | 多源感知融合 → 合法性与空间风险研判 → 事件值班闭环 → 受控反制与证据归档 |
| 公安/机场/执法系统 | 外部 | 现场处置、行政处罚、刑事案件 |

招标文件把四层关系写死了，顺序不能颠倒：

1. **融合感知**是技术底座。
2. **合法性 + 空间安全风险**是业务判断。
3. **事件驱动**是运行方式。
4. **授权处置 + 证据归档**是管理闭环。

机器处理全量目标；人只处理不确定项、紧急项和必须由人承担责任的决策。\
识别置信度 ≠ 违法概率 ≠ 可以反制。

## 2. 建议学习顺序（约 4 个半天）

不要从刑法或设备协议开始。按「谁有权飞 → 飞哪里 → 怎么被看见 → 怎么处置 → 怎么处罚」读。

## 4. 法规条款 → 本平台业务对照

下面按值班室真实问题组织，而不是按法条顺序。

### 4.1 天上飞的是什么：分类不能只用「无人机/鸟」

条例按性能把无人驾驶航空器分为 **微型、轻型、小型、中型、大型**。CCAR-92 再按运行风险分为 **开放类、特定类、审定类**。

对本平台：

- 光电分类输出「无人机 / 鸟 / 气球 / 风筝 / 未知」。规范写死：**未知不得直接标成鸟类**。
- 非无人机合法性判定为「不适用」，走空间安全风险，不进非法飞行待办。
- 机场周边鸟群可以生成飞行安全事件（东营有黄河三角洲候鸟场景）。
- 中型/大型还有适航、运营合格证；本平台匹配计划时缺字段不得判合法。

### 4.2 它有没有资格飞：身份、执照、保险、计划

法律要求大致是：

- 所有者实名登记，取得登记标志后才能激活使用（CCAR-92 第 92.205 条；GB 46761 从 2026-05-01 强制激活）。
- 操控微型、轻型：一般不强制执照，但要满足安全操控要求；小型及以上及超视距等要执照。
- 经营性飞行、以及使用小型/中型/大型做非经营性飞行，要依法投保责任保险。
- 管制空域内的飞行活动，一般要在拟飞行前 1 日 12 时前通过 UOM 申请；空管前 1 日 21 时前批复。
- **免申请**的常见情形：微型/轻型/小型在**适飞空域**内飞行；常规农用作业。不是「所有 120 米以下都随便飞」。

对应本平台 C01/C02 和飞行计划页：

- 权威计划来自上级管服，默认只读。
- 无上级数据时，本地导入必须标注「本地临时」，不得显示为上级下发。
- 匹配要逐项给出：时间窗、航线/走廊、高度、起降点、无人机、飞手。
- **缺关键字段、定位不可靠、临界边界 → 只能待确认，不能高置信非法，更不能判合法。**

规范默认硬规则（一票否决，招标方可书面替换）：

1. 进入生效中的禁飞区。
2. 无有效飞行计划且位于禁飞区。
3. 进入书面指定的重大活动保护区。

临界缓冲默认：水平距边界 100 米内、高度距限高 ±30 米内，不得给高置信非法。\
高度必须标明 AGL（距地）还是 AMSL（海拔）；设备不上报距地高时，限高类不得用海拔冒充距地高给出非法。

### 4.3 它在哪儿飞：管制空域 vs 适飞空域

条例把真高 **120 米以上**、机场周边、军事禁区、重要基础设施、重大活动区等划为管制空域。其余由空管划设适飞空域。山东省 2026 年 5 月把适飞空域扩到约 39.1%，但这是会调整的图层。

东营还要叠加：

- 胜利机场净空保护区。
- 黄河三角洲候鸟迁徙期临时管控。
- 市公安可在人员聚集场所周边适飞空域内采取警示、限飞、疏导。

对应空域管理页：规则必须有 ID、版本、来源、有效期、优先级。规则更新后活动目标自动重算新版本，历史事件引用旧版本。

### 4.4 系统怎么「看见」它：三路感知 + Remote ID

规范的三路接入：

| 路 | 设备 | 法律/业务含义 |
| --- | --- | --- |
| 第一路 | 融合感知箱 ← 雷达、光电、反制 | 发现、确认、受控处置 |
| 第二路 | 5G-A 通感直连云端 | 网联无人机身份与链路 |
| 第三路 | TDOA/AOA 直连云端 | 目标/遥控器/飞手位置 |
| 辅助 | ADS-B、气象 | 有人机协同与环境，不单独报价成第四路 |

Remote ID（运行识别）从 2026-05-01 起，新生产民用无人机应在飞行全过程自动发送身份、位置、速度等，且不应能关闭发送。本平台如果收到这类数据，它是**身份证据**，不是合法性结论。

规范实时性默认：≤3 秒实时，3–10 秒轻微延迟，10–30 秒暂时失联，>30 秒目标消失。过期位置不得动画成实时。

### 4.5 系统怎么判断，人做什么：分流与闸门

这是规范最重要的产品法律化设计，直接对应条例「协同监管 + 分类管理」和「反制必须依法配备」。

四个独立维度，禁止合成一个「高等级非法」标签：

| 维度 | 取值 | 回答的问题 |
| --- | --- | --- |
| 系统判定 | 合法 / 异常 / 非法 / 待确认 / 不适用 | 规则上是否合法 |
| 风险等级 | 高 / 中 / 低 | 会造成多大损害 |
| 处置时效 | 紧急 / 优先 / 常规 | 必须多快响应 |
| 业务状态 | 待研判 / 待签收 / 待核实 / 待处置 / 处置中 / 待审批 / 已关闭 | 现在处于哪一工作阶段 |
| 判定置信度（辅助） | 高 / 中 / 低 | 结论有多确定。只用于分流 |

默认分流：

| 系统结果 | 自动动作 | 禁止 |
| --- | --- | --- |
| 合法且证据完整 | 不告警，降权，在飞持续监视，落地后归档 | 在飞期间归档、结束监视 |
| 异常 | 异常告警 | 当成非法事件 |
| 待确认 / 疑似非法 / 置信不足 | 研判任务 | 形成最终非法结论 |
| 高置信非法 | 非法告警（待签收、待核实） | 直接待处置、直接反制、直接成案 |
| 非无人机 | 不适用，走空间安全 | 进入黑飞待办 |
| 合法但碰撞/失联/敏感区接近 | 可并行安全事件 | 等合法性结论才处理安全 |

分层闸门（实质性）：

1. 自动创建的是告警，不是正式待处置事件，更不是反制批准。
2. 仍须签收核实：目标是否还在、风险是否还在、当前能做什么。「我已知晓」≠ 签收 ≠ 领取处置。
3. 联系飞手、持续跟踪：转处置后由处置员做。
4. 反制、公安移交、重大关闭：指挥审批；发起人与审批人不得为同一登录账号。
5. 演示禁止「一判非法就反制」。

置信度默认：≥0.80 且关键字段完整、无多源冲突为高；0.50–0.80 为中；低于 0.50 或冲突或缺字段为低。关键字段至少：有效坐标、时间、目标类型（含未知）、高度。

### 4.6 反制：法律资格 vs 平台按钮

条例第 43 条：只有军队、警察、经公安授权的高风险反恐重点目标管理单位可以依法配备反制设备，并在公安或军事机关指导监督下从严控制。非法拥有、使用反制设备：没收，可处 5 万元以下罚款；情节严重 5 万–20 万。

对本平台的直接含义：

- 页面可以申请、审批、受控下发、收执、急停。
- 审批页**不得**提供绕过设备安全策略或法规限制的技术操作。
- 测试环境命令不能打到生产设备。
- 无真机用模拟回执验收软件，回执缺失必须显式记录，不能把「点了下发」当成「已经驱离」。
- 反制失败不得直接关闭事件。
- 光电—反制联动（A10）必须经审批，不得全自动下发。

山东办法进一步写明：对违规飞行，公安可依法采取干扰、截控、捕获、摧毁等必要技术防控。那是**公安机关的法定处置权**，不是本系统值班员的默认权限。

当前代码里的劝离链（核实 → 联系/观察 → 条件反制申请 → 独立移送）符合「先联络、反制走授权、处罚走移交」的法律结构。不要退回更早的「核实后必然反制再干扰」五步演示。

### 4.7 处罚：本平台只做到移交

规范原文口径：

- 案件（Case）是外部执法对象。
- 本平台不建设案件办理流程，不设立独立行政处罚案件对象。
- 不生成处罚决定书，不设置罚款金额。
- 统计「已移交外部执法的事件数量」，不统计本平台行政处罚案件数量。
- 目标已消失但违法事实仍成立：实时处置可结束，转入后续办理或移交，不得当作未发生。

条例罚则举例（实施主体多为公安/民航，不是本系统）：

- 未经实名登记飞行：责令改正，可处 200 元以下；情节严重 2000–2 万元。
- 未经批准在管制空域操控微/轻/小型：责令停止飞行，可处 500 元以下；情节严重没收并处 1000–1 万元。
- 2026-01-01 起，违反空域管理情节较重还可适用治安拘留。

所以工作台文案必须保持：

- 「通知处罚部门」= 交接完成。
- 「拟罚金额」≠ 「已罚款」。
- 没有案件时显示待反馈，而不是办结。

### 4.8 证据、审计、个人信息

从发现开始就要形成证据：原始点迹、融合轨迹、规则版本、计划版本、系统结论、人工结论、命令、回执、外部通知。只追加不覆盖。

法律侧：轨迹和飞手信息受个保法约束；证据导出、人工改判、规则发布、反制审批都是高敏动作，要二次确认和审计。规范默认热数据轨迹/告警不少于 90 天，视频不少于 180 天。

### 4.9 值班责任与 SLA（不是法律强制时限，但是合同验收默认值）

紧急：待签收超过 10 分钟或处置中 30 分钟无新动作 → 升级值班长。\
优先：30 分钟 / 2 小时。\
常规：2 小时 / 8 小时。\
超时只升级，不自动关闭，不自动反制。

打开详情 = 只读协同，不占用责任。领取必须显式点击，后端原子校验。

## 6. 容易学错的十个点

1. **本平台合法 ≠ 国家已批准这次飞行。** 本平台是用上级下发或本地临时规则做比对；批准权在空管/UOM。
2. **有 Remote ID ≠ 合法。** 只说明「看得见是谁」；仍可能偏航、超高、进禁飞区。
3. **无 Remote ID ≠ 必然黑飞。** 存量机、信号遮挡、非无人机都可能没有。应待确认或走其他源，而不是直接非法。
4. **120 米不是全国统一「随便飞」。** 真高 120 米以上通常是管制空域；120 米以下还要看是不是适飞空域、是不是机场/军事/保护区。
5. **微型真高 50 米、轻型/小型真高 120 米** 是适飞空域内的常见限高口径，不是「只要低于这个数就合法」。
6. **2017 实名登记规定已废止。** 现在看 CCAR-92 和 GB 46761。
7. **劝离短信成功 ≠ 风险解除。** 送达回执和现场结果分开存。
8. **批准反制 ≠ 目标已迫降。** 必须有设备回执和轨迹评估（A11），失败要留在处置中。
9. **移交公安 ≠ 本平台立案结案。** 规范明确禁止把事件主键叫「案件」。
10. **等保二级稿和三级稿同时存在。** 独立技术规范是二级，9.9 谈判稿是三级。不要在页面或方案里随口写错级别。

## 7. 谈判稿里的四项现场算法（懂业务也要知道门槛）

9.9 谈判要求供应商在谈判现场、最终报价前，用采购人当场给的 CSV 跑通 K01–K04，PPT 不能代替。四项全部满足才能进入报价比较，不单独计分。

| 编号 | 测什么 | 对应规范算法 | 业务含义 |
| --- | --- | --- | --- |
| K01 | 两路观测关联成统一目标 | B01/B02 | 同一架飞机不能显示成两个 |
| K02 | 双源融合、3 秒中断后续接 | B03–B05 | 丢点时不能把预测画成实时真值 |
| K03 | 用历史轨迹预测未来 10/20/30 秒 | 位置预测 | 预测必须单独标识 |
| K04 | 矩形空域+高度+时间命中，并解释原因 | C02 | 规则可复现；命中 ≠ 已认定违法、≠ 可处置 |

演示明确写了：空间规则命中和预测**不得直接替代**身份核实、人工研判或处置审批；现场不得向生产设备发控制命令。这和分层闸门是同一法律精神。

## 9. 自学时怎么用官方平台（半小时实验）

1. 打开 https://uom.caac.gov.cn/ ，只看公开页：政策法规、空域查询入口、飞行活动申请说明。体会「计划在国家平台申请，本平台只消费结果」。
2. 在 UOM 或山东交通运输厅通告里看适飞空域示意图的颜色含义：蓝色适飞、白色/其他管制。把它映射到本平台规则图层的「来源=上级」。
3. 打开本仓库融合感知页，对照规范问四个问题：这个目标的系统判定是什么、置信度是什么、风险等级是什么、业务状态是什么。如果页面把它们揉成一个红标，就是在违反规范实质性条款。
4. 打开告警事件页，看当前动作是联系、观察、申请反制还是移送。用条例第 43 条检查：反制按钮前面有没有审批闸门。
5. 打开处置与处罚页，看是「交接/回执」还是「已罚款」。用规范「不建案件对象」检查文案。
