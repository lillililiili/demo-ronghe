# 业务前台专项详细测试用例

日期：2026-09-27　版本：V1.0　执行状态：全部 Not Run

配套：[前台专项测试计划](前台专项测试计划-2026-09-27.md)。本清单覆盖当前 8 个主业务模块、大屏、登录、路由、模拟输入联调与异常恢复；编制完成不代表执行通过。

## 执行约定

- 身份 R-READ/R-OP/R-APP/R-EXEC/R-DIRECT/R-LIMIT/R-NOMENU/R-DISABLED/R-ADMIN、数据 D-01～D-12 及基线差异 G-01～G-07，定义见测试计划。
- P0：关键验收阻断项；P1：重要功能；P2：一般体验或扩展。每行中列出的数据变体分别记录，不能仅挑一个执行后标整行通过。
- 所有正向操作必须同时核对页面、API 回读和对象 ID；涉及通知、反制、移送时增加可信回执/审计。只出现成功提示不算通过。
- 反向操作必须核对拒绝提示和业务无副作用；安全测试预期的401/403/404不记成前台网络缺陷，但不能接受未捕获异常或白屏。
- 使用隔离测试通道，不直接操控真实硬件或真实收信人；数据只能来自获准入口。接口桩验证须单独标记，不能替代后端联调。
- `T_sms`：G-04 确认后的短信观察时长；`T_voice`：当前需求与源码均为10秒。以服务端时间线判断，不以动画倒计时结束推定业务完成。
- “无写入”指无未经用户动作/有效服务端条件触发的业务写入；正常访问日志和认证审计不属于失败。
- 通用执行记录：用例ID/变体、执行人、时间、版本、角色、批次与关联ID、实际结果、状态、证据路径、缺陷号、复测结果。文末有模板。
