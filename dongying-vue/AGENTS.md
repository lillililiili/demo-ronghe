# AGENTS.md

本文件适用于 `dongying-vue/` 前端目录。仓库级说明见根目录 `AGENTS.md`。

目录组织与编码约定参考了同类 Vue 工程的分层方式，但**不要**把那套技术栈原样搬进来：本仓库保持 JavaScript、原生 CSS、Naive UI 与渐进式 legacy 迁移。禁止借「对标」引入 TypeScript、Less、Ant Design、pnpm/yarn 或新的生产依赖。

## 项目定位

- 这是“东营无人机融合感知与低空安全管理平台”演示工程的 Vue 3 迁移版。
- 当前工程采用渐进式迁移：Vue 外壳与已迁移页面和 legacy 经典脚本并存。首要目标是保持现有业务语义、状态流、数据口径和交互兼容，再逐步减少 legacy。
- 产品方向以根目录“自动研判与快速响应”和 `../docs/自动研判与快速响应优化评估-2026-09-15.md` 为准。`../docs/事件驱动业务流程梳理.md` 是历史分析与路线图；独立“我的工作台”已移除，不凭旧路线图恢复页面或虚构任务、SLA、责任人及自动化能力。

## 技术基线与常用命令

- 技术栈：Vue 3、Vite 6、Vue Router 4（hash 路由）、Pinia 3、Naive UI、ECharts，地图使用 MapLibre GL 与 PMTiles。
- 使用 npm；`package-lock.json` 是依赖锁文件。不要改用 pnpm 或 yarn。
- 路径别名：`@/` → `src/`。跨目录引用一律用 `@/`，同目录组件可用相对路径。
- 常用命令：
  - `npm install`
  - `npm run dev`
  - `npm run build`
  - `npm run preview`
- 项目当前没有 `test` 或 `lint` npm script。不要声称运行过不存在的命令。
- 未经用户明确同意，不新增生产依赖，不更换构建工具，不做与当前任务无关的依赖升级。

## 目录结构

当前真源见 `../docs/目录结构.md`。分层约定（路径相对本目录）：

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `src/assets/css/` | 全局样式切片与入口 `index.css` | 页面私有、只服务单个 SFC 的样式 |
| `src/components/` | 跨页面复用的 Vue 组件 | 某一页专用的业务块 |
| `src/config/` | 导航、路由、页面主题等静态配置 | 运行时状态 |
| `src/hooks/` | 跨模块 composable（`use` 前缀） | 某一页专用的逻辑 |
| `src/layout/` | 壳层：顶栏、侧栏、面包屑、页面宿主 | 业务页 |
| `src/pages/` | 路由页面 | 通用组件 |
| `src/ui/` | Naive 适配层（toast/modal/theme/表单桥） | 展示型 Vue 组件 |
| `src/services/` | API、权限、数据装配和地图等共享服务 | 页面私有渲染 |
| `src/stores/` | Pinia 全局状态 | 页面局部 ref |
| `public/assets/js/` | 保留的地图、图表、UI 等经典脚本 | 新的 Vue 代码或恢复已删除的 Mock 状态机 |
| `public/assets/img/` | 运行时静态图 | 样式文件 |

新增文件先判断该不该公共复用：只有跨页面使用的才进 `src/components/`、`src/hooks/`、`src/services/`。

## 样式规范

- 全局样式在 `src/assets/css/`，由 `src/main.js` 首先 `import '@/assets/css/index.css'`。不要再往 `public/assets/css/` 加样式，也不要在 `index.html` 用 `<link>` 加载业务 CSS。
- `src/assets/css/index.css` 的 `@import` **顺序即层叠顺序**，后写覆盖先写。不要为了「好看」重排 import。
- `src/assets/css/tokens.css` 是主题颜色与间距 token 的唯一真源。`src/ui/theme.js` 必须运行时 `getComputedStyle` 映射 Naive UI，禁止在主题配置里手抄色值。
- 2026-09-19 用户参考图确立深宝蓝底、亮蓝卡片与青蓝强调色；不恢复低饱和灰蓝面板。颜色统一从 tokens 读取，卡片常态轮廓使用蓝色，业务状态与类别仍由原有图标、数字及标签表达；不据配色参考改变布局、导航或地图航迹颜色。
- 分层：
  - `tokens.css` / `reset.css`：变量与基线
  - `layout/`：壳层（顶栏、导航、面包屑、大屏模式）
  - `mixins/`：通用布局工具类（`.row` `.col` `.grid` 等）
  - `components/`：跨页组件类（面板、KPI、表格、按钮、地图、弹窗等）
  - `visual-2026.css`：覆盖层，改顶栏/导航/面板时必须同时看这里和 `layout/`、`components/`
  - `themes.css`：`body[data-theme]` 模块插画
  - `pages/`：只作用于某页的选择器
- 改样式先找已有全局类组合；不够再补对应切片。新增选择器尽量限定在页面根类下（如 `.workbench-page`），避免污染其他页。
- 已有 class 名（`.hdr` `.nav` `.tb` `.kpi` 等）是视觉与 DOM 指纹的一部分，禁止为了 BEM 或「规范化」重命名。
- 图片走 `public/assets/img/`，CSS 里用根路径 `url('/assets/img/...')`，不要用相对 `../img/`。
- Vue 单文件若需要局部样式，写在该组件的 `<style scoped>`。不允许为了把 SFC 行数做小，把组件局部样式抽成单独 CSS 文件；行数超标时按业务块拆子组件。
- 不引入 Less/Sass，除非用户明确要求并接受新增依赖。

## 功能页面模块组织

1. 新增功能页使用独立文件夹，相关代码收敛在该文件夹内：

   ```
   src/pages/<feature>/
     XxxPage.vue
     components/     # 仅本页使用
     hooks/          # 仅本页使用
   ```

2. 只有跨页面复用的组件、hooks 才分别放入 `src/components/`、`src/hooks/`。
3. 已迁移的扁平页面（`src/pages/*Page.vue`）不要为了目录整齐再搬一次；后续若拆子组件，再就地改成功能文件夹。
4. 开发前先搜索并复用 `src/components/`、`src/hooks/`、`src/ui/`、`src/services/`、`src/assets/css/` 中的已有能力。
5. 弹窗组件命名 `xxxModal`，抽屉 `xxxDrawer`，页面 `xxxPage`，hooks 以 `use` 开头。
6. 新组件目标不超过约 500 行、函数不超过约 100 行。已迁移页受 DOM 指纹约束，禁止只为行数拆分而改 DOM 结构。

## 当前架构契约

- `index.html` 中 `public/assets/js/**` 以经典 `<script>` 按固定顺序加载，随后才加载 `src/main.js`。这些 IIFE 依赖经典脚本语义和 `window.*` 全局对象；不要随意改成 ESM、调整加载顺序或异步加载。
- 经典脚本实际加载清单以 `index.html` 为准；修改 `UI`、`CH`、`MapView` 等共享能力及 Vue shim 前搜索全部消费者，不因旧文档列过 `MOCK`、`EVT` 或 `PAGES` 就恢复已删除模块。
- `src/config/navModel.js` 是导航、路由、页面主题和重定向表的当前真源；新增或改名页面时同步检查侧栏、标题、面包屑、重定向和别名。
- `src/pages/registry.js` 是 Vue 页面迁移开关。只有页面行为和 DOM 验收通过后才能登记；未登记页面继续由 `LegacyHost` 承载。
- `monitor` 等六个管理地址已迁出业务前台，只显示迁移提示；磁盘上存在旧组件不代表它仍注册或应该恢复。
- `public/assets/js/mock.js`、legacy `pages/` 和 `src/services/workbenchEvents.js` 已不存在。业务数据通过现有 API 服务读取，后端仍可能返回明确标记的 mock/replay 数据；专用页面演示场景与接口模式分开，接口失败不得回退为模拟成功。
- 无人机、飞行风险和设备异常保持各自后端状态与契约，多个页面复用同一业务记录及共享动作，不在页面中另造状态机。

## Legacy 与 Vue 迁移规则

- 只有任务涉及仍存在的 legacy 页面时，才读取其当前脚本并执行迁移对照；已删除的 `public/assets/js/pages/` 不重建。已迁移业务以当前 Vue 页面、接口和最新确认要求为基准。
- 需要与同级 `dongying-demo` 母本同步时，先运行 `bash tools/parity-diff.sh`。若母本目录不存在，明确说明无法做字节级对照，不要猜测差异。
- 共享 legacy JS 和 `public/assets/img` 仅在核对差异及当前消费者后按需同步，禁止整目录覆盖。**CSS 已由本仓 `src/assets/css/` 维护，不再与母本逐字节同步**；上游样式 diff 必须人工重放到对应切片。
- 已迁移页面必须把上游 JS 差异人工重放到对应 Vue 页面，不能用旧脚本直接覆盖 SFC。
- 保留 legacy 的状态生命周期：需要跨导航保留的模块级状态放在 SFC 普通 `<script>` 模块作用域；仅当旧 `mount()` 本就完全重置时，才放在 `setup` 生命周期中。
- 模块加载期的数据注入、注册或随机数消耗只保留一处。不要在 SFC 中重复 `U.regParams`、Mock 注入或其他副作用。
- 页面卸载必须清理图表、地图、动画帧、计时器、事件监听和弹窗。Vue 页面优先调用 `usePageChrome()`，并保持与 legacy 兼容的清理顺序。
- `v-html` 只用于仓库内受信任的 legacy 渲染串和图标输出。禁止把外部输入、用户输入或未清洗数据直接传入 `v-html`；还要避免为了包裹 HTML 额外增加会破坏 DOM 指纹的节点。
- 保持 hash 地址与旧书签兼容，例如 `#/situation`、`#/alarms`、`#/risk`、`#/monitor` 和 `#/bigscreen`。

## 表单控件（Naive UI 强制）

- **产品表单只使用公共表单件**（内部才是 Naive UI）：`src/components/form/` 的 `UField`、`UFieldGrid`、`UFormFooter`、`UControl`。Vue 模板禁止出现原生 `<input>`、`<select>`、`<textarea>`，也不要在页面里直接铺 `NInput`/`NSelect`/`NDatePicker`（权限矩阵等无对应公共件的除外）。日期时间范围走 `type="datetimerange"`。
- **新弹窗表单**走 `openFormModal()`（`src/ui/formModal.js`）或 `openModal({ render: () => h(Comp), footer: false })` 后在 Comp 里用 `UField`。样板：`ControlledFormModal.vue`、`CarouselModal.vue`。
- **禁止**为了“看起来像组件”而用 CSS 给原生控件描边；也禁止在 Vue 页面继续拼 `U.field` + `` `<input class="ip">` `` / `U.select` 作为新表单。
- 仍由 `innerHTML` 绘制的旧工具条 / 调测参数 / monitor 字符串，必须带 `.ip` / `.sel` / `type="checkbox|radio"`，由 `src/ui/legacyControls.js` 升级为真 Naive 组件。新代码不要再扩大这条兼容路径。
- `tools/scan.cjs` 对 Vue 模板中的原生表单控件判红。扫描、修复和生成新代码均遵守本条。

## UI 与交互规则

- 遵守根级 AGENTS.md“以客户实际需求为边界”（2026-09-20 用户确认）：现有页面上的设计稿与原型同样不得擅自增加客户未确认的业务功能。新增数据接入或设备类型，不自动扩展为跨页展示、对照分析、关联策略或风险联动；有必要扩展时先说明场景和范围并取得确认。
- 页面字段以实际接口和设备能力为依据；未知能力明确待确认，不凭示例数据宣称设备支持。用户已否定的扩展从当前设计和实现中撤回，旧稿标注失效。
- 业务页面面向实际操作员，不展示其当前任务不需要的接入排查字段、实现原理或设计说明。技术追溯信息留在后台对应配置与日志；只保留业务识别、操作和判断所需的信息及真实异常提示。设计评审标记放在独立评审层，不能作为常驻产品文案（2026-09-20 用户确认）。

- 交互控件优先使用现有 Naive UI 适配：toast 走 `src/ui/nv.js`，弹窗走 `src/ui/modal.js`，确认框走 `src/ui/confirm.js`。具体 legacy → Naive 映射见 `tools/NAIVE-MAP.md`。
- 弹窗保持单例、遮罩关闭、`data-close`/`data-act` 委托和既有 z-index 契约；Vue 页面不要绕回 legacy toast 或另造第二套弹窗系统。
- 展示型 legacy helpers（如 tag、kv、sect、metricStrip）可以继续复用。不要仅为“组件化”改变已有 DOM 数量、文案、数据口径或视觉签名。
- 优先复用现有图标、品牌资源、`MapView`、图表和组件；不要用 emoji、占位图、临时手绘 SVG 或虚构数据代替真实界面资产。
- UI 文案使用简体中文，并沿用现有业务术语。首屏优先表达结论、依据、风险、下一动作和阻断原因，技术细节按需展开。
- 所有新增交互要有明确的空态、无权限态、阻断态、处理中态、失败态和完成态。可点击元素优先使用语义化 `button`/`a`，并支持键盘与可见焦点。
- 页面不得产生 document 级横向滚动。与任务相关时至少检查 1280×720、1366×768、1440×900/1024；大屏页面还应检查目标大屏尺寸。表格或长内容应在局部容器内滚动。

### 日常操作与布局（用户确认）

- 业务详情的 `TargetLiveVideo` 实时视频区域默认展开，保留手动收起与重新展开；收起、切换目标或离开时继续取消旧读取并释放画面（2026-09-22）。
- 飞行计划天气预报按当前计划 `start_at` / `end_at` 筛选并裁剪显示时段，仅端点相接不算覆盖，保留原预报数据、发布时间和来源。2026-09-23 后续确认取消天气预报过期概念：不做整批到期判断、不显示过期提示或设置到期刷新；兼容旧 `STALE` 响应中的预报，按计划覆盖时段正常展示。计划时间无效、无覆盖、未接通及读取失败仍分别提示；不改变气象风险的有效时段判断。

- 2026-09-17 后续精简：手动反制按钮周围不常驻操作解释，缺依据时点击进入补充表单查看原因；其他阻断原因在点击时提示，不因按钮可点击而放宽提交资格。授权状态与历史入口保留。

- 2026-09-17 证据页精简：图片固定为 100% 适应比例，不显示缩放/适应/原图四个按钮；视频移除自定义前后步进，仅保留紧凑倍速选择与正常播放控件。台账移除冻结、引用两列，详情移除文件标题卡、文件信息与技术校验信息块、重复“打开内容预览”入口；保管、关联、采集时间及模拟标识保留。“校验哈希”面向业务人员改为“检查文件完整性”，不得把通过检查表述为内容真实。结构化文字材料优先显示中文分组，未知字段与无法解析的材料明确提示，原件和历史事实保持不变。

- 证据预览仅呈现图片、视频或轨迹与必要查看操作、采集时间、模拟/回放标识和异常提示；文件名、编号、来源关联、校验保管、坐标及原始数据移至证据页对应记录。文件通过 `#/evidence?file=<evidence_id>` 精确定位；原始轨迹通过 `subjectKind`、`subjectId` 与 `track` 重新读取授权证据链后定位，不拿 `track_id` 当文件 ID，不回退到首条或最新轨迹。

- 新增、修改、删除模块前核对完整状态流程：哪些状态需要操作、哪些只看历史、哪些不适用。突出当前主要动作，避免已完成步骤反复要求核验；不适用且无历史可隐藏，有历史保留查看，缺权限、缺数据和失败要说明原因。
- 删除重复标题、解释和按钮，系统已知信息自动带入；日常文案说人话，优先名称和业务含义，不要求值班员按内部编号查找。内部 ID 仍用于精确关联，不能因界面精简删除审计、来源、时效、模拟标识或异常依据，也不能把“超出自动通知时效”缩写成“事件已结束”。
- 飞行计划、全部风险事件和空域监测采用列表、地图、详情联动。列表及详情独立滚动，浏览记录时地图持续可见；详情按选择展开，空域监测未选中时不留空白右栏，关闭后保留筛选和列表上下文。
- 常用筛选常驻，次要条件放明确命名的“更多筛选”；收起后保留生效条件提示和清除入口。已自动生效的筛选不再叠加重复“查询”按钮；点选空域查看详情不擅自启用范围筛选。
- 切换目标、事件、页签或关闭详情时立即隔离旧状态并丢弃迟到响应，不闪现上一事件的急停、授权、视频或办理结果；所有入口按当前对象精确读取。
- 深蓝底色配鲜明的图标、数字与状态色，普通正文保持清晰浅色；雷达、光电等设备使用对应图标。同一状态跨页同色，航迹颜色遵守下节规则。侧栏当前固定分组、平铺入口、统一蓝色，不因旧多彩示例恢复折叠或改动导航；当前故障设备的红色闪光与历史告警的静态提示分开。

### 文字完整展示（强制）

- 同页去重按“同一实体、同一事实、同一时点与口径”判断：详情补充摘要未展示的信息，不复制摘要整块。证据台账内嵌预览不重复列表已有取证时间，独立预览仍保留采集时间；视频时长由原生播放控件展示。列表识别与详情定位、不同渠道/历史快照、操作权限和失败原因保留。分类统计已有卡片时，筛选页签无需重复同源数量（2026-09-17）。

- 用户确认的展示要求：界面不得出现用来截断或替代文字的省略号，包括 `…`、`...`、`。。。`。适用范围包括侧栏导航、页签、标题、按钮、状态标签、表单选项、列表、表格、卡片和弹窗。
- 不使用 `text-overflow: ellipsis`、会截断文字的 `line-clamp`、组件的 `ellipsis` 配置或字符串截取后追加省略号来处理空间不足。已有实现不代表符合本规范；修改相关区域时应一并纠正。
- 优先通过合理分配列宽、调整容器宽度、允许换行、自适应行高或调整布局完整展示内容。长编号和连续字符串可按需断行；不得靠缩小到难以阅读的字号解决。
- 不得仅将 `ellipsis` 改成 `clip`，或使用 `overflow: hidden`、固定高度等方式继续无提示裁切。Tooltip、`title` 或详情弹窗只能补充信息，不能替代当前展示文字的完整可读性。
- 内容较多时可使用局部滚动；独立的长内容区域可提供明确的“展开全文 / 收起”交互，收起态不以省略号占位。导航、按钮、状态、标识和关键结论必须直接完整显示，不依赖悬浮或点击才能辨认。“更多”等操作入口使用明确文字，不用省略号代替。
- 验收覆盖 1280×720、1366×768、1440×900/1024 及目标大屏尺寸中的适用视口，并检查最长名称、长编号、侧栏展开与收起等相关状态：不得出现省略号截断、静默裁切、文字重叠或 document 级横向滚动。代码搜索只能辅助排查，不能替代真实浏览器检查。

### 地图航线与轨迹展示

- 用户确认的统一颜色：符合计划走廊的已飞轨迹绿色，偏离的已飞轨迹红色，尚未飞过的计划航线灰色；按轨迹片段显示，不能用整条目标的合法性状态替代航线符合性。无匹配计划、走廊或分段依据时显示未知，不擅自染红或染绿。
- 轨迹必须按观测时间、轨迹身份和连续性绘制，保留真实转弯与停留；对时间倒序、已知中断、不同轨迹及无效点断开处理，不能强连成穿插线。模拟来源不能伪装成真实采集，不能为了“像真实”修改已有观测记录。
- 计划航线共用 `MapView.strokePlannedRoute()`，统一灰色，不随计划状态或风险改色；Vue 页面通过 `src/services/positionMap.js` 的 `strokePlannedRoute()` 调用。各业务页可传入起终点、标签等显示选项，不再另画厚描边、光晕或流动线。
- 计划航线使用稳定细虚线，实测轨迹使用稳定实线；弥合和预测保持独立线型。不得通过动画暗示静态计划正在执行或历史轨迹仍在更新。
- 仅投影数据源已有几何，保留真实轨迹断点；不平滑出不存在的路径、不补造航点、不把几何顶点编号冒充作业航点。模拟/回放来源标记必须保留。
- 多航线总览按需显示名称、起终点与节点，选中详情应完整可读。线条的像素衬边不表示走廊宽度；业务走廊只按已提供的米制宽度绘制。

## 业务与数据一致性

- 融合感知目标查询从北京时间当天零点开始，到本次刷新时刻结束；目标完整分页，地图与“今日目标”统计同源，跨天重新计算范围。近期尾迹读取遵循接口窗口限制，不影响当天目标保留。最后上报时间与后端时效状态独立保留，不能将当天停止上报的目标写成持续跟踪；此约定替代最近 5 分钟的目标范围（2026-09-22 用户确认）。

- 合法性判定的右侧功能按算法是否能够可靠明确判定分流：明确合法与明确非法均不显示“核对信息缺口”或等价人工确认要求；可靠程度不足、无法明确判定时才显示该人工复核功能。读取后端 `decision_assurance.review_required`，不能只按 `legal_status`、`REVIEW` 权限或风险评分决定是否需要复核；待处理队列用服务端 `needs_review` 在分页前筛选。旧响应缺少可靠性结果时保持未知，页面不得自行生成置信度；依据与历史保留，权限继续由后端校验。详见 [合法性自动判定 Spec](../docs/superpowers/specs/2026-09-17-legality-auto-decision-design.md)（2026-09-17 用户确认及首版实现）。
- 合法性研判页只读取明确 `object_type_code=UAV` 的目标相关研判，列表、分页总数、各状态统计与目标深链使用同一服务端筛选；详情回读再次核对类别，不显示已变为非无人机或类别未知的目标及其复核动作。不以存在匹配计划为必要条件，保留无计划飞行的无人机研判；不在前端分页后删行冒充完整筛选，不删除或改变其他模块的风险历史。
- 飞行计划的计划风险记录与全部风险事件排除无实际接入/评估依据的预设展示样例，列表、分页数量、对应统计和导出使用同一服务端筛选。正常模拟/回放及 MQTT 派生风险保留来源标识，不能一概过滤；记录缺失不显示为安全，历史数据不删除。
- 风险通知统一显示“通知上级”，操作时不选择接收单位，不按区域或风险类型分发。计划报送单位反馈、飞手提醒和处罚移送继续按各自业务关系办理，不能套用风险通知目的地。

- “造数据、补演示数据、刷新今天的数据、MQTT 模拟、补齐业务链”等请求自动使用 `generating-business-scenario-data`，并读取根目录 AGENTS 与下述配套规范；实时输入、业务前置资料和历史补录按根目录规则选择入口，不在页面中单独生成相互脱节的数据。
- 追加演示数据遵循根目录“追加数据的跨模块配套”和[配套规范](../docs/演示数据跨模块配套规范.md)。页面有记录不等于场景完整；按同一目标、计划、事件、通知、回执和证据核验所有入口。历史模拟补录必须在记录中说明来源与补录性质，不使用前端状态或刷新旧时间掩盖缺失链路。

- 不得虚构事件 ID、责任人、SLA、协作关系、授权记录、证据、回执或统计趋势。界面只展示当前数据模型真实存在或由既有规则可确定推导的内容。
- 权限同时影响导航/可见性、数据范围、操作按钮和敏感字段。前端权限仅改善体验；不要把它描述为生产级后端授权。
- 任何状态动作必须复用共享状态机并同步审计、证据、关联记录和回执；不要只改按钮文案或页面局部状态。
- 无人机流程遵循根目录“自动研判与快速响应”原则。飞手短信在告警事件建立后由后台自动发送一条，不再以核实、研判或时效作为发送门槛；没有已核验的执行飞手时短信和电话都不发送（2026-09-21 用户确认）。电话录音的其余条件、反制申请与处罚移送仍按各自后端条件办理，见 `../docs/backend-stage19/uav-advisory-workflow.md`。2026-09-17 用户确认删除告警详情的“需要你处理”“补充操作与事后移送”及“飞手通知与现场记录”块，处罚移送改为后台自动办理；页面消费 `auto_handoff` 只读状态，不调用创建交接接口，不把缺字段显示为已自动移送。后台配套未启用时如实提示，后台原始记录及冻结材料保留。不得把旧五步演示链或尚未落地的自动观察强加为现状。
- 自动通知区分发送资格与历史结果：已有发送/送达记录及时间不能被后来观测过期覆盖；未发送且依据失效时显示具体阻断原因。缺少记录不推定当时已经发送，历史演示样本须明确模拟发送及模拟回执；短信送达不代表已读、飞离或风险解除。
- 飞手通知包括短信和电话录音通知。告警详情与融合感知读取同一事件的各渠道状态，分别呈现短信送达、电话接通及播放结果；电话结果未知不能展示为已联系或开放盲目重拨。录音/通道未配置、权限不足、读取失败与没有历史记录分别处理，人工联系记录不生成自动外呼回执。
- 反制和公安信号干扰须有人授权，核对目标、范围、时效及执行条件；急停针对本次处置及关联干扰，适用状态下直接可见，先提交停止、后补原因。请求提交、设备停止回执与现场核查分别呈现，超时或离线显示停止未确认，急停后不自动恢复。
- 当前反制均由人工发起，告警详情“反制授权”区保留“手动反制”按钮（2026-09-17 后续确认）。条件不齐时说明原因；允许补充依据时从按钮进入按需表单，不恢复已删除的现场记录整块。补录只保存事实，用户再次发起才按 `can_direct_counter` / `can_request_counter` 进入直接反制或申请审批；加载、轮询、保存依据不自动申请或下发。
- 未执行计划不判实际飞行合法性，但仍可查看起飞前风险与设备状态。到时未见对应目标时由系统检查附近设备；无异常且依据完整只能提示疑似未按计划起飞，由报送单位确认，缺数据不算正常。检查、通知与回执按同一检查记录关联展示。
- 飞行计划“全部风险事件”限定异物与气象；空域监测按自身范围合并观测与风险，不因布局修改混入其他风险类型。空域规则由上级下发，业务前台查看与监测，不恢复本地划设、调整或结束管制操作。机巢周边场景指无人机起降设施，不等于有人机机场或机巢控制能力。
- 光电追踪由目标、可信位置、权限、可用设备及任务状态决定，不以必须有风险记录或从某个入口打开作为前提；成功回执后才展示对应视频，模拟视频明确标记。纯气象风险不虚构可追踪目标。设备异常通知生成后台运维待办，不恢复旧设备管理页面；待办处理完毕不等于设备已恢复。
- 无人机事件完成“通知处罚部门”表示完成交接，不等于行政处罚案件已经办结；不要添加手工归档步骤来混淆实时处置与案件办理。
- 飞行计划风险按现有后端核验、通知与回执契约推进，不恢复已删除的 `M.RISK_FLOW`/`RISK_IMPL`。设备异常的确认、指令、设备回执、恢复校验与关闭由后台独立办理，不把三类事件强行套入一条状态链。
- 地图、图表和列表必须读取同一份状态。切换事件、路由或重挂页面后，不得遗留多个活动 `MapView`、overlay canvas、定时器或全局监听器。

- 处罚通知分别展示送达状态（待发送、送达待确认、已送达、发送失败）与签收回执（未进入签收、等待签收回执、已签收、回执超时），不压缩为“已通知/未通知”。发送中和结果未知明确展示；当前配置变化不覆盖历史发送事实，送达或签收不代表处罚办结。
