# 自动移送到处罚：待批准的后台配套

日期：2026-09-17。

## 已完成与当前边界

按本轮两张截图，告警详情已删除“需要你处理”“补充操作与事后移送”和“飞手通知与现场记录”。人工联系、补充现场、紧急依据及手动移送按钮随整块移除；现场与授权摘要、短信与电话结果保留。后台历史记录和既有交接材料不删除。

页面只读取处置接口中的 `auto_handoff`。已有真实交接编号时可进入同一处罚交接；接口缺失时显示“自动移送状态暂不可用”。当前共享后台仍是原有手动提交实现，自动移送尚未实现或启用。

## 需要批准的具体后台改动

1. 在 `houtaiguanli/server/` 新增持久化自动移送任务与后台调度，独立于页面与登录会话。默认关闭；首次显式启用时保存生效时间，只处理生效后新建的合格事件，不批量追溯移送旧历史。重启后沿用原生效边界并恢复未完成任务。
2. 合格依据为已确认属实的事件，或同事件、同目标、同归属的最新有效、明确非法且可靠性充分的算法结果。算法路径检查证据时效，未知、缺失、失败或不充分均阻断；保存算法与规则版本，不伪造人工核实或将事件强改为“已核实”。
3. 读取唯一启用且配置为默认的处罚接收方；缺配置、配置有歧义时明确阻断。不得按列表第一条猜测接收方，不套用风险“通知上级”的目的地规则。
4. 以事件锁、持久任务唯一约束及已有交接检查防重。同一事件已有处罚交接时沿用，不因配置变化再次创建。失败保留失败事实和原因，不用前端重试循环代替后台任务。
5. 为系统自动移送增加独立提交方式和可识别的系统提交主体，使用新增迁移区分系统与人工记录；保留原有人工提交的权限、版本及状态守卫。记录系统审计，不冒用某个用户会话。
6. 复用移送材料组装，冻结事件、研判依据、现有记录和证据引用。自动办理仅将材料加入处罚交接队列，初始为“待发送 / 未进入签收”；不调用真实短信、电话或处罚部门外部通知，也不自动立案、处罚、反制或认定办结。
7. 处置接口增加只读状态，并核对处罚列表、详情和后台消费者。已有交接事实不被后来的数据过期或配置变化覆盖。当前处罚通知接口仍要求事件 `CONFIRMED`，算法明确非法但未做人工核实的自动交接会受该守卫限制；实施时须核对这一兼容边界，不把“已入队”描述为“可以发送”或“已经送达”。后台管理端目前没有该接口消费者。

## 前端已预留的响应

`auto_handoff` 使用 `enabled`、`status`、`reason`、`handoff_id`、`trigger_source`，以及触发、更新时间与来源等可审计字段。

| 状态或来源 | 页面显示 |
| --- | --- |
| `WAITING` | 等待自动移送到处罚 |
| `BLOCKED` | 自动移送暂不可办理，并显示原因 |
| `DISABLED` | 自动移送尚未启用 |
| `FAILED` | 自动移送失败，并显示原因 |
| 真实交接编号，来源 `MANUAL_CONFIRMATION` 或 `RULE_ILLEGAL` | 已自动移送到处罚，可查看同一交接 |
| 既有人工交接，来源 `EXISTING_HANDOFF` | 已移送到处罚，不改称自动移送 |
| 缺字段或未知状态且没有交接编号 | 自动移送状态暂不可用 |

## 验证要求与审批阻断

后台获准实施后，验证合格与阻断分支、同事件并发防重、重启恢复、启用前历史排除、默认接收方缺失或重复、材料与审计、读取无副作用及权限边界。SQL、迁移和锁需在隔离 PostgreSQL/PostGIS 验证，不能用现有业务数据库冒充测试环境。当前没有后台实现或测试通过的结论。

自动审批先拒绝向后台仓写入，认为新增自动调度、调整提交者约束与本地默认启用会产生处罚移送记录，超出其认定的明确授权范围。随后提出仅在临时目录准备且默认关闭的隔离补丁，仍被自动审批以缺少具体后台变更批准为由拒绝。两次均未应用实现，也未启用后台能力；后续需要用户对上述具体范围明确批准。
