# 设备运维接口契约

版本：V1.1；日期：2026-09-04。

本契约对应“运维管理”下设备管理、设备实时监测、设备接入调测三页。当前同时保留明确隔离的开发 `mock` 模式，并已按资料实现 `RADAR_TCP_V3_0_0` 与 `COUNTERMEASURE_TCP_4CH_V2_0` 两种 live 协议能力。适配器按 `source_mode + protocol_code` 路由；live 连接或协议失败不会回退为 mock 成功。

## 1. 通用约定

- 根路径：`/api/v1`。前端默认同源访问 `/api`，本地 Vite 代理至 `127.0.0.1:8080`，可用 `APP_PUBLIC_API_BASE_URL` 覆盖 API 根路径。
- 认证：`Authorization: Bearer <session_id>`。`session_id` 存在浏览器 `sessionStorage`；刷新通过 `GET /auth/me` 校验，401 清理会话并返回登录页。
- 字段：snake_case；所有业务 ID 均为字符串；时间为 Unix epoch 毫秒。
- 信封：成功 `{ "ok": true, "data": ... }`；失败 `{ "ok": false, "error": { "code": "...", "message": "..." } }`。
- 空值：Jackson 忽略 null。字段缺失表示未知或没有事实，前端不得补成 `0`、在线、正常或通过。
- 模拟：模拟对象返回 `source_mode: "mock"`、`simulated: true`；live 对象返回 `source_mode: "live"`、`simulated: false`。界面只对前者显示“模拟回执”“模拟通过”。协议模拟器通过不等于已完成甲方现场联调。
- 权限：`*.read` 控制读取，`*.op` 控制写操作。`ROLE-ADMIN` 固定拥有全部权限；其他账号仅依据超级管理员配置的自定义角色权限访问，未知或未授权角色拒绝。

## 2. 设备台账

### `GET /devices`

参数：

| 参数 | 约定 |
| --- | --- |
| `page/size` | 默认 1/20；size 为 1–100 |
| `keyword` | 匹配设备编号或名称，最长 100 字符 |
| `type_code/channel/region/vendor` | 精确筛选 |
| `connectivity` | `ONLINE/OFFLINE/ABNORMAL/UNKNOWN` |
| `enabled` | `true/false` |
| `sort` | `priority`、`device_no_asc/desc`、`name_asc`、`type_asc`、`owner_asc`、`vendor_asc`、`connectivity_asc`、`last_heartbeat_desc` |

默认 `priority` 顺序为异常、离线、未知、在线，再按设备编号。结果为 `{items,page,size,total}`。列表摘要包含台账 `version`、启停状态、最新连接/健康状态、告警标志与最后心跳。

### 其他台账接口

| 方法与路径 | 行为 |
| --- | --- |
| `GET /devices/options` | 返回 `types/channels/regions/vendors` 当前可用筛选项 |
| `GET /devices/{device_id}` | 台账详情、最新指标与连接配置可见性；无 `devices.op` 时 `connection_visible=false` 且不返回连接对象 |
| `POST /devices` | 创建设备；设备编号、名称、类型名称和通道必填 |
| `PUT /devices/{device_id}` | 使用请求体 `version` 乐观锁更新台账与连接配置；不能修改实时状态 |
| `PATCH /devices/{device_id}/enabled` | 请求 `{enabled,version,reason}`；启用和停用均写审计，不物理删除 |

`source_id` 与 `external_device_id` 必须同时为空或同时存在；经纬度也必须成对出现。坐标按声明值保存，首版默认 WGS-84，不转换坐标，也不推算 AGL/AMSL。

连接配置 DTO：

```json
{
  "transport": "TCP",
  "host": "192.0.2.20",
  "port": 9001,
  "path": null,
  "data_format": "JSON",
  "charset_name": "UTF-8",
  "auth_mode": "Token",
  "credential_ref": "vault://devices/radar-01",
  "heartbeat_interval_seconds": 30,
  "report_interval_millis": 1000,
  "sampling_rate_hz": 10,
  "compression_enabled": false,
  "retransmission_enabled": true,
  "timeout_millis": 3000,
  "retry_count": 3,
  "longitude_offset_deg": 0,
  "latitude_offset_deg": 0,
  "altitude_offset_m": 0,
  "time_sync_mode": "NTP",
  "time_server": "time.example.invalid",
  "timezone_name": "Asia/Shanghai",
  "time_sync_interval_seconds": 60
}
```

接口不接收或返回明文密钥。`credential_ref` 只是外部密钥管理系统中的引用。

### 来源与协议专属配置

`GET /device-protocols` 返回协议版本、只读能力、配置字段及默认地址提示。`GET/POST/PUT /integration-sources` 和 `PATCH /integration-sources/{id}/enabled` 维护 live 来源；来源创建后固定为停用，启用时逐台校验协议适配器、TCP 配置、协议配置、凭据引用和 CIDR 白名单。回环、链路本地、云元数据地址及白名单外地址即使能解析也拒绝连接。

设备请求可携带 `protocol_configuration`：

```json
{
  "login_role": "DATA",
  "recognition_code_ref": "env:RADAR_RECOGNITION_CODE",
  "rtk_enabled": true,
  "coordinate_transform_enabled": false
}
```

雷达登录角色固定为数据权限 `0x5`。非零识别码只通过 `env:` 凭据引用解析，不进入响应、日志或报告。

```json
{
  "device_address": 1,
  "wire_encoding": "AUTO",
  "poll_interval_millis": 5000
}
```

四通道设备地址只允许 1–244，广播地址 245 被禁止。`AUTO` 只用无副作用 `0x10` 查询依次探测 `RAW_BYTES/ASCII_HEX_SPACED/ASCII_HEX_COMPACT`，本次会话识别后固定编码。

## 3. 实时监测与命令

| 方法与路径 | 行为 |
| --- | --- |
| `GET /device-monitor/overview` | 总量、在线/离线/异常/未知、告警数、供应商/型号数和按通道/类型聚合 |
| `GET /device-monitor/tree` | 支持 `keyword/channel/type_code`，最多返回 500 台并给出 `truncated` |
| `GET /devices/{id}/state` | 最新连接、工作、健康、心跳与指标；每项指标保留 `code/label/value/unit/source` |
| `GET /devices/{id}/state-history` | `metric_code/from/to/limit`；默认最近 60 分钟，最大 24 小时、500 点 |
| `GET /device-incidents` | 按 `device_id/severity/stage` 分页查询异常 |
| `GET /device-events` | 按 `device_id/after_seq/limit` 增量查询；响应 `next_seq` |
| `GET /devices/{id}/protocol-status` | 雷达返回登录、最近帧、CRC/重连、活动航迹和坐标参考；反制返回探测编码、完整状态字、四频段状态和查询时间 |
| `GET /sensing/targets` | 按设备、活动状态、雷达分类和更新时间分页查询雷达航迹目标 |
| `GET /sensing/targets/{id}/track` | 最多查询 24 小时、500 个原始航迹点 |

前端总览和设备树每 10 秒刷新，所选设备状态、曲线、事件和活动命令每 2 秒刷新。暂停时停止刷新；页面卸载时清除全部定时器和图表实例。

### 重启

`POST /devices/{device_id}/commands/reboot` 返回 HTTP 202。必须提供唯一的 `Idempotency-Key` 请求头和 `{ "reason": "..." }`。同一键、同一请求返回原命令；同一键、不同载荷返回 `IDEMPOTENCY_CONFLICT`。

命令状态：`QUEUED → SENT → SUCCEEDED/FAILED/TIMED_OUT`；契约同时保留 `ACCEPTED/CANCELLED` 供 live Adapter 使用。`GET /device-commands/{command_id}` 返回命令、模拟标识、结果以及追加保存的 `receipts`。

停用、离线或状态未知设备拒绝重启。当前 mock Worker 从数据库 Outbox 领取任务，使用条件更新租约、指数退避和最大重试次数；超过截止时间或重试上限进入 `TIMED_OUT`。应用重启后继续扫描未完成记录。

两个本轮 live 协议均未声明重启能力，因此即使设备在线也返回 `DEVICE_NOT_OPERABLE`。雷达启停、寄存器写入、反制继电器动作及射频发射没有 REST、Outbox 或页面入口。

## 4. 接入调测

状态机：

```text
CREATED -> CONNECTING -> CONNECTED -> READY -> RUNNING
                                      |          |
                                      |          +-> PASSED / FAILED / UNTESTABLE
                                      +-> CANCELLED
```

任一非终态可取消；非法跳步返回 `ILLEGAL_STATE`。重新连接必须创建新任务并填写 `previous_task_id`，旧任务和旧报告不覆盖，且前次任务必须属于同一设备。

| 方法与路径 | 行为 |
| --- | --- |
| `POST /commission-tasks` | `{device_id,previous_task_id?}`；创建 `CREATED` 任务 |
| `POST /commission-tasks/{id}/connect` | `{version}`；HTTP 202，进入 `CONNECTING` |
| `PUT /commission-tasks/{id}/configuration` | `version` 加连接配置 DTO；仅 `CONNECTED` 可保存，进入 `READY` |
| `POST /commission-tasks/{id}/start` | `{version}`；HTTP 202，进入 `RUNNING` |
| `POST /commission-tasks/{id}/cancel` | `{version}`；取消非终态任务 |
| `GET /commission-tasks` | 支持 `device_id/status/page/size` |
| `GET /commission-tasks/{id}` | 返回任务详情、版本和配置快照 |
| `GET /commission-tasks/{id}/events` | `after_seq/limit` 增量返回步骤日志 |
| `GET /commission-tasks/{id}/report` | 仅 `PASSED/FAILED/UNTESTABLE` 可查看，返回判据快照、分项结果和模拟警示 |

任务在创建时冻结 `source_mode`、协议代码/版本、协议专属配置、CIDR 白名单及凭据引用；连接配置在 `PUT /configuration` 时冻结。后续编辑设备或来源不会改变历史任务使用的适配器路由和安全边界。

mock 分项仅验证流程接线，不是正式阈值。雷达 live 调测依次验证 TCP、DATA 登录、心跳、工作模式读取、可选 RTK 和点迹/航迹接收；雷达待机无业务数据时为 `UNTESTABLE`。反制 live 调测只验证 TCP、编码探测、状态查询、地址/校验和和四通道映射；`PASSED` 也不包含射频发射验证。

## 5. 雷达与四通道接入约定

- 雷达帧为大端 `0x55AA55AA + frame_length + command + frame_id + payload + CRC16-MODBUS`；live 拒绝调试 CRC `0xCCCC`。TCP 解码器处理拆包、粘包、错误帧头重同步和 1 MiB 帧长上限。
- 雷达每 10 秒发送心跳，连续三个周期无有效帧判离线；连接按 1、2、4…60 秒退避，由 `device_connection_lease` 保证同一设备同一时刻只被一个应用实例持有。
- `UPLOAD_TRACK_V3` 的无符号 32 位航迹 ID 保存为十进制字符串；原始 x/y/z、速度、SNR、两种 RCS、设备分类和选中标志追加保存。超过 3 秒未刷新只转为失活，不删历史。
- 分类 0–5 只映射为待识别、人、车辆、无人机、鸟、未识别，不推导合法性、风险、融合置信度或告警。点迹无稳定目标 ID，只写原始 Inbox 和最新点迹摘要。
- RTK 至少 20 帧后形成未人工验证的站点参考；协议声明高度无效，因此不保存或推导 AGL/AMSL。参考值、北向标志和方位基准未全部验证前，经纬度保持缺失，绝不生成零坐标。
- 四通道完整 32 位继电器状态字保存；只把低四位归一化为 900M、1.5G、2.4G、5.8G。适配器实现中不存在 `0x11/0x12/0x13` 发送路径；迫降 `0x0F` 与驱离 `0x0D` 仅存在于协议编码单测。

## 6. 稳定错误码

| 错误码 | HTTP / 含义 |
| --- | --- |
| `UNAUTHENTICATED` | 401，会话缺失、过期或失效 |
| `FORBIDDEN` | 403，无动作权限 |
| `DEVICE_NOT_FOUND` | 404，设备不存在 |
| `DEVICE_COMMAND_NOT_FOUND` | 404，命令不存在 |
| `COMMISSION_TASK_NOT_FOUND` | 404，调测任务不存在 |
| `DEVICE_NO_CONFLICT` | 409，设备编号或来源外部编号冲突 |
| `VERSION_CONFLICT` | 409，乐观锁版本落后，前端刷新后重试 |
| `ILLEGAL_STATE` | 409，状态机前置条件不满足 |
| `DEVICE_NOT_OPERABLE` | 409，设备停用、离线或其他不可操作状态 |
| `IDEMPOTENCY_CONFLICT` | 409，同一幂等键对应不同请求 |
| `ADAPTER_UNAVAILABLE` | 503，对应模式无设备适配器 |
| `PROTOCOL_NOT_CONFIGURED` | 503，真实协议尚未配置；预留给 live Adapter |
| `PROTOCOL_UNSUPPORTED` | 400/503，协议代码不支持或对应适配器未注册 |
| `PROTOCOL_FRAME_INVALID` | 400/运行态失败，帧头、长度、CRC、地址、功能码或校验和无效 |
| `PROTOCOL_MODEL_UNVERIFIED` | 400，资料型号与协议版本关系未核实 |
| `NETWORK_TARGET_FORBIDDEN` | 400，目标地址不在 CIDR 白名单或属于强制拒绝地址 |
| `CREDENTIAL_UNAVAILABLE` | 400/运行态失败，凭据引用缺失、格式错误或无法解析 |
| `CONTROL_NOT_ENABLED` | 409，协议控制能力未开放 |
| `VALIDATION_ERROR/INVALID_REQUEST` | 400，字段或请求格式无效 |

## 7. Adapter 联调边界

`DeviceAdapterRegistry` 按来源模式和协议代码选择 `DeviceAdapterPort`。`RadarTcpV300Adapter` 与 `CountermeasureTcp4ChV20Adapter` 已承接本轮资料中的只读连接和调测能力；甲方新增协议通过新 Adapter 接入，不改变前端 REST 契约。

1. 厂商字段与平台 DTO/状态枚举映射；未知码保留原值并输出 UNKNOWN 原因。
2. 使用 `credential_ref` 从批准的凭据设施取密钥，不把密钥写入接口、日志或报告。
3. 把认证后的设备回执写入 Inbox，再关联到命令回执；重复来源消息不重复推进状态。
4. 只依据确认后的判据生成真实调测结论；无判据或必要数据缺失返回 `UNTESTABLE`。

本轮不包含真实反制发射、雷达启停/寄存器写入、真实控制授权、融合感知告警联动、Excel/PDF、证据归档和完整组织数据范围。`UAD-GD01` 为三通道资料，不绑定四通道协议；`UAD-GRF-210R/UAD-GRB-578D` 核准证也不作为协议兼容证明。取得现场设备、网络路由和型号确认前，软件验收仅以协议模拟器为准。
