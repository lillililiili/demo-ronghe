# 合法性判定与告警：页面设计、处理规则、操作流程

版本：2026-09-23，设计评审稿。依据：本轮44项场景Excel、当前页面源码、用户截图和项目已确认约定。本文是拟采用的业务设计，不是全部功能已经上线的声明，也不是完整法规清单。

## 1. 两个模块各管什么

**飞行计划／合法性判定负责判清楚；告警／处置负责把当前风险处理完。已有告警时，在告警里核对同一份研判；没有告警时，在合法性判定中核对。**

| 事情 | 业务归属 | 操作入口 | 完成后看什么 |
|---|---|---|---|
| 查看计划、航线、飞行时间及计划状态 | 飞行计划 | 现有计划详情；相关页面可查看关联资料 | 有效计划及适用时间 |
| 自动判定、查看依据、核对不确定项 | 合法性判定 | 有告警在告警详情原地核对；无告警在合法性判定核对 | 同一份研判与复核记录 |
| 风险告警、通知飞手、通知上级、跟踪纠偏 | 告警／处置 | 告警详情 | 事件状态、独立通知回执、有效后续观测 |
| 反制申请、审批、执行监测、急停 | 告警／处置 | 告警详情“手动反制”；现有“反制办理”页签 | 授权、下发、设备回执分别查看 |
| 交接、处罚通知送达、签收、办理结果 | 移送与处罚 | 告警只读查看移送进度，通过同一交接进入 | 交接进度与处罚办理结果 |

“在哪里显示”和“在哪里处理”分开：明确识别为无人机的研判记录均可在合法性判定查询；满足风险触发条件的事件进入告警。同一目标可以两页都有，不复制出两份人工复核待办。鸟类、气球、风筝及类别未知目标不进入无人机合法性判定，继续遵循原风险模块范围。

## 2. 合法性判定页怎么改

保留现在的顶部统计、左侧筛选与列表、右侧结论和空间证据地图、底部主按钮。用户要求删除的“关联资料与判定信息”整块继续删除，不重新放回算法版本、演示规则集及准确率状态。

| 位置 | 内容与操作 | 规则 |
|---|---|---|
| 结果页签 | 待处理、全部无人机、合法、异常、非法、不可判定 | 默认待处理；范围仍为“不可判定或待复核”的并集 |
| 筛选区 | 区域、复核、计划、核实位置 | 核实位置为全部／告警页面／合法性判定页面；列表、统计、分页同范围 |
| 列表 | 目标编号、匹配计划、区域、判定结果、违规／未知原因、研判时间 | 判定结果与复核状态分开；未知可靠性不伪装待复核 |
| 详情首部 | 当前采用结论、依据、观测时间、研判时间、确实存在的信息缺口 | 有人工结论时与原系统结论区分；不重复堆叠同一事实 |
| 地图与证据 | 当前目标实际轨迹、匹配计划、关联视频与证据 | 绿色符合、红色偏离、灰色未飞计划线；未知关系单列，不补轨迹 |
| 底部主按钮 | 有实际关联告警：前往告警页面；无告警且需复核：核对信息缺口 | 可靠明确结论不强制复核；按钮按后端权限与状态出现 |
| 历史／更多操作 | 查看复核记录、允许时重新研判或纠错 | 重新研判生成新记录；不覆盖原始结论 |

没有关联告警、告警生成受阻、无告警查看权限、关联读取失败必须分别显示。不能仅因“曾触发生成”就把操作员引到不存在的告警。有关联告警但没有权限时，不借合法性页绕开同一办理归属和权限。

## 3. 告警页怎么改

保留顶部统计卡、告警与处置／反制办理页签、左侧事件列表、右侧地图及详情。两个页签切换时统计卡保持完整尺寸。44项业务场景不做成44个新告警类型，也不新增一个“总处理状态”替代现有状态。

| 详情顺序 | 展示什么 | 可以做什么 |
|---|---|---|
| 当前风险与依据 | 当前风险、采用结论、关键依据和观测时效；有缺口时写具体缺什么 | 可靠明确结论直接查看响应；确实需核对才显示主入口 |
| 核对信息缺口 | 原地展开现有复核表单：确认／驳回／改判、核对说明 | 提交同一研判复核命令；无须跳回合法性页再填一次 |
| 通知摘要 | 飞手短信、电话录音各自状态 | 展开查看各渠道接收信息、过程、回执、失败原因与允许的动作 |
| 风险依据与证据 | 关联研判、计划、实际轨迹、证据入口 | 可在当前详情查看目标实时视频；切换目标停止旧视频 |
| 底部操作 | 当前主动作、手动反制、当前事件反制记录 | 反制另做权限与依据校验；不能因复核完成而自动下发 |
| 移送进度 | 后端实际进度及同一交接入口 | 只读，未启用／未接入／失败／未知如实显示 |

不恢复“需要你处理”“补充操作与事后移送”“飞手通知与现场记录”等已取消整块，不新增人工现场情况填报。通知摘要及回执是原通知事实的精简展示，不再包在已取消的混合表单中。旧观察、反制和冻结材料保留为历史。

## 4. 什么情况进入告警

以下是业务触发边界。具体距离、高度、持续时间、时间容差、重复通知间隔、观测有效期和解除观察窗口，必须使用有效配置；本设计不编造数值或默认启用新规则。

| 类别 | 可以进入告警的前提 | 只留在研判待核对的情形 | 首要处理 |
|---|---|---|---|
| 无所需授权飞行 | 该次飞行确需授权，来源完整及时，明确无其他有效授权且实际在飞 | 计划接口失败、身份匹配失败、来源不完整 | 可靠违规按策略响应；有疑点核对授权 |
| 疑似无计划飞行 | 计划查询正常且来源完整，已启用此类疑似风险规则 | 未启用该规则，或查询失败导致查不到计划 | 若触发，告警标待核对；不直接标已确认黑飞 |
| 禁飞／限制／临时管制 | 有效位置、有效区域和时段，适用规则及例外条件明确 | 边界、规则版本或位置质量不足 | 持续跟踪，按已启用策略通知；有疑点核对 |
| 航线／区域偏离 | 有明确匹配计划、有效走廊或边界，偏离超过配置阈值 | 未匹配计划、走廊缺失、定位漂移或断点 | 通知飞手纠偏、监测恢复；不直接反制 |
| 高度违规 | 实测与规则／计划限高使用可比高度基准，依据充分 | 高度基准缺失或数据不足 | 通知纠正，继续观测 |
| 时间违规 | 有实际飞行事实，适用起止时间明确且没有有效延期／例外 | 计划时间缺失；只有计划结束、没有实际观测 | 按规则通知，保存发生时的事实 |
| 夜航／超视距条件不满足 | 适用条件及所需资料可核验，能证明不满足 | 仅识别夜间时段、仅距离较远、飞手位置未知 | 按已启用规则处理；条件不清核对 |
| 多项同时发生 | 每项风险分别有依据 | 某项未知不能抹去其他已证实风险 | 同一关联事件保留各风险；只解除有恢复依据的项 |

通知失败、通知未知、目标失联、反制失败、移送失败是现有事件的处理异常，优先更新同一事件，不因每一次失败重复生成新的无人机违规事件。

## 5. 一条记录的自动处理规则

| 步骤 | 输入与依据 | 后端自动做什么 | 人何时介入 | 失败后怎么处理 |
|---|---|---|---|---|
| 识别目标 | 当前观测及目标类别 | 区分类别，关联同一目标和轨迹 | 类别、关联不确定 | 未知仍未知，不假定无人机 |
| 核对资料 | 计划、授权来源、适用规则、空域、实际飞行 | 检查时效和必要资料，逐项计算 | 必要资料缺失、冲突、结论不可靠 | 显示具体缺口，保留可信单项事实 |
| 形成研判 | 各项检查及证据充分性 | 给出结果、依据、可靠性与需要复核的原因 | 无法可靠明确判定或发现新证据纠错 | 失败／未接入／旧记录未知不当作可靠 |
| 触发告警 | 有效风险事实及已启用规则 | 生成或更新精确关联的事件，按既有规则去重 | 独立事实争议或关联异常 | 生成失败单独显示，不伪造已关联 |
| 通知和监测 | 当前事件、有效依据、接收信息、通道配置 | 按授权规则通知飞手、通知上级；持续监测 | 缺联系人、失败、结果未知、其他异常 | 两渠道分别留痕，按条件重试，保留旧事实 |
| 复核影响处理 | 同一研判复核及当前事件全部依据 | 更新采用结论，重评待办、通知及动作资格 | 只核对未解决部分，不重复确认已处理事实 | 保存结果与关联处理结果分开显示 |
| 风险恢复 | 有效后续观测和对应解除规则 | 更新单项风险，检查是否仍有其他风险 | 数据异常或独立争议 | 失联、过期、执行未知不作解除 |
| 事后移送 | 后端自动移送配置及实际交接 | 能力启用时按既有流程推进 | 查看失败／异常及既有办理事项 | 保留历史，移送不等于处罚决定 |

这些动作由后端事实和规则驱动，不依赖用户停留页面。读取详情、刷新、轮询、打开视频不得触发复核、通知、反制或移送写入。

## 6. 复核规则与两页同步

1. 先使用后端的判定可靠性及允许动作判断是否需复核。合法、非法标签、风险分值、目标识别置信度均不能替代这一步。
2. 有实际关联告警时，主入口放在告警详情；没有关联告警时，在合法性判定。业务仍写入同一研判的复核历史。
3. 表单沿用确认（采纳系统结论）、驳回（系统误判）、改判（选择其他人工结论）。核对说明必填，1—1000字，只填补充依据，不重新抄写已有资料。
4. 保存时带研判及事件的精确关联、当前版本和幂等标识。两人同时提交时回读新版本；超时结果未知先查记录，不盲目重复提交。
5. 保存后两页读取同一结论和历史。原系统结果、依据、人工操作人及时间分别保留；人工复核不篡改机器证据充分性。
6. 后端重新评价受影响事件、各项风险和动作资格。可靠结论可按有效策略采纳，同一事实不要求再填写一次“告警属实”；独立于合法性判断的事件争议仍按现有事件核实处理。
7. “研判已复核”不必然等于“告警已确认”，更不等于“风险已解除”。改判合法或驳回一份研判时，还要检查其他有效风险，不批量关闭全部关联事件。
8. 复核后仍不可判定，可继续留在合法性页“待处理”，因为该队列是不可判定或待复核的并集。不能为清待办将未知改成合法。
9. 如果复核已保存但关联更新失败，明确展示两个事实，后端恢复处理；依赖该结论的新动作不得继续使用已被纠正的旧依据。

## 7. 通知、反制、解除分别判断

| 动作 | 必要条件 | 页面规则 | 不能推出的结果 |
|---|---|---|---|
| 飞手短信 | 有效触发策略、依据、接收信息、已接入启用通道 | 分别显示触发、发送、送达、失败／未知 | 送达不等于已读或纠偏 |
| 电话录音 | 有效策略、可用号码、录音及电话通道启用 | 分别显示拨打、接通、播放、失败／未知 | 接通不等于播放完成或理解 |
| 再次通知 | 当前仍符合通知条件，符合重试／重复通知配置 | 新尝试与历史事实分开；未知结果先查回执 | 不能通过刷新过期告警强行重发 |
| 通知上级 | 当前有效风险通知规则 | 统一通知上级，不增加职责单位选择 | 不覆盖飞手通知及处罚通知的接收关系 |
| 手动反制 | 当前有效无人机观测、关联本事件且证据充分的明确违规依据，以及后端授权、设备、时效、急停校验 | 有直接权限用直接反制，否则按申请审批资格；提交、排队、续链均重验 | 复核成功、短信失败、没有回复均不是反制授权 |
| 反制执行 | 有效授权、实际下发及设备反馈 | 授权、下发、回执、执行结果各自展示；急停独立可见 | 申请通过不等于已执行，执行成功不等于风险解除 |
| 风险解除 | 有效后续观测与对应解除规则，关联风险逐项检查 | 显示解除依据及时间；历史通知、轨迹和授权保留 | 目标消失、数据过期、计划结束均不能单独解除 |

当前没有配置自动反制。原型“手动反制”只演示入口与阻断原因，不发送任何命令。不提供人工执行通道或手填执行成功。设备急停后的实际停机核查仍属于设备安全流程。

## 8. 值班员实际怎么操作

### 流程A：正常飞行

系统持续比对 → 合法性页记录可靠合法结论 → 不触发对应风险告警 → 值班员无需确认。出现新的有效风险后转对应风险流程。

### 流程B：只有信息缺口，没有告警

打开合法性判定“待处理” → 按核实位置筛选“合法性判定页面” → 选中记录，查看具体缺项及有效资料 → 系统尚未补齐时，点击“核对信息缺口”提交有依据的结论 → 查看同一复核记录或新研判。仍不足就继续不可判定，不强行判合法或黑飞。

### 流程C：已有告警，需要核对

打开告警，或从合法性页“前往告警页面”精确进入当前事件 → 看风险、依据与观测时效 → 原地点击“核对信息缺口” → 填确认／驳回／改判及说明 → 提交后查看保存结果和关联更新状态 → 后端根据有效结论继续响应。合法性页同步展示同一复核记录，不再填写第二次。

### 流程D：可靠偏航，通常提醒即可

系统确认偏航且达到配置阈值 → 生成／更新关联告警 → 按启用策略发送短信、拨打录音电话并持续监测 → 值班员查看两个渠道回执 → 有效航迹恢复且满足解除规则则更新风险。无需先做人工核实；偏航或通知失败不直接反制。

### 流程E：可靠明确违规，确实需要设备干预

系统采纳可靠违规依据并响应 → 值班员在告警点击“手动反制” → 后端返回申请或直接反制资格，缺少条件则显示原因 → 按当前权限完成申请／审批或直接操作 → 在“反制办理”看实际下发及设备回执，必要时急停 → 持续监测风险变化。任何阶段结果未知都保留未知，不人工填成功。

### 流程F：通知失败或目标失联

通知失败：展开对应渠道记录 → 区分失败、发送中、未知及未启用 → 按后端资格处理可重试事项，保留另一渠道结果。

目标失联：查看最后有效观测及过期原因 → 保留告警和历史通知 → 处理数据异常并等待新有效观测；阻断依赖旧观测的新反制动作。恢复观测后重新评价，不把失联当飞离。

### 流程G：发现误判或一项风险恢复

在当前办理入口查看证据并纠正同一研判 → 原始结论和历史保留 → 后端逐项检查其他风险 → 有其他风险继续处理；单纯证据不足保留未知；有解除依据才解除对应风险。事件历史及冻结交接材料不删除。

### 流程H：风险结束后的移送与处罚

告警查看自动移送的真实启用状态和进度 → 已有交接时打开同一交接 → 在移送与处罚查看送达、签收及办理结果。风险处理耗时与事后案件办理分别计时，送达或签收不代表办结。

## 9. 页面异常状态

| 状态 | 页面展示与处理 |
|---|---|
| 加载、空列表 | 显示加载或当前范围无记录，不展示虚构正常值 |
| 关联读取失败 | 已知依据继续可见；关联部分明确失败，可重试读取 |
| 无权限 | 现有可见事实只读，写动作不可用；不能跨页绕过 |
| 新研判取代旧研判 | 旧记录可读，按明确取代关系进入新记录，不按目标随便取最新一条 |
| 多人并发／提交超时 | 留住说明，回读版本、历史及实际结果；不重复制造办理记录 |
| 复核保存成功、事件同步失败 | 展示关联处理失败，阻断依赖错误旧结论的新动作，保留已保存复核 |
| 目标失联／依据过期 | 显示当前未知、最后有效时间，保留历史；不自动变合法或解除 |
| 没有视频 | 按未接入、无任务、无权限、读取失败准确区分，不把跟踪成功当有视频 |
| 已解除／历史事件 | 只读看解除依据、历史通知、授权和交接，不恢复当前风险闪烁 |

## 10. 当前已经有的与还要补的

根据本轮代码检查：合法性页已提供核实位置筛选及关联告警入口，相关资料大面板已移除；研判复核和告警核实仍是不同命令。研判复核当前不会自动改变告警核实状态，反制资格仍有事件已确认的后端检查。

因此实施必须按以下顺序，不能只删前端按钮：

1. 后端确定事件精确采用哪份研判，以及复核后的采纳、关联更新、冲突和失败恢复规则；同时核对后台管理端与业务前台消费者。
2. 告警内嵌同一研判复核表单，复用现有复核命令；两页读取同一结果。
3. 后端有效采纳和下游动作校验打通后，取消对同一事实重复填写“告警属实”的步骤。独立事件争议保留。
4. 核对按单项可信风险触发告警的策略。当前综合不可判定可能阻断告警，不能直接把所有未知都改成告警。
5. 联合验证通知、反制授权、失联、恢复和移送，保留真实接口未接入／未启用的边界。

## 11. 验收情景

- 可靠合法和可靠非法均不出现强制人工核对。
- 计划接口失败只产生明确缺口，不假装无计划黑飞。
- 已有告警时从合法性页精确进入该告警，复核只提交一次，两页刷新后结果一致。
- 无告警时在合法性页复核；关联受限或读取失败不误当无告警。
- 筛选的列表、统计、分页同源；明确非无人机及类别未知不进入研判范围。
- 偏航通知后有独立短信及电话回执，通知成功不直接解除风险。
- 复核改判合法但仍有其他有效风险时，事件继续处理。
- 两人同时办理和提交超时不会重复写历史，不提示未经确认的成功。
- 复核已保存但关联失败时，页面如实显示且不会继续使用已被纠正的旧依据下发新动作。
- 失联阻断需要实时依据的反制；新有效观测恢复后重新检查全部资格。
- 申请、审批、直接反制、排队下发和续链分别检查权限及时效；急停独立可见。
- 未接入视频／短信／电话／自动移送如实显示，模拟不冒充真实成功。
- 多项风险逐项恢复，通知、执行、风险解除、处罚送达及签收保持独立。
- 新流程不覆盖原系统结论、人工复核、旧通知事实与冻结材料。

## 13. 飞行计划详情：当前仍影响本计划的风险

2026-09-23 用户确认：原“本计划的风险记录／近7天”区块应展示现在仍存在的风险，不是近7天历史发生量。已同步修改正式前台与后端读取接口，能力边界如下。

标题改为“本计划当前风险”，右侧显示“当前 X 起”，取消“近7天”。列表与数量使用同一范围：关联本计划，并有有效依据表明当前仍存在、仍影响本计划的风险。7天前发生但现在仍存在的也应纳入，不能按发生日期截断。

| 当前事实 | 展示方式 |
|---|---|
| 有有效依据确认风险仍存在、仍影响本计划 | 进入当前风险列表及当前数量 |
| 已通知或已签收，但风险仍存在 | 继续显示；通知进度独立保留 |
| 有有效依据确认已解除、已排除或已不再影响本计划 | 移出当前列表，在“全部风险事件”保留历史，不删除记录 |
| 目标失联、依据过期、当前状态无法确认 | 单独标为“状态待确认”，与明确当前风险分别计数；不假定解除 |
| 尚未到风险有效时间 | 不计入现在仍存在的数量；原记录保留 |
| 当前范围读取失败或缺少持续性判断能力 | 显示读取失败或当前状态无法确认，不显示“当前0起”冒充无风险 |
| 成功读取且没有当前风险及待确认项 | 显示“暂无当前风险”；历史仍可查，不据此承诺飞行安全 |

判断输入应包含风险来源有效时间、最新有效观测／更新、对本计划的当前影响及明确恢复／排除事实。缺少某类风险的持续或解除规则时，如实标明能力缺口，不给所有风险套一个擅自设定的时间阈值。前端不另建状态机，“未排除”不能直接等价于“现在还在”。

2026-09-23 实施：`GET /api/v1/risks/current` 按计划与账号范围读取，在分页前分类并返回 `current_total`、`uncertain_total`、`as_of`。明确排除的记录不列入；气象依据处于有效时段时列为当前，未到时段不列入，过期或缺少依据列为待确认；其余风险尚无可信持续／解除契约，统一如实列为待确认。没有新设失效阈值，也没有新增人工确认必经步骤。旧风险列表与历史不变。前台每30秒只读刷新，支持手动刷新及分页，离开页面清理轮询；失败不显示零起。当前实现不代表所有类型已具备实时解除判定能力。
