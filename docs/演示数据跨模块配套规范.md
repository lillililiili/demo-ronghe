# 演示数据跨模块配套规范

2026-09-16 用户确认：以后追加数据必须注意模块逻辑之间的配套。适用于本业务前台及其使用的同级 `../houtaiguanli` 后端演示数据；不授权操作生产数据或真实短信、设备通道。

## 基本原则

“造数据”等请求按两级 AGENTS 自动使用 `generating-business-scenario-data` 技能，将本规范作为项目依据；具体业务约束以最新项目规范和当前契约核对，不复制成长期不更新的另一套规则。实时设备数据优先走现有 MQTT 模拟入口，前置资料与历史补录分别配套；模拟来源及批次须贯穿接入、派生记录和验收。

以完整场景为单位追加数据，不以页面或表为单位机械加行。追加前明确业务日期和时区、批次、对象、关联 ID、来源、预期状态，以及“何时发生、系统当时做了什么、结果是什么、当前还需要做什么”。日期属于今天不等于目标观测、研判或事件仍在实时有效期内。

任何已有实现尚未提供的字段、权限、规则、自动化与回执不能在页面上编成既成事实。模拟数据明确使用 mock/replay，并在历史补录记录、审计及补充材料中说明其性质。

## 各模块的必要配套

| 场景 | 应关联的数据 | 必须成立的关系 |
| --- | --- | --- |
| 感知目标与轨迹 | 来源、目标、来源链路、轨迹、观测、最新状态 | 同一目标、同一来源范围；时间与坐标合理；断点保留，历史不冒充实时 |
| 飞行计划 | 报备资料、航线版本、时段、航空器、执行状态、实际轨迹 | 未执行不判实际飞行；已完成保留历史；无目标不等于未起飞 |
| 合法性与告警 | 目标/计划、规则版本、输入快照、研判、告警、事件 | 最新与历史结论分开；告警引用自身依据；未知原因不得为演示成功而删除 |
| 自动短信 | 触发依据、策略、任务、稳定渠道键、接收人、内容、发送记录、回执、审计 | 一事件一自动任务；发送和回执对应同一记录；已送达不因后来过期被覆盖 |
| 气象/异物风险 | 风险事实、适用计划和时间、核验、通知、接收方、回执 | 气象不虚构目标；风险状态与核验历史一致；未投递不显示已通知 |
| 劝离与反制 | 联系、联系后的现场观察、有效授权、指令、设备回执、结果核查 | 联系不等于飞离；发送不等于获准反制；申请、审批、执行分别有依据 |
| 处罚交接与案件 | 已核实事件、交接、材料快照、投递/接收、案件、办理历史 | 交接与案件状态一致；立案不是处罚决定；冻结材料不随新数据回写 |
| 证据 | 文件内容、哈希、来源、采集/入库时间、对象关联、可用状态 | AVAILABLE 有可下载且可校验的内容；历史补录通过补充材料关联 |
| 统计与大屏 | 业务事实、统计日期、范围和来源标识 | 数量口径可追溯；独立报表样本要明确为独立模拟口径，不能冒充业务台账精确汇总 |

## 自动通知：当前资格与历史结果

正常实时链为：有效观测及符合策略的明确依据 → 后台触发 → 任务领取 → 渠道发送 → 送达或失败回执 → 联系记录与审计。该过程不依赖浏览器停留，也不默认要求用户先点发送。

- 有已送达历史：持续显示原发送结果及时间，仍可提示当前目标观测过期；不得反转成未发送。
- 尚未发送且依据失效：保留阻断原因，不能推断已经发送，也不自动补成功回执。
- 发送失败或结果未知：如实保留，按服务端允许的重试与同一渠道幂等键恢复。
- 模拟送达不代表真实短信发送、接收人阅读、目标飞离或风险解除。
- 当前本地演示时效为观测/研判 120 秒、事件/人工确认 300 秒；这是可配置演示参数，不是正式行业规范。追加数据应适配策略，不能为了使页面成功而放宽这些参数。

## 历史模拟补录

用户要求补齐历史演示通知时，可以建立明确标识的模拟历史发送与模拟回执，但不能将其描述成当时系统真实执行过的操作。

1. 只操作明确的演示批次。先读取已有任务、联系、核实、交接、案件和审计；有用户办理、发送中、失败重试或已送达记录时不得覆盖。
2. 保留原告警时间、当前研判及未知原因。历史场景时间、实际补录时间和补录来源分别记录；无法还原的规则或观测不伪造、不硬填到规则引擎事实表。
3. 补录任务与联系记录使用稳定 ID 和幂等键，记录 `simulated=true`、`SIMULATED_DELIVERED` 和“模拟历史补录”。回执必须指向同一事件的联系记录；事件版本与实际新增记录同步，业务状态不被短信自动改变。
4. 审计保留操作前状态和补录原因。发生在交接后的补录，新增可校验的补充材料并关联事件/案件；不篡改已有冻结快照来声称交接时已包含该材料。
5. 历史夹具配套检查与实时策略触发验收分开报告。历史补录成功不证明这些事件在当时或当前满足自动发送资格。

## 验收与防重

- 数据库：同事件/同来源/同范围、唯一约束、状态与记录、时间顺序、任务与回执、文件哈希；重复运行不新增、不重置。
- 保护：原计划、轨迹、研判、告警发生时间、已办事项、冻结材料和非本批次记录保持不变；必要的事件版本更新及补录审计单独记录。
- API：标准接口回读状态与历史，不能仅凭 SQL 数量或页面文字宣称流程通过；读取不新增通知。
- 页面：告警详情、融合感知同一事件、处置与处罚、证据详情交叉核对；刷新和重新登录后仍一致，结果过期不抹掉历史送达。
- 实时场景另测：新鲜输入由实际后台策略自动处理、失败与重试、防重、未知和失效阻断；不通过伪造送达测试实时自动化。
- 测试优先使用最小隔离数据库/相关表，避免为少量补录复制整个实时观测库，减少对运行环境的负载。
