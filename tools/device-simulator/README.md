# 设备信息 MQTT 模拟器

## 全量关联场景（2026-09-30）

启动本机模拟器后打开 `http://127.0.0.1:8766/`，先连接本机业务后端，再点击地图下方“配置全量场景”。可选择无人机正常与异常飞行、单鸟与鸟群、未知/识别中目标、气球、人员、车辆、船舶、遥控器、气象、五类空域及设备异常，并选择现有飞手、计划来源绑定和通知回执策略。点击“生成完整草稿”后，可在地图中编辑目标、轨迹与来源；“完整资料与接口字段”可编辑整份场景 JSON。确认草稿后点击“一键启动全量场景”，等待运行状态进入“运行中”，再用“回读平台数据”核对设备、计划、空域、目标、轨迹点、气象、研判和告警。启动请求进入准备阶段不表示业务链路已经通过。

全量场景经授权接口提交计划、航线、空域、气象和规范化目标观测；已接入 MQTT 协议的设备继续发送设备与目标报文，不走数据库 seed。目标可设置 `motionMode=once|loop|pingpong`、逐航点 `altitudePath`、`dwellSeconds`、有限 `silenceWindows` 及明确高度基准；旧场景默认到终点停留。每类字段的必填、可选、不适用、未知项及输入路径见 [全类型字段覆盖表](docs/全类型字段覆盖表-2026-09-30.md)。

“停止场景上报”停止本批位置和设备报文；“停止全部收发”还停止通知接收与本机设备指令监听。停止不会删除已提交资料、历史观测、通知或审计记录，也不代表目标已飞离或风险解除。登录失效、MQTT 断开或发送结果未知时运行会停止并显示原因；恢复后须重新登录、检查本批回读，再决定是否启动新批次。真实飞手/接收对象资格、短信和电话通道、录音或媒体资源、反制授权与设备回执仍由平台实际校验；媒体未就绪时只能判为未就绪，不能把模拟器输入或接口接收计为媒体、通知或反制验收通过。

## 全链路实时收发（2026-09-30）

入口仍为 `http://127.0.0.1:8766/`，连接本机 `8081` 后端。新版服务加载后，地图下方显示“实时收发”。如提示尚未加载模块，须重启 Python 服务；刷新静态页面不能替代重启。服务重启后重新登录，收发不会自动恢复。

1. 打开“收发模式设置”，选择正常、异常或混合模式。默认持续运行、通知接收与模拟反制设备启用；反制设备须选择已有模拟计划取得单位和区域，不自动授予反制权限。无计划时先经“资料输入”提交，或显式关闭反制设备接收。
2. 点击“开始模拟”同时启动所选接收端与 MQTT 场景；只想接收通知和设备指令时用“启动接收端”。本地后端需加载 `local,qa`，保留现有录音配置及数据库连接，不能混用 `8767/18091` 隔离服务。
3. “暂停发送／停止场景上报”只控制场景；“停止全部收发”同时停止场景、通知接收和 TCP 监听并注销接收租约。退出网页不会停止任务。修改模式前需停止全部收发。

正常模式以运行副本消除设备离线、故障和短信后停报设定，保留业务风险和原轨迹；原场景另存 `source-scene.json`，不覆盖旧批次。异常模式沿用设备故障／离线窗口，可配置各通知渠道失败、超时、不回执和电话未接通／仅接通；混合模式保留正常设备指令并允许各渠道配置成功、失败、延迟、不回执或轮换结果。指令“不回执”不执行光电及四通道写指令；四通道“状态不变”返回实际未变化的模拟状态，光电仍正常。不得把通知成功、停报或指令发送确认视为飞离或设备执行完成。

四通道设备端仅监听 `127.0.0.1:10006`，支持协议 `0x10–0x13`、二进制和 ASCII Hex，端口占用报错，不切换端口。新启动模拟继电器全部关闭；停止模拟器后的本地归零不作为平台已核查停机的回执。

通知接收器每 0.5 秒取请求、每 5 秒续租，租约 30 秒，默认模拟电话播放 3 秒。每条消息保存首次接收时的处理模式与播放时长，切换配置或重启不改变该消息结果；短信观察 3 秒、电话播放完成后观察 10 秒仍由平台计算。收件箱包含短信、电话、风险、处罚、计划反馈、设备运维六类权威历史；运维通知回执不代表设备恢复。

本地接口：`GET/POST /api/realtime/config`、`GET /api/realtime/status`、`POST /api/realtime/control`（`action=start|stop_all`）。配置字段为 `mode`、`continuous`、`notifications_enabled`、`countermeasure_enabled`、`countermeasure_plan_id`、`command_mode`、`play_seconds`、`outcomes`。文件只保存模拟配置；登录与 MQTT 凭据仍仅驻内存。`start-realtime-workers.ps1` 调用统一接收控制，不再另启旧设备保活进程。

主进程与单独启动的接收器共用同一操作系统锁，防止重复回执；独立 `device_presence.py` 见到统一控制会停止保活，不会在场景停止后恢复旧设备。实时模式禁止数据库 seed 配套，计划、空域和天气使用已有受权接口。

本轮代码验证：Python 132 项、Node 43 项通过；四通道测试使用真实本机 TCP socket。实际 `8766/8081` 重启被自动审批阻止，尚未完成新进程五分钟全链路验收，不能用单元测试或首页 HTTP 200 代替。完整状态见后台仓库 `docs/designs/2026-09-30-realtime-simulator-delivery.md`。

## 持续实时模拟（2026-09-29）

在“运行时长”选择“持续运行（手动停止）”，再点击“开始模拟”。当前场景已启用且协议已接入的设备持续发送工参心跳，目标每秒发送新的时间戳、位置和速度，由平台实际接入、融合并生成研判。页面显示已运行时间，可暂停、继续或停止；关闭网页不停止服务端任务。

场景 JSON 中 `duration: 0` 表示持续运行，原有定时场景保持原时长。未设置 `motionMode` 的旧目标到终点后原地上报；显式配置 `loop` 或 `pingpong` 时沿闭合段或原路连续运动，不瞬移。场景中的离线、故障、通知后撤离或停报设置仍生效。持续模式的设备异常配置限定在启动后 24 小时内的一次有限时窗。计划、空域的原有效期不随持续模式延长；未接入的设备协议不会伪造报文。

MQTT 断开、发布确认失败或登录失效仍会停止并显示原因，需要恢复连接后重新启动；重启模拟器服务也不自动续发，须重新登录。新运行产生新批次，旧目标停止跟踪后的历史告警不会被改写成当前观测。持续上报不代表通知送达、获准反制或设备执行成功。

## 飞行计划申报资料（2026-09-28）

“资料输入 → 飞行计划输入”现在可以填写申报单位、飞手、起降点名称及 WGS-84 经纬度，并选择已有单位/飞手档案、来源报送单位关联。表单与展开的 JSON 报文同步；新样本默认使用“数据模拟器（飞行计划）”专属 mock 来源，首次提交由后端登记。

已有计划可从“已有模拟计划”或接收记录点击“读取并补录资料/补录计划资料”，读取当前版本后保存。补录保留原时间、状态、无人机 SN、航线和原上传记录；版本冲突需重新读取。缺失资料不自动编造，没有档案时填写申报名称后仍显示待关联；档案继续在后台用户管理左侧单位机构维护。

新增代理白名单仅开放 `/local-interface-simulator/plan-options`（GET）和 `/local-interface-simulator/plans/{id}/filing`（GET/POST）。服务端限制模拟/回放计划，并复用单位管理权限及飞手归属、角色和有效性校验，资料和关联一起回滚或成功。本次改动仅覆盖资料输入入口；地图 MQTT 场景的既有批次配套数据不自动回填。

验证命令：`node --test tests/test_plan_form.cjs tests/test_external_ui.cjs tests/test_external_session.cjs`，以及 `python -m unittest discover -s tests -p test_external.py`（在本目录执行）。

根据地图页面设计实现的独立本机工具。通过现有后端注册模拟设备，用 MQTT 向现有接入、融合与规则链路发送报文；不新建平台后端、不改业务前台路由、不直接填造告警。

## 启动

```sh
python3 tools/device-simulator/server.py --port 8766
```

打开 http://127.0.0.1:8766/ 。需 Python 3.9+、Node.js 及业务前台已有依赖；MQTT 使用现有 `paho-mqtt` 2.x，未新增项目生产依赖。启动时自动构建共享地图入口。

地图读取当前业务前台的同一配置、PMTiles 数据包、影像与配色。默认地图服务为 `http://localhost:5173`，需保持业务前台地图服务运行；端口变化时使用 `--map-origin http://localhost:实际端口`。地图资源仅经本机同源代理读取，保留 HTTP Range 206，不复制整份地图包；读取失败显示错误和重试入口。

启动终端需保持运行。若页面提示“模拟器服务未连接”，重新执行上述启动命令；页面会自动恢复状态读取。重启后在“登录系统”重新登录一次，历史批次保留且不会自动续发。提交操作时断连表示结果未知，先恢复连接并核对运行记录，再决定是否重新操作。

默认使用实时模式，不接受 `--database` / `--schema`；计划与空域资料通过既有资料输入入口提交。只接受回环 API 与已启用、source_mode=replay 的本机 MQTT 连接；不能用于现场/生产环境。

旧地图场景需要自动配套计划和空域时，显式选择 `--isolated-qa-scene`。仅允许 `stage456_verify_*` 测试库及 `monitor_events_<32位小写十六进制>` schema，并须使用 8766 以外的端口及共享 `.data` 目录以外的独立批次目录：

```powershell
python tools/device-simulator/server.py --isolated-qa-scene --port 18767 --database stage456_verify_qa0928r10 --schema monitor_events_替换为本次fixture的32位标识 --container 替换为测试数据库容器 --data-dir tools/device-simulator/.data-qa --map-origin http://localhost:5173
```

隔离场景模式保留原场景时长、故障/离线窗口及目标通知后行为，不启动实时通知接收器或本机反制 TCP 接收端。页面明确显示模式，实时收发设置与按钮禁用；仍可开始、暂停、继续、停止场景上报并回读系统结果。既有账号权限、管理员 seed 限制与 loopback broker 身份校验保留，错误参数在服务启动前拒绝。

每次 `psql` 只搜索指定 schema，禁用 `psqlrc` 覆盖，业务表不存在时直接失败；PostGIS 的 `ST_GeomFromText` 须安装在 `public`。默认容器为 `deploy-db-1`，用 `--container` 指定实际测试容器。启动不新建 schema，每批在创建批次及配套写入前核对当前 API 的 broker UUID。底层 `Prerequisites` 未指定 schema 时仍保留原默认查询行为；CLI 隔离模式必须显式指定 schema。

## 怎么操作

1. **连接设置**：填现有系统 API（本机为 `http://127.0.0.1:8081/api/v1`）、账号和密码。读取后台 `local-lingyun-replay`；如 broker 需要认证，另填 MQTT 用户名密码。凭据仅保存在进程内存，不写场景、日志或浏览器存储。计划/区域受控 seed 只允许测试系统管理员。
2. **地图编排**：地图上方分为“设备与目标”“航线与区域”“计划与气象输入”；左侧按任务显示对象，右侧编辑当前对象。风险列表默认收起，可通过“展开列表”配置。在系统真实地图上拖动、缩放，放置设备组（气象、5G-A、光电、TDOA、雷达），修改数量；绘制目标轨迹、计划航线与限飞区域。点击左侧对象定位并在右侧应用设置；“全览”回到当前场景范围。设备经纬度使用 WGS84，单台、追加、整组移动均保留。
3. **风险场景**：勾选本次启用的风险配置，配置对应的飞行计划或空域依据。目标与来源设备由模拟目标的设备观测生成，平台回读后自动判定关联；设备离线、设备故障场景才直接配置设备。目标有有效来源设备时，即使没有风险行也可上报；取消风险勾选不会停止该目标观测。组内支持协议的设备仍上报正常心跳。
4. **启动 MQTT 模拟**：冻结场景快照，复用或幂等注册 replay 设备与本批次资料，然后定速沿轨迹发送。运行 30 秒至 20 分钟后结束；暂停停止全部上报、继续沿原模拟进度运行；停止等待在途发布退出。关闭网页不停止 Python 进程内的运行任务。
5. **运行记录 → 回读系统结果**：分别查看 Broker PUBACK、后台设备事实、本批次目标、研判与告警。空结果不补成功，读取失败保留错误。源设备通过 `fusion_device_id` 对应目标 `source_links.device_id`。
6. **导出场景 / 导入场景 / 导出本批次**：场景可复用；批次导出包含设备/计划/区域映射、最近发送记录和系统回读。完整报文保存在本机 `.data/<batch>/events.ndjson`。

运行时锁定编辑器；停止后可以修改。保存场景仅保存编辑草稿，不会启动发送。未完成地图绘制时不能启动。

## 数据流与保护

- 设备注册：现有 `POST /api/v1/devices/onboard`，逻辑设备使用 `map-sim-<kind>-<scene-device-id>` 稳定身份；启动前按 `device_no` 回读并核对 broker、提供方、协议和外部编号，只有不存在时才用稳定幂等键注册，source_mode=replay。目标、计划、区域和批次证据仍使用批次身份。
- 雷达、5G-A、TDOA：复用 `LINGYUN_MQTT_V8_6` 工参和 SenseData 契约。QoS 1、retain=false；目标与批次身份固定，观测时间随实际发送更新，按速度和折线距离推进，终点停留，不循环瞬移。鸟群按数量生成独立观测编号、固定小范围编队偏移。
- 光电：`EO_EDGE_MQTT_20250826` HeartBeat，以及真实订阅下发主题后的 BeginTracking / EndTracking / CameraStatus 模拟回执。匹配系统当前任务后才执行；可显式开启本机 TEST VIDEO 水印测试流，不表示现场实拍。
- 离线：时间窗内停止该设备所有上报，恢复后正常上报；系统按自身超时阈值判离线。故障：协议 A workState=2，窗口结束后恢复原配置。
- 计划/区域：全量实时场景使用授权模拟接口提交 replay 航线、计划与空域，不走数据库 seed。仅显式隔离 QA 模式沿用受控 seed，通过 PostgreSQL 事务新增 replay 配套资料，并先核对 broker UUID。完整场景快照在任何写入前落盘，不覆盖或删除旧记录。
- 计划、区域时段使用**运行当天 Asia/Shanghai**。普通场景遵守页面时间；“超出计划时段”按选择的提前/延后及分钟数，将该目标配套计划定位到本批次开始前后，实际生效时刻可从系统计划回读。
- 一条编辑航线可为不同无人机生成各自绑定序列号的计划；鸟群关联的计划用于航线风险，不伪造鸟群飞行计划匹配。
- 暂停可能使系统判设备离线，停止不代表风险解除。发送失败或 PUBACK 超时会停止任务，结果未知不自动重发。MQTT 在两帧之间断线时等待最多 30 秒并恢复订阅；单条发布确认结果未知仍停止任务。服务重启恢复上次批次记录，**不自动续发**；重新登录并启动同一场景时复用稳定设备绑定，新运行仍使用新批次资料。
- 这不是平台规则引擎；不通过前端定时器生成系统告警、通知成功或反制成功。实际状态、合法性判定和告警均以系统回读为准。
- 2026-09-23：可视地图已替换为系统共用的真实底图，复用 `offlineMap.js`、`mapTheme.js` 与地图 tokens。旧 version=1 场景的内部 x/y 保留原 WGS84 换算，渲染时使用地图投影，因此原已发送位置不漂移；新选点不再受旧示意画布范围限制。重载已保存的草稿时，已完成批次不会覆盖草稿；运行中的批次仍显示其冻结快照。

## 当前协议边界

### 速度上报修正（2026-09-28）

- 目标报文现在携带 `objects[].speed`（米/秒），按当前轨迹段计算；雷达和 5G-A 同时携带 `extension.speedX/speedY/speedZ`（东、北、上）。当前轨迹为等高运动，Z 轴为 0；TDOA 不套用雷达的三轴扩展。
- 位置与速度共用 `target_motion()`：转弯改变方向，到终点、单点轨迹或设定速度为 0 时上报 0。通知触发撤离后使用撤离轨迹及撤离速度；停止目标上报时仍不发送目标报文。
- 修复仅影响加载新代码后的新报文，不回填已完成批次。服务需重启才加载 Python 修改，重启后重新登录，历史批次保留且不会自动续发。
- 设备上报、设备指令接收、外部接口输入与通知输出的完整核对见 [模拟器收发完整性梳理](../../docs/模拟器收发完整性梳理-2026-09-28.md)。清单区分已修复、待补能力及既有只读约定；不代表真实设备能力全部通过验收。

## 独立实时通知接收器（2026-09-29）

`realtime_notification_receiver.py` 独立运行，通过已启动且已登录的本机 8766 服务复用内存会话，无需保持浏览器打开，也不读取账号、密码或数据库。它读取平台实际出站请求并经 API 提交模拟设备回执；后端不得以本地 MOCK 定时成功替代本接收器。平台须已提供 `receiver_messages` 队列及 30 秒接收器租约；不满足时显示错误并停止续租。

```powershell
python realtime_notification_receiver.py --proxy http://127.0.0.1:8766
# 可选：改变模拟电话实际播放时长（默认 3 秒），或指定各渠道结果配置。
python realtime_notification_receiver.py --play-seconds 3 --outcome-file .data/notification-outcomes.json
# 默认数据目录下创建 stop 文件，接收器退出并注销租约。
New-Item -ItemType File -Path .data/realtime-notifications/stop
```

再次运行前移除自己创建的 stop 文件；`--data-dir` 可指定独立持久化目录，`--stop-file` 可指定停止文件。同一代理端口通过操作系统文件锁只允许一个接收器，即使选择不同数据目录也不能重复运行。后台运行请使用隐藏窗口并重定向日志；保持既有 8766 代理进程运行，代理重启后须在原界面重新登录。

接收器每 0.5 秒轮询、每 5 秒续租。收到请求后先以 UTF-8 原样持久化 `state.json` 与 `events.jsonl`，刷盘后才提交带版本及稳定幂等键的回执。短信为 `SUBMITTED → DELIVERED`；电话为 `SUBMITTED → ANSWERED`，经过实际播放时长才到 `PLAYED`；风险、处罚、计划反馈及设备维护为 `SUBMITTED → DELIVERED → ACKNOWLEDGED`。每轮只推进一个阶段，重启恢复电话计时，回执响应丢失时先查询平台确认；接通响应丢失则保守重新等待完整播放时长，不重复拨打。该播放时长不修改平台短信送达后 3 秒、电话播放后 10 秒的观察窗口。

只处理六类通知及 `simn-` 消息，`created_at` 必须为 epoch 毫秒。提交中或已接通请求满 60 秒只上报 `TIMEOUT`，不补造送达或播放完成；已送达通知仍可晚到签收。401、平台不可达、队列不支持或本地落盘失败会显示错误、停止本轮回执并退避 1～30 秒；不可达期间停止续租，旧租约最多 30 秒失效。恢复可访问后继续读取当前请求，不回填历史成功。

结果文件为按 kind 配置的 JSON 对象，例如 `{"ADVISORY_SMS":"no_receipt","ADVISORY_VOICE":"answered_only","RISK_NOTICE":"failed"}`。可用值：`success`（缺省）、`no_receipt`（完全不回执）、`failed`、`timeout`；电话另支持 `no_answer`（首步 FAILED）、`answered_only`（仅接通，超时后 TIMEOUT）。错误配置阻断回执和续租。模拟接收事实不代表真实短信、运营商电话、飞离、风险解除或业务办理完成。
