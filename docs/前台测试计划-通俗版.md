# 业务前台测试计划 通俗版

日期：2026年9月27日

这份文档给实际使用系统、负责测试和参与验收的人看。按下面的顺序操作，检查页面显示和实际处理结果是否一致。每测一项，记下“通过、有问题、暂时测不了、还没测”。

本文是测试安排，下面写的是系统应该怎样表现，不是已经测过的结果。

## 一 这次主要测什么

主要测试业务前台里的登录、融合感知、飞行计划、合法性研判、空域管理、告警事件、反制办理、移送与处罚、证据管理、运行统计和大屏。

要检查的不只是“按钮能不能点”。还要看：点完后事情有没有真正办成、处理的是不是这架无人机、换个账号能不能看到不该看的数据、出了问题会不会误显示成功。

| 打开哪个系统 | 地址 | 测试时用它做什么 |
| --- | --- | --- |
| 业务前台 | http://localhost:5173/#/login?redirect=/legality | 主要测试对象，按值班人员的日常操作来测 |
| 管理后台 | http://127.0.0.1:5175/login?redirect=/system/roles | 准备账号、设置权限，检查设备、通知和规则配置 |
| 信号模拟器 | http://127.0.0.1:8766/ | 模拟无人机、设备和飞行过程，配合检查前台反应 |

模拟测试使用测试设备和测试通知渠道。模拟短信成功，只能说明这次模拟过程正常，不能据此认定真实手机收到了短信；视频和设备动作也一样。

## 二 开始之前准备好这些东西

### 1 准备能做不同事情的账号

不需要把所有操作都放在一个管理员账号里。至少准备能覆盖下面几种情况的账号，哪些账号可以兼用，由管理员按实际权限安排。

| 账号能做什么 | 用来检查什么 |
| --- | --- |
| 只能查看 | 能看资料，但不能核实告警、审批或反制 |
| 能核实告警、申请反制 | 能提交申请，但不能跳过审批 |
| 能审批 | 使用另一账号审批，检查申请和审批是否分开 |
| 能执行已批准的反制 | 只能执行当前允许执行的任务 |
| 被明确授予直接反制权限 | 可以免去逐次审批，但仍要满足设备、范围、时间和证据要求 |
| 只能看某个单位或区域 | 不能看到、下载或处理其他单位、区域的资料 |
| 没有某个页面权限 | 即使知道页面地址，也不能直接进入 |
| 已停用 | 不能继续登录或操作 |
| 没有被授予直接反制权限的管理员 | 检查“管理员”身份是否被错误地当成直接反制许可 |

测试记录里写账号名称和权限，不写密码。

### 2 准备几组能互相对应的数据

请开发或环境维护人员配合，通过现有录入、接入和模拟工具准备。不要为了让页面有数据，直接把“执行成功”“已签收”等结果填进数据库。

| 准备什么 | 具体例子 |
| --- | --- |
| 正常飞行 | 有有效飞行计划，沿计划航线飞行的无人机 |
| 异常飞行 | 偏离航线、没有计划、进入测试限飞区域的无人机，各准备一组 |
| 不是无人机的目标 | 鸟、气球、风筝，以及暂时不知道类别的目标 |
| 信息不够的情况 | 没有新位置、资料不全、系统暂时不能确定是否合法 |
| 不同通知结果 | 没有核验飞手、短信可用或不可用、电话可用或不可用、发送失败或结果未知 |
| 不同飞行动作 | 收到短信后离开、收到电话后离开、继续飞、停止上报位置 |
| 不同办理进度 | 待审批、已批准、已驳回、已过期、排队中、执行中、执行失败、已急停 |
| 不同风险情况 | 待核验、待通知、已经通知但风险仍在、已经排除、暂时不能确认 |
| 不同天气资料 | 完全覆盖飞行时间、只覆盖一部分、不覆盖、缺少计划时间 |
| 不同证据 | 图片、视频、文件、飞行轨迹；还要有文件丢失、损坏和无查看权限的情况 |
| 容易混淆的数据 | 名称一样但实际不同的无人机、计划、文件；至少三页的列表；很长的名称 |

每次模拟都记下本次运行编号，以及对应的无人机、计划和告警编号。后续跨页面检查时，始终对着同一件事看，不能在几个页面各找一条看起来相似的数据。

### 3 有几件事要先说清楚

这些问题来自前一轮编制时对说明文档和代码的核对。正式测试前，应由负责人员确认当前实际情况。

| 要先确认的事 | 为什么要确认 |
| --- | --- |
| 短信送达后到底观察3秒还是10秒 | 现有说明写10秒，前一轮看到的代码写3秒。不能一边按3秒操作，一边按10秒判错 |
| 反制是人工发起，还是允许规则自动发起 | 既有要求是人工发起，但代码已经有自动发起的处理。自动模式要先明确使用条件 |
| 哪些自动功能已经开启 | 页面能打开，不代表自动研判、短信、电话、移送都已经开启 |
| 用哪些测试账号 | 不直接假定旧演示账号、旧密码还能用 |
| 计划、空域等测试资料从哪里录入 | 旧模拟器的配套方式与较新的数据录入要求存在差异，需要先确定本轮允许的办法 |

没有确认的相关项目，写“暂时测不了”和具体原因。能独立测试的其他项目继续做。

## 三 建议按这个顺序测试

| 顺序 | 做什么 | 做到什么程度再往下走 |
| --- | --- | --- |
| 第一步 | 检查账号、配置和测试数据 | 能登录，知道自己能做什么，本次数据能查到 |
| 第二步 | 每个页面先走一遍 | 能正常打开、查列表、看详情，关键位置不空白、不报错 |
| 第三步 | 完整处理一件事 | 从发现无人机，一直检查到通知、反制、移送和证据；只测本轮已具备的能力 |
| 第四步 | 换条件、换账号再测 | 检查误报、没权限、信息不足、设备故障、断网、重复点击等情况 |
| 第五步 | 修复后重新测 | 原问题确实消失，前后相关操作没有被改坏 |

按原详细计划估算，约需5～7.5个人工工作日，不包含等环境、等外部接入和开发修复的时间。多人配合、数据准备情况不同，实际时间也会变化。

## 四 先完整走通这六种情况

### 第一种 无人机正常飞行

先准备一份有效飞行计划，再让模拟无人机沿计划航线飞行。到“融合感知”里找到它，查看位置和轨迹；再打开对应飞行计划和合法性研判。

正常表现：几个页面显示的是同一架无人机，计划匹配正确；有充分依据时显示合法；已飞过且符合计划的轨迹显示绿色，尚未飞过的计划航线显示灰色。不能无故产生违规告警或反制动作。

### 第二种 无人机违规后按申请审批流程处理

准备一架持续在告警区域内飞行的违规无人机，并为它准备已核验的飞手和可用的模拟短信、电话渠道。值班账号核实告警后，观察短信、等待观察、电话、再次观察的过程。

仍未离开时，使用普通申请账号发起反制，换另一个有权账号审批，再由有执行权限的账号操作。查看测试设备有没有实际收到命令、有没有返回结果。具备移送条件后，再核对交接、送达、签收和证据。

正常表现：每一步处理同一个事件，审批前不能执行，页面提交成功不能冒充设备已经执行成功；移送、送达和签收分别有对应记录。

### 第三种 有直接反制权限并在执行中急停

使用被明确授予直接反制权限的账号，对一条符合条件的告警发起反制。执行过程中点击急停，查看设备回复和停机核查结果。

正常表现：可以免去逐次审批，但仍检查对象、设备、范围、时间和当前证据；记录真实操作人。点击急停后，只有确认了设备的实际结果，才能认定已经停机。重新打开页面不能自动恢复执行。

### 第四种 告警是误报或者信息不够

一条告警选择“误报”；另一条保留为资料不足或位置已过期。分别查看通知和反制情况。

正常表现：误报不会继续发短信、打电话或反制；资料不足时明确说明缺什么，不把“不知道”当成“合法”“已经飞走”或者“可以反制”。原始记录和处理历史保留。

### 第五种 风险已经通知但还没有解除

选一条计划或空域风险，核验后通知上级。对方收到或签收之后，保持风险仍存在；随后再提供能够证明风险解除的有效依据。

正常表现：收到通知时，风险仍然显示存在；有解除依据后才按规定退出当前风险列表。之前的通知记录仍能查到。

### 第六种 操作后突然断网

请开发人员在测试环境配合，模拟“系统可能已经收到操作，但页面没收到回复”。分别检查核实、通知、反制申请等操作，再恢复网络查看结果。

正常表现：页面说明结果还不能确定，先查原操作是否已经办成。不能因为没看到回复就重复发短信、重复申请或重复下发设备命令。

## 五 逐个页面检查

以下表格中的一行可能包含几种情况。例如“合法和非法各一条”，两条都要测，不能只测其中一条就写通过。

### 1 登录和账号权限

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 从提供的前台地址登录，再刷新页面 | 进入有权限的页面，登录身份正确，刷新后不白屏 |
| 不填账号密码、输错密码、使用停用账号 | 分别给出清楚提示，不让无效账号进入 |
| 用要求首次改密的账号登录，改密前直接打开业务页面 | 先完成改密；改密后旧密码不能继续使用 |
| 退出登录后，按浏览器后退，再刷新旧详情页 | 不能继续读取或操作受保护资料 |
| 用不同权限账号打开每个业务页面和大屏 | 能进哪些页面，与管理员给的权限一致；知道地址也不能绕过 |
| 用只能看甲单位的账号，尝试查看乙单位的列表、详情、文件和视频 | 不能看到、下载或处理乙单位资料；请开发协助检查直接访问也不能绕过 |
| 保持页面不关，让管理员撤销权限或停用账号，再尝试操作 | 旧页面不能继续靠原来的权限办事 |
| 打开原来的设备、监测、调测、用户、角色、审计页面地址 | 只显示已迁移提示，不重新出现后台管理功能，不自动跳到另一系统 |
| 打开旧风险页、旧首页、旧工作台地址和旧反制授权链接 | 进入当前承接业务的位置；反制授权仍定位同一条记录 |
| 修改登录后的跳转地址，填外部网站、无权限页面或错误地址 | 不被带到陌生网站；无权限仍拦截；错误地址不造成来回跳转 |
| 开两个标签页，退出甲账号后登录乙账号，再回旧标签页 | 不混入甲账号的数据；旧页面的失败回复不把乙账号的新登录错误清掉 |
| 打开详情后刷新、前进、后退，再试一条不存在的记录 | 能找回正确上下文；不存在时明确提示，不能随便换成另一条 |

### 2 融合感知

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 用模拟器发送一架无人机的位置，在前台找它 | 列表、地图、详情是同一架；位置、来源和最后上报时间正确 |
| 让多台设备观察同一目标，再增加一个相邻但不同的目标 | 同一目标按规则合并，不把旁边另一架错误合并；请开发核对识别关联 |
| 查看今天出现过、但已超过5分钟没有更新的目标 | 今天的记录仍保留；但不能说它还在持续实时跟踪；目标多页时数量不漏算 |
| 请开发准备跨夜数据，检查北京时间零点前后 | “今日目标”按新的一天重新计算，不混入前一天数量 |
| 分别查看正常、离线、有故障、数据失效的设备，再恢复设备 | 地图上的当前异常有提示，恢复后停止；设备类别仍看得清 |
| 在列表选择目标、设备和告警，并打开两侧详情 | 地图选中位置突出、不被挡住，也不能为了显示好看把坐标挪走 |
| 查看有转弯、停留、中断、不同段落的轨迹 | 如实显示，不能把中断前后强行连起来，不能补出不存在的飞行路线 |
| 查看按计划飞、偏离计划、尚未飞过和缺少判断依据的路段 | 按计划已飞段绿、偏离段红、未飞计划段灰；缺依据说明未知，不能乱染色 |
| 打开视频后换目标、收起视频、离开页面 | 旧画面及时停止；无视频、无权限、模拟画面分别说清楚 |
| 请开发模拟地图加载失败、数据读取失败，再恢复 | 失败不能显示成“没有目标”，也不能用假数据填充；恢复后地图不重叠 |

### 3 飞行计划

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 打开一份已录入的计划，核对单位、飞手、无人机编号、起降点、时间和航线 | 与录入资料一致；缺的资料写未提供，不能自己补造 |
| 按不同条件查计划，组合筛选、翻页、清空条件 | 条件一起起作用，列表和总数一致；改条件后不会卡在空白的旧页码 |
| 选择不同计划查看航线，再关掉详情 | 每份计划对应自己的航线；选择和筛选不混乱；轨迹颜色保持一致 |
| 计划到时间却没发现无人机，分别检查设备正常、异常、资料不足 | 分清“设备异常”“可能没起飞”“目前不能确认”，不能一律认定未起飞 |
| 在起飞时间之前查看设备检查 | 可以查看检查情况，不能提前当成“到时未起飞”去通知 |
| 对真实测试异常发出设备异常通知，再快速重复点击 | 后台能找到对应处理事项；不能多建同一事项；通知完不等于设备已修好 |
| 查看完全覆盖、部分覆盖、不覆盖计划飞行时间的天气预报，以及缺计划时间的情况 | 只展示与计划时间重合的部分；没覆盖和缺时间分别说明 |
| 打开有覆盖但时段已经结束的预报，再切页回来 | 按现有要求正常保留发布时间和时段，不恢复已取消的“预报过期”提示和到期刷新 |
| 查看“本计划当前风险”，加入持续风险、已解除风险、已通知但未解除风险和待确认情况 | 当前数量与当前列表一致；已通知仍可能是当前风险；待确认单独说明；历史保留 |
| 快速切换同名的不同计划，再进入研判或证据 | 不串天气、风险或证据；完成、取消计划按当前规则展示，不拿上一份内容顶上 |

### 4 合法性研判

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 首次打开页面，对照各类待处理记录 | 默认显示“待处理”；确实需要处理的记录不漏，列表、翻页和统计一致 |
| 准备无人机、鸟、气球、风筝和未知目标，再尝试列表和直接链接 | 这个页面只承接明确识别为无人机的研判；没有计划的无人机仍可保留 |
| 切换“核实位置”，再叠加其他筛选 | 按当前研判是否关联告警筛选；不能把没权限查看告警误认成没有告警 |
| 分别打开依据充分、可以明确判为合法和非法的记录 | 两种明确结论都不强行要求再人工确认；不能只看风险分数来判断可靠程度 |
| 打开依据不足、且没有对应告警的记录，进行人工复核 | 在合法性页办理；复核后更新结果并保留以前的依据和处理历史 |
| 打开依据不足、但已有对应告警的记录 | 去对应告警页核实；回来能看到同一结果，不要求两页各核实一次 |
| 打开没有保存可靠程度的旧记录，或判断失败的记录 | 明确写未知或不可用，不能默认当成可靠或合法 |
| 筛选“待复核”“已确认”“已驳回”“已改判” | 按实际处理情况分类，不把所有“从未人工操作”的记录都塞进待复核 |
| 两个人同时打开同一条待复核记录，先后提交不同结果 | 后提交的人收到冲突或更新提示，不能无声覆盖先提交结果 |
| 带着筛选条件打开指定目标或计划的研判链接，再快速换记录 | 能定位指定记录，必要时解除妨碍定位的筛选；详情和视频不串对象 |
| 查看详情里的各个区块 | 保留判定依据和复核历史；不恢复已经删除的整块信息及上一条、下一条箭头 |
| 请开发模拟目标后来被判为非无人机，或关联告警读取失败 | 不继续按无人机展示；读取失败不能被当成无告警并放开重复核实 |

### 5 空域管理

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 查询、选择、关闭不同空域详情 | 列表、地图范围和详情对应；没选中时不留空白详情栏；选择空域不偷偷改变筛选 |
| 准备范围内、边界上、范围外的目标，并用限制区域账号查看 | 按已确定的空间规则处理；不能只凭地图上看起来靠近就算在范围内，也不能越权 |
| 查看当前风险和已经解除的历史风险 | 当前异常有提示，历史不继续闪；通知送达不自动解除异常 |
| 有位置、有权限且测试设备空闲时，发起光电跟踪 | 跟踪的是所选目标；命令收到、跟踪成功、有视频分别显示 |
| 没有位置、没有权限、设备忙，或只有气象风险时尝试跟踪 | 明确说明不能操作的原因；不能虚构一个目标去跟踪 |
| 查看空域资料和风险详情 | 不恢复“关联规则”区块，不把后台规则编辑功能放回前台 |

### 6 风险核验和通知上级

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 对待核验风险分别选择属实和排除 | 处理结果及历史正确；已排除的事项不继续要求重复核验或通知 |
| 对核验属实的风险执行“通知上级” | 通知正确的上级，不新增按区域、风险类型选职责单位的步骤 |
| 在飞行计划“全部风险事件”的“通知与回执”页签查看 | 这里只看通知及回复，不再出现核验、改判操作；核验在风险详情办理 |
| 分别制造发送失败、等待结果、已送达、超时的情况 | 分别显示真实状态；点完发送不能立刻当作已通知成功；结果未知时先核对 |
| 上级签收后让风险继续存在，再提供有效解除依据 | 签收不解除风险；有实际解除依据后才更新当前风险，旧通知保留 |
| 查看过了有效时间的气象风险，以及缺少新依据的其他风险 | 按实际依据处理；无法确认的说明待确认，不能一律当作已经解除 |

### 7 告警事件

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 找到本次模拟产生的新告警，打开详情 | 无人机、事件、研判对应；需要人工核实的显示待核实；查看本身不办业务 |
| 有权限的值班人员把告警核实为属实，再刷新 | 显示“告警已确认”，记录谁处理的；后续通知按飞手和渠道条件办理 |
| 将另一条待核实告警判为误报 | 留下处理原因和历史；不会继续发短信、打电话或发起反制 |
| 组合筛选、翻页，在“告警与处置”和“反制办理”间切换 | 列表和数量正确；顶部统计卡大小保持一致 |
| 查看现有告警和旧的人工现场记录 | 不再有“现场情况”“人工补充现场情况”写入口；旧记录可看但不能替代当前依据 |
| 快速切换两条名称相似的告警 | 不把前一条的通知、视频、授权、急停状态显示到后一条 |
| 两个人同时核实，或一人快速重复点击提交 | 不重复处理，不无声覆盖别人的结果；需要时提示重新读取 |
| 无核实权限或缺关键依据时尝试处理 | 有清楚的阻止原因；能进页面不等于能做所有操作 |
| 打开告警及反制详情的视频，收起后再展开 | 默认展开，支持收起；没接入、没权限、读取失败分别说明；看视频不触发反制 |

### 8 飞手短信和电话

先确认短信观察时长。下面所说的“观察结束”，以系统保存的开始和结束时间为准；如需精确到秒，请开发协助核对。

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 已核验飞手、短信电话都可用，让无人机持续留在告警区域，再核实属实 | 先短信，观察，再电话，再观察；仍没离开才到待反制。不能少等、乱跳步骤 |
| 没有已核验执行飞手时核实属实 | 直接到待反制，不给未核验的人发短信打电话 |
| 短信渠道不可用时核实属实 | 按既定流程到待反制，不假装短信已送达 |
| 短信可用、电话不可用，无人机还在区域内 | 先发短信并完成观察，再到待反制；不能直接跳过观察 |
| 短信送达后让无人机真正飞离，继续上报位置 | 有位置证明离开后，不再升级电话或待反制；原告警确认记录仍保留 |
| 一条始终不核实，另一条判为误报，多次打开页面 | 两条都不发短信或电话；打开、刷新页面不触发通知 |
| 短信送达后停止无人机位置上报，但设备还在线 | 不当作飞走，也不继续自动打电话；即使显示待反制，缺少有效位置仍不能实际反制 |
| 电话播放完成后让无人机飞离 | 第二次观察根据实际位置判断离开，保留电话通知记录 |
| 短信只发出但没确认送达，或电话没接通、没播放完 | 不把这些状态当成已通知完成；不错误启动下一段观察 |
| 请开发重复发送同一条通知回复，或把短信、电话回复顺序打乱 | 不重复发送，不混用两个渠道结果，旧回复不覆盖新事实 |
| 用别的事件或上一次模拟的回复干扰本次事件 | 本次告警不被推进，本次无人机不因此触发撤离 |
| 已有送达记录后关闭渠道，或让当前位置过期 | 当时已经送达的事实仍保留，不能改成“从未发送” |
| 通知开始后关闭前台和收件箱，过一段时间再打开 | 已启用的后台流程能继续按条件处理，不依赖人守着页面 |
| 通知处理中断网或重启测试服务，再恢复 | 先核对原任务，不盲目重复发送；未知结果如实显示 |

### 9 反制申请 审批 执行和急停

“待反制”表示需要考虑后续处理，不表示任何人现在都能执行。位置有效、违规依据充分、权限和设备允许等条件仍然要满足。

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 普通申请人对符合条件的告警选择设备并提交反制申请 | 进入审批流程，申请人和对象正确；审批前不能执行 |
| 用另一有权账号分别批准和驳回，再尝试由申请人审批自己的申请 | 按现有审批约束处理；不允许的自批被拦；驳回不能继续执行 |
| 用执行账号执行已批准且有效的任务 | 收到命令、开始执行、执行完成分别显示；只有设备结果才能证明实际执行情况 |
| 对已经过期、撤销、驳回的授权执行，包括停留在旧页面再点 | 都重新检查当前状态，不因旧按钮还在就发命令 |
| 用明确有直接反制权限的账号操作符合条件的事件 | 可以免逐次审批；记下真实发起人，不捏造审批人 |
| 用普通申请、审批、执行账号，以及没有单独授予直接权限的管理员尝试直接反制 | 不能把这些身份自动当成直接反制许可 |
| 有直接权限，但对象、区域、设备不在允许范围，或已经过期 | 仍然阻止操作，不能超范围执行 |
| 分别使用过期位置、未知或合法结论、证据不足、另一事件的研判 | 申请、直接发起、实际执行都要挡住；不能拿旧现场记录凑依据 |
| 命令排队时撤权，或让授权、位置过期 | 真正发命令之前再检查，不把失效的任务继续下发 |
| 任务需要继续执行时，让原授权到期或撤销资格 | 后续命令仍重新检查，不能超出原来允许的时间 |
| 设备忙、离线、故障时操作，再试重复点击和两个人同时提交 | 说明失败或冲突；不重复下发；不能改走“人工填写执行成功” |
| 设备已经收到命令，但回复迟迟不到，过后再补回结果 | 超时不能证明设备没执行；不要盲目重发；后到结果对应原任务 |
| 执行中点击急停 | 停止按钮容易找到；急停请求、设备回复、实际停机核查分别看，不能一点就当已停机 |
| 未开始执行时撤销；急停后刷新或重新打开任务 | 撤销与急停分清；刷新不自动恢复执行或授权 |
| 急停失败、结果不明、重复急停或设备回复顺序错乱 | 不能显示成已经安全停机；不串任务，继续清楚提示实际状况 |
| 准备超过一页的待办，进入“待我处理”，再看“全部记录” | 待办不漏页；读取失败不能说没待办；当前事件和历史记录区分正确 |
| 查看以前的人工执行记录 | 只读保留，不重新进入可审批、可执行队列，不提供人工登记成功或失败 |
| 请开发配合，让批准、撤销、执行同时发生，并模拟短时服务中断 | 只接受当时合法的操作，不重复发命令；办理历史与实际结果一致 |

### 10 移送与处罚

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 打开本次事件的移送记录，核对目标、材料和来源 | 是同一件事，不把反制申请审批放回这里办理 |
| 分别检查自动移送开启、未开启、执行失败的情况 | 按真实情况显示；只读打开或刷新页面不会偷偷发起移送 |
| 查看待发送、等送达确认、已送达、发送失败的记录 | 四种情况分清，保留每次发送记录，不能把未知写成成功 |
| 查看未进入签收、等签收、已签收、签收超时 | 签收与送达分开；已送达不等于已签收，已签收不等于处罚完成 |
| 对允许补发的未发送或明确失败记录操作，再对结果未知的记录尝试重发 | 只允许当前合法操作；结果未知先核对，不反复发送 |
| 请开发模拟重复、迟到或发错事件的送达签收回复 | 不重复处理，不串事件，历史事实不被随便覆盖 |
| 查看已有正式办理结果和还没有决定的记录 | 没有决定不编出处罚结果；收到材料不自动结案 |
| 已固定保存的材料之后又增加新证据，或改变当前配置 | 原材料内容保留，新资料另行关联；直接反制记录写真实发起人 |
| 用范围受限或无办理权限的账号看详情、下载材料、尝试发送 | 查看、下载、处理都受权限限制，不能越权 |

### 11 证据和视频

| 怎么测 | 怎样才算正常 |
| --- | --- |

| 同一事件有多个同名文件，从业务页点击查看证据详情 | 精确打开刚才那个文件，不能换成第一个或最新的文件 |
| 同一目标有多条轨迹，从业务页跳到轨迹证据 | 打开正确的那一条，不能把轨迹编号当成文件编号找错内容 |

| 用无权限账号，或退出后再打开原文件链接 | 不能因为知道地址就下载或预览 |

| 视频加载时快速切换目标，或离开告警、研判、反制页面 | 旧画面停止，不把上一目标画面放到下一目标上 |
| 查看长文件名、大图片、冻结记录，连续开关预览 | 内容不被裁掉，页面不越来越卡，历史资料不被改变 |

### 12 运行统计

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 用本次能对得上的目标、立案和处罚结果核对数字 | 新目标按首次发现计数，不因重复上报重复算；立案按立案时间，处罚只算有效结果 |

| 查看很长的分类名称、空图表和全零图表 | 看得全、分得清，不靠省略文字掩盖重要内容 |

### 14 信号模拟器和前台一起测

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 启动一批独立测试信号，依次找发送记录、平台目标、前台展示 | 一步步对得上；模拟器显示“发送成功”还不等于平台已产生目标、研判或告警 |
| 分别模拟正常飞行、偏航、无计划、进入限飞区、鸟群、设备故障 | 各类结果由实际判断产生；鸟群不进入无人机合法性页；设备故障不冒充无人机违规 |
| 在模拟器和前台同时看同一设备、无人机、航线和区域 | 实际位置一致，不能用示意坐标代替；高度含义不明时不擅自换算 |
| 分别选择短信后撤离、电话后撤离、继续飞行、短信后停止上报 | 只响应本次目标的通知；撤离过程中继续发送真实模拟位置；停报不算飞离 |
| 打开短信、电话、风险、处罚收件箱，刷新和翻页 | 只查看既有记录；不能因此发送、拨号或签收；未送达或未知不能算已经收到 |
| 输入一份计划或天气资料，再重复提交相同的一次消息 | 前台资料正确，不因为重复提交而多出一份业务事实；不改旧历史 |
| 运行中暂停、停止，或让登录失效、重启模拟器 | 如实停止或显示失效；重启不自行续发；旧批次保留，前台不假装仍有新位置 |

关闭模拟器网页不一定会停止正在运行的模拟任务。结束测试时，要在工具里明确停止，并核对已经停止发送。

### 15 需要开发配合的异常测试

这些情况普通点击不容易稳定制造。测试人员负责记录页面表现，开发人员协助制造条件和核对实际处理结果。

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 分别让登录失效、权限不足、记录不存在、服务出错、请求超时 | 提示对应真实原因，不全部显示“暂无数据”，不不停重试 |
| 操作已经到系统，但页面没收到回复，再恢复网络 | 先查询原结果，不重复核实、通知、申请或下发 |
| 先查甲记录再查乙记录，让甲的结果更晚返回 | 最后仍显示乙，不被甲覆盖；离开页面后旧结果不回来乱改 |
| 两个人同时核实、批准、撤销同一件事 | 有冲突提示，重新读取当前状态，不无声覆盖别人 |
| 隐藏标签页后恢复，断网后恢复，观察自动刷新 | 不积压大量请求，不重叠刷新；能重新显示当前数据 |
| 用有代表性的数据量检查首次打开、筛选、详情和地图的速度 | 记录真实等待时间；先确定可接受标准，不能为了快而漏掉列表和待办 |
| 输入长文本、特殊符号和类似网页代码的测试文字 | 当普通文字显示，不执行代码、不破坏页面；不合法输入清楚提示 |
| 准备不同单位、不同来源但同名的数据，再换账号查询 | 不混数据，不越权；模拟、回放和真实来源分清 |
| 当前业务继续变化，回头查看已固定保存的历史材料 | 过去事实保持原样，新情况另有记录，不能事后补出假的审批或回复 |

速度可先按“主要页面3秒内、筛选和详情2秒内”作为讨论目标，但这不是已经确认的验收承诺。测试时记录电脑、网络、数据量和实际耗时；同一操作多测几次，不能只报最快的一次。

### 16 规则设置改变后前台会怎样

这里检查规则对前台的影响，不需要重新测完后台所有配置功能。涉及自动反制的项目，先确认本轮确实允许测试该模式。

| 怎么测 | 怎样才算正常 |
| --- | --- |
| 自动执行没有开启，只保存或启用一条规则配置 | 不能把“规则存好了”当成自动动作已经开启；人工操作仍按原权限和条件办理 |
| 自动服务正在启动、运行异常，之后恢复 | 不假装已经成功执行；恢复后不重复办同一件事 |
| 在已确认允许的自动模式下，分别准备条件全满足、不满足、未知、持续时间不够 | 只有符合已批准条件时才推进；不知道不能当作满足 |
| 自动反制条件表面满足，但账号、设备、位置、证据或急停条件不允许 | 仍须阻止动作，不能用“规则通过了”代替反制资格 |
| 动作排队后，规则、授权或允许时段发生变化 | 真正发送和继续执行之前再次检查，不能照旧结果继续办 |
| 某类规则没有启用，或已经暂停，再尝试有权限的人工操作 | 自动部分按设置暂停；人工入口不被错误隐藏，也不能因此绕过权限 |

## 六 这几种情况最容易误判

| 页面上看到的情况 | 正确理解 |
| --- | --- |
| 点了发送，出现提交成功 | 说明系统接到了这次操作，还要继续看实际发送和送达结果 |
| 短信已送达、电话已播放 | 说明通知到了，还要看无人机的新位置，才能判断有没有离开 |
| 无人机不再上报位置 | 可能失联或数据中断，不能直接认定飞走 |
| 显示待反制 | 仍要检查权限、有效位置、违规依据和设备条件 |
| 反制审批通过或直接授权成功 | 获得了相应授权，不代表设备已经执行 |
| 急停请求已提交 | 还要看设备回复和实际停机核查 |
| 上级已收到、处罚部门已签收 | 说明交接到了相应阶段，不代表风险解除或处罚办结 |
| 文件完整性检查通过 | 文件内容没有出现相应的完整性问题，不代表内容所描述的事实一定真实 |
| 页面显示0 | 只有确实为零时才正确；没有读到数据应写未知或失败 |

## 七 发现问题怎么记录

每个实际测试情况单独记一条。比如短信可用、短信不可用是两种情况，应分别记录。

| 记录什么 | 怎么写 |
| --- | --- |
| 测试日期和测试人 | 谁在什么时候测的 |
| 测的是哪一项 | 例如“短信送达后无人机停止上报位置” |
| 用了什么账号和数据 | 账号权限、这次模拟编号、无人机或告警编号；不要写密码 |
| 怎么操作的 | 按1、2、3写出别人能重复的步骤 |
| 应该看到什么 | 按本文件对应要求写 |
| 实际看到了什么 | 如实写页面状态和实际结果，不只写“不正常” |
| 结果 | 通过、有问题、暂时测不了、还没测；确定不在范围内的另写理由 |
| 证据 | 截图、短视频、操作时间；必要时由开发补充处理和设备记录 |
| 修好后再测 | 哪个版本修的，再测结果如何，有没有影响其他步骤 |

例如：“10:20短信已送达，随后停止无人机位置上报。10:21页面显示‘已飞离’，但没有新的位置依据。应显示无法确认离开，不能直接判定飞离。附告警编号、通知时间和截图。”这比只写“告警流程有问题”更容易定位。

记录“暂时测不了”时，写清楚差什么：没有合适账号、设备没接入、模拟通知没开、时长还没确认等。这些都不能当成通过。

## 八 测到什么程度可以说通过

必须先满足以下要求：

1. 登录、主要页面和日常处理流程能正常使用。
2. 普通申请审批、直接反制、执行、急停等本轮需要交付的关键流程，都有完整结果，不能有还没测或测不了的关键环节。
3. 无越权查看、下载或操作；无错误反制、重复下发、急停假成功；无跨事件串数据。
4. 通知、位置、授权、执行、移送、处罚分别显示真实状态，没有把未知显示成成功。
5. 当前数据和历史材料正确，列表、地图、详情、统计和导出能对得上。
6. 常用屏幕和浏览器里能看清、能操作；修复过的问题重新测过。
7. 剩余问题逐条列出。影响主流程、权限、反制或历史事实的问题必须先处理；轻微问题由业务负责人明确接受后再安排修复。

测试报告要分别写“通过多少、有问题多少、暂时测不了多少、还没测多少”。不要只写一句“基本正常”。真实设备或真实通知如果在交付范围内，要补真实验证，不能用模拟测试替代。

结束时停止本轮模拟、核对测试设备已停止、恢复临时调整的网络和测试配置。保存测试记录，不为清理页面而删除原有业务历史或已固定的材料。
