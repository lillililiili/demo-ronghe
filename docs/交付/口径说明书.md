# 口径说明书：界面上"说不了"的三种提示

> 面向验收。本文解释系统在**数据不足时**给出的三类提示分别代表什么、在什么条件下出现、为什么它们不是缺陷，以及各自在什么条件满足后会消失。
>
> 内部依据见 `docs/交付/内部依据/`。

## 一句话原则

**数据不足时说判不了，不编结论。**

这套系统在很多地方宁可显示"尚未接入""不可判定""暂不可用"，也不显示一个看起来完整、实则猜出来的数字或结论。原因很直接：这些内容会进入告警处置、合法性研判、处置授权和行政处罚的记录，一个编出来的结论事后没有人能解释它从哪来。**因此，看到这三类提示时，应当理解为"系统如实说明它现在拿不到这项事实"，而不是"这里坏了"。**

三类提示的区别：

| 说法 | 含义 | 谁来消除 |
| --- | --- | --- |
| **尚未接入** | 这项能力的外部来源还没有对接进来（设备、外部系统、上级渠道）。说的是**系统当前的状态** | 对接方：设备厂商、外部系统、上级单位 |
| **不可判定** | 来源接进来了，但这一条的输入不足以得出结论 | 数据本身：补齐计划、航线、时间等输入后自然变化 |
| **暂不可用 / 校验异常** | 这一段内容当前取不到，或取到了但校验没通过 | 视具体情况，见第三节 |
| **待确认** | **我们不知道，需要客户或厂家给答案。** 说的是**这件事还没有结论**，不是系统的状态 | 客户或设备厂家：给出答复之后我们才能落实 |

**"尚未接入"与"待确认"最容易被混为一谈，但责任方不同**：前者是"对方的东西还没接进来，接进来就好"；后者是"连该怎么做都还没定，得先有人给答复"。交付材料里凡是写"待确认"的地方，都同时写明了要问谁——看到它请当成一个**待回答的问题**，而不是一条待开发的功能。

---

## 一、"尚未接入"

**全仓出现 29 处，其中 21 处会出现在界面上，8 处是源码注释。** 界面上的 21 处对应下面 8 类情形——同一句话在不同页面各写一次，用户实际遇到的是这 8 种。

### 1. 融合感知页：实时视频、通知机场/周边

目标卡片上的这两个按钮是**灰的、点不动的**，标注"未接入"。

- **什么情况下出现**：始终如此。
- **代表什么**：视频流与机场/周边通知都需要外部系统提供通道，本平台尚未与之对接。
- **为什么不是缺陷**：按钮保留是为了让验收方看到完整的处置动线；但**能点的按钮必须真的能用**，所以在通道接入前一律禁用，不做"点了弹一个假成功"的假象。
- **什么条件满足后消失**：视频平台与机场/周边通报渠道确定接口并完成对接后。

### 2. 告警事件页：反制 / 信号干扰的处置状态、合法性一栏

- 告警卡片的"合法性"显示"尚未接入"；
- 顶部若干统计数字在读不到处置授权服务时显示"尚未接入"；
- 页面底部注明"实时视频 / 轨迹回放 / 通知处罚"未接入、按钮保留但禁用。

**这里有一处必须分清的差别**：同一个位置有三种不同说法，含义完全不同，不可混为一谈——

| 显示 | 含义 |
| --- | --- |
| **尚无授权** | 服务是通的，这个事件确实还没有人申请过处置 |
| **尚未接入** | 服务本身没接进来，系统不知道有没有授权 |
| **读取失败** | 服务接进来了，这一次没读到 |

把中间那种显示成"尚无授权"，会让人以为"确认过、没有授权"，从而错过一次本该有的处置。这三种分开，是有意的。

### 3. 合法性研判页：起降点、飞手/单位、可信输入几何、转入处置

- "起降点""飞手 / 单位"两栏显示"尚未接入"；
- 地图区域显示"可信输入几何尚未接入，地图不可绘制"；
- "转入处置"按钮禁用，标注"尚未接入"。
- 研判理由里可能出现"起降点尚未接入""飞手/单位尚未接入"。

**代表什么**：起降点与飞手/单位属于飞行计划的申报信息，需要由外部飞行管理系统提供；平台自身的观测数据里没有这两项事实。地图不绘制是同一个原因——没有可信的航线几何就不画一条看起来精确的线。

**什么条件满足后消失**：外部飞行计划系统提供这两项字段之后。

### 4. 飞行监管页：审批信息、飞行计划导出

- "审批信息"区块显示"尚未接入审批事实读取"；
- "导出"按钮在飞行计划页禁用，说明只提供告警与风险两类导出。

### 5. 处置与处罚页：外部处罚系统与文书报送渠道

案件页注明：**案件只在本平台内流转，外部处罚系统与文书报送渠道尚未接入。**

**代表什么**：立案、裁量、决定书、复核都在平台内完成并留痕，但决定书不会自动报送到外部处罚系统，也不会自动送达。**这一点在验收时需要特别确认**：平台内的记录是完整的，对外的那一步是人工的。

### 6. 空间安全风险：驱鸟处置

"驱鸟处置"按钮禁用；点击相关入口会提示"驱鸟处置尚未接入：设备指令与作业参数待设备方确认"。

**为什么不是缺陷**：驱鸟设备的指令格式与作业参数尚未由设备方确认，在确认之前下发任何指令都是猜的。

### 7. 我的工作台：联动反制与信号干扰、设备重启与恢复校验

- "联动反制与信号干扰尚未接入：属实后停留在'已核实，待处置'"；
- "设备重启、恢复校验与关闭命令尚未接入工作台；只读展示。"

**代表什么**：工作台负责把事情推到下一步，但反制/干扰的实际下发与设备重启的下发不在工作台完成，需要到对应页面操作或由设备方对接。

### 8. 处置授权服务、处罚案件服务整体不可用

页面显示"处置授权服务尚未接入""处罚案件服务尚未接入"，相关提交入口不可用。

**什么情况下出现**：这两个服务的接口整体取不到时（部署未包含、或服务未启动）。**正常部署下不应出现**；若验收现场看到，属于部署问题而不是功能缺失，应检查服务是否启动。

## 二、"不可判定"

**全仓出现 13 处，其中 1 处是样式注释。其余不是 12 条不同的提示，而是同一个词在不同页面的用词表里各定义一次**——用户在屏幕上看到的始终是同一个说法。

### 它出现在哪

| 位置 | 这一栏在说什么 |
| --- | --- |
| 合法性研判页 · 研判结论 | 引擎无法判定这次飞行是否合法 |
| 合法性研判页 · 单条规则结果 | 这条规则的输入不足，判不了 |
| 合法性研判页 / 飞行监管页 · 计划匹配 | 无法确定这架飞行器对应哪份计划 |
| 合法性研判页 · 高度关系 | 无法确定实际高度与计划高度带的关系 |
| 飞行监管页 · 计划时间 | 计划的开始或结束时间缺失时，时间关系判不了 |
| 设备接入调测页 · 调测结论 | 这项检查在当前条件下得不出通过或失败的结论 |

### 代表什么

**"不可判定"是引擎判不了，不是"等人来确认"。** 两者的区别在验收时很重要：

- 判不了 → 需要补输入（计划、航线几何、时间、设备回报）；
- 等人确认 → 需要有人去点一下。

系统在这两种情况下用的是不同的说法，不会把前者显示成后者。

### 合法性研判页上那个"系统待确认"页签

同一批记录，**页签名叫"系统待确认"，而每条记录的结论栏写的是"不可判定"**。这两个词指的是同一件事的两面，不是前后矛盾：

- **"不可判定"说的是引擎的输出**——它按现有输入得不出结论；
- **"系统待确认"说的是这批记录的去向**——正因为引擎判不了，所以要进人工队列由人来定。

换句话说：引擎判不了（不可判定）→ 所以转人工（系统待确认）。**这里的"待确认"是"等人来看这一条"，与上文术语表里那个"待确认"（等客户或厂家给答案）不是同一件事**，后者出现在交付材料里、不出现在页面上。

### 什么条件满足后消失

对应的输入补齐后，同一条记录重新研判即可得出结论——**不需要改代码**。例如：飞行计划补上起止时间后，时间关系不再是"不可判定"；航线几何提供后，计划匹配可以判定。

## 三、"暂不可用"与"校验异常"

这一类来自接口返回的**可用性标记**：接口不是简单地把内容省略，而是明确说明这一段为什么没有内容。前端把它翻译成中文显示。

### 界面显示与含义

| 界面显示 | 含义 | 是不是缺陷 |
| --- | --- | --- |
| **无权限查看** | 当前账号没有查看这一段的权限 | 不是。按角色授权，属于正常 |
| **尚无引擎研判** | 这条记录还没有被研判过 | 不是。研判后自然出现 |
| **暂不可用** | 这一段当前取不到 | 需要看现场情况，见下 |
| **校验异常** | 这份证据文件的完整性校验没有通过 | **需要关注**，见下 |
| **设备急停不可用** | 授权已撤销，但设备侧的急停协议没有提供这个动作 | 不是。协议限制，已如实记录 |

### 两处需要特别说明

**"校验异常"要当回事。** 它表示这份证据文件的校验没通过——可能是文件被替换、损坏，或存储介质有问题。证据链区块会把这样的记录数量单独标出来（例如"证据链（8 项 · 1 份校验异常）"）。**验收时若看到这个标记，应当追查那一份文件，而不是当成显示问题。**

**"设备急停不可用"不是失败。** 处置授权被撤销时，系统会尝试让设备急停；如果该设备的协议里根本没有急停动作，系统记录"授权已撤销；设备急停未执行（协议未提供）"，而不是记成"停止失败"。区别在于：前者说明协议没有这个能力，后者会让人以为设备抗命。

### 这一类提示的来源

这些说法不是页面自己编的，而是接口明确告知"这一段为什么没有内容"之后，由页面译成中文显示。换句话说：**页面不会在拿不到内容时自行猜一个说法**，每一句都有服务端给出的明确理由与之对应。

---

## 验收时的建议做法

1. **先分清三类**：看到提示先判断属于哪一类——外部还没接（尚未接入）、输入不够（不可判定）、这一段取不到（暂不可用）。三类的责任方不同。
2. **"尚无授权 / 尚未接入 / 读取失败"三种说法要分开看**，它们不是同义词。
3. **"校验异常"单独追查**，这一项与其他提示性质不同。
4. **禁用的按钮不是没做完的界面**：它们标注了禁用原因，且一律不做"点了给个假成功"的处理。
