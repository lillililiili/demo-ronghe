# E2E 骨架（阶段 15.3）

Playwright，只钉一件事：**每个页面对每个角色进不进得去**（决策 15-10）。
不做业务流程——业务流程有后端用例守着，这一层要接住的是"权限矩阵改了、页面注册漏了、
路由别名挪了位"这类接缝问题，它们在单测里全都看不见。

## 跑之前需要什么

| 依赖 | 说明 |
| --- | --- |
| 后端 | `http://127.0.0.1:8081`，`local` profile，`app.dev-seed.enabled=true`（要有 `admin1` / `reviewer1`） |
| 前端 | `http://localhost:5174`。**已经跑着就直接复用**（`reuseExistingServer`），不会被杀掉重启——同一台机器上可能有别的会话在用 |
| 浏览器 | `node node_modules/playwright/cli.js install chromium` |

用 `localhost` 而不是 `127.0.0.1`：Vite 只监听 IPv6（`[::1]:5174`）。

## 跑

```bash
npm run e2e
```

改端口或后端地址：`E2E_PORT`、`E2E_BASE_URL`、`APP_API_PROXY_TARGET`。

## 口令

来自环境变量 `E2E_PASSWORD`，缺省 `changeme`，与 `app.dev-seed.password` 同源。
**只适用于开了 dev-seed 的本地/CI 环境**，别拿这套去连任何真实环境。

## 矩阵是怎么来的

- **页面清单** 直接 `import` `src/config/navModel.js`。清单是事实：新增一页而忘了加用例，
  矩阵会自己长出来。
- **别名与重定向策略**（`#/risk` → 飞行计划、`#/airspace` 由飞行计划的权限承载）在
  `e2e/support/matrix.js` 里**另写一份**，不 import `services/accessControl.js`。
  别名是策略主张不是事实：照抄产品代码的话，谁把它挪了位，测试跟着一起挪、照样全绿。
- **可达与否的期望取自服务端** `/auth/me` 的 `menu_keys`，不在用例里再抄一份角色矩阵。
  要验的正是"前端的判断与后端的授权是否一致"。

## 每条用例断言什么

1. 应可达 → 没有拒绝页，**且**真渲染出了内容（只看"没有拒绝页"，白屏也会绿）。
2. 应不可达 → 出现拒绝页，且标题里是**中文页名**而不是英文路由键（决策 12-14）。
3. 应用级 `console.error` 与未捕获异常为零。
4. 4xx/5xx 响应按 `EXPECTED_FAILED_RESPONSES` **逐条对账**，清单外的一律红。
5. 1280 / 1366 / 1440 三档视口下没有横向滚动。

## 两条反空转自检

全绿不等于跑过。所以另有两条：本账号至少有一个可达页；**整张矩阵里至少有一个"应被拦下"的组合**。
没有后一条的话，演示种子哪天把 `ROLE-DEMO-REVIEWER` 授成全菜单，36 条会全绿，
而"拦得住"那一半一次都没执行。

## 失败响应清单不是豁免

`e2e/support/session.js` 的 `EXPECTED_FAILED_RESPONSES` 逐条列出"这个角色已知会被拒的请求"，
每条都写了理由。**不要用宽泛正则整类放行**：一旦放行，以后任何"页面发了它这个角色发不出的请求"
都再也看不见了，而那正是把动作权限接进角色矩阵时最容易出的问题。
清单里现有的几条都标着"已报领导的观察项"，是待办不是永久豁免。
