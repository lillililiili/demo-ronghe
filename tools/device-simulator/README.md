# 设备信息 MQTT 模拟器

## 飞行计划申报资料（2026-09-28）

“资料输入 → 飞行计划输入”现在可以填写申报单位、飞手、起降点名称及 WGS-84 经纬度，并选择已有单位/飞手档案、来源报送单位关联。表单与展开的 JSON 报文同步；新样本默认使用“数据模拟器（飞行计划）”专属 mock 来源，首次提交由后端登记。

已有计划可从“已有模拟计划”或接收记录点击“读取并补录资料/补录计划资料”，读取当前版本后保存。补录保留原时间、状态、无人机 SN、航线和原上传记录；版本冲突需重新读取。缺失资料不自动编造，没有档案时填写申报名称后仍显示待关联；档案继续在后台用户管理左侧单位机构维护。

新增代理白名单仅开放 `/local-interface-simulator/plan-options`（GET）和 `/local-interface-simulator/plans/{id}/filing`（GET/POST）。服务端限制模拟/回放计划，并复用单位管理权限及飞手归属、角色和有效性校验，资料和关联一起回滚或成功。本次改动仅覆盖资料输入入口；地图 MQTT 场景的既有批次配套数据不自动回填。

验证命令：`node --test tests/test_plan_form.cjs tests/test_external_ui.cjs tests/test_external_session.cjs`，以及 `python -m unittest discover -s tests -p test_external.py`（在本目录执行）。

根据地图页面设计实现的独立本机工具。通过现有后端注册模拟设备，用 MQTT 向现有接入、融合与规则链路发送报文；不新建平台后端、不改业务前台路由、不直接填造告警。

## 启动

```sh
python3 tools/device-simulator/server.py --port 8766 --database houtaiguanli
```

打开 http://127.0.0.1:8766/ 。需 Python 3.9+、Node.js 及业务前台已有依赖；MQTT 使用现有 `paho-mqtt` 2.x，未新增项目生产依赖。启动时自动构建共享地图入口。

地图读取当前业务前台的同一配置、PMTiles 数据包、影像与配色。默认地图服务为 `http://localhost:5173`，需保持业务前台地图服务运行；端口变化时使用 `--map-origin http://localhost:实际端口`。地图资源仅经本机同源代理读取，保留 HTTP Range 206，不复制整份地图包；读取失败显示错误和重试入口。

启动终端需保持运行。若页面提示“模拟器服务未连接”，重新执行上述启动命令；页面会自动恢复状态读取。重启后在“登录系统”重新登录一次，历史批次保留且不会自动续发。提交操作时断连表示结果未知，先恢复连接并核对运行记录，再决定是否重新操作。

`--database` 显式启用本机测试库的计划、区域配套，默认容器 `deploy-db-1`（可用 `--container` 指定）。未传该参数仍可运行无需计划/区域的设备与目标场景。只接受回环 API 与已启用、source_mode=replay 的本机 MQTT 连接；不能用于现场/生产环境。

## 怎么操作

1. **连接设置**：填现有系统 API（本机为 `http://127.0.0.1:8081/api/v1`）、账号和密码。读取后台 `local-lingyun-replay`；如 broker 需要认证，另填 MQTT 用户名密码。凭据仅保存在进程内存，不写场景、日志或浏览器存储。计划/区域受控 seed 只允许测试系统管理员。
2. **地图编排**：地图上方分为“设备与目标”“航线与区域”“计划与气象输入”；左侧按任务显示对象，右侧编辑当前对象。风险列表默认收起，可通过“展开列表”配置。在系统真实地图上拖动、缩放，放置设备组（气象、5G-A、光电、TDOA、雷达），修改数量；绘制目标轨迹、计划航线与限飞区域。点击左侧对象定位并在右侧应用设置；“全览”回到当前场景范围。设备经纬度使用 WGS84，单台、追加、整组移动均保留。
3. **风险场景**：勾选本次实际发送的场景，指定目标、上报设备以及必要的计划/区域。取消勾选仅影响本次目标/异常发送，组内支持协议的设备仍上报正常心跳。
4. **启动 MQTT 模拟**：冻结场景快照，为新批次配套 replay 设备与资料，然后定速沿轨迹发送。运行 30 秒至 20 分钟后结束；暂停停止全部上报、继续沿原模拟进度运行；停止等待在途发布退出。关闭网页不停止 Python 进程内的运行任务。
5. **运行记录 → 回读系统结果**：分别查看 Broker PUBACK、后台设备事实、本批次目标、研判与告警。空结果不补成功，读取失败保留错误。源设备通过 `fusion_device_id` 对应目标 `source_links.device_id`。
6. **导出场景 / 导入场景 / 导出本批次**：场景可复用；批次导出包含设备/计划/区域映射、最近发送记录和系统回读。完整报文保存在本机 `.data/<batch>/events.ndjson`。

运行时锁定编辑器；停止后可以修改。保存场景仅保存编辑草稿，不会启动发送。未完成地图绘制时不能启动。

## 数据流与保护

- 设备注册：现有 `POST /api/v1/devices/onboard`，每次运行独立设备编号及幂等键，source_mode=replay。
- 雷达、5G-A、TDOA：复用 `LINGYUN_MQTT_V8_6` 工参和 SenseData 契约。QoS 1、retain=false；目标与批次身份固定，观测时间随实际发送更新，按速度和折线距离推进，终点停留，不循环瞬移。鸟群按数量生成独立观测编号、固定小范围编队偏移。
- 光电：`EO_EDGE_MQTT_20250826` HeartBeat。不会虚构跟踪任务、实时视频或控制执行回执。
- 离线：时间窗内停止该设备所有上报，恢复后正常上报；系统按自身超时阈值判离线。故障：协议 A workState=2，窗口结束后恢复原配置。
- 计划/区域：现有计划接口没有通用写入口，空域创建接口固定为 live。因此复用项目本机模拟脚本的受控 seed 做法，通过 PostgreSQL 事务仅新增 replay 航线、版本、计划及限飞区域。执行前以 broker UUID 核对 API 与数据库一致。完整场景快照在任何写入前落盘，不覆盖或删除旧记录。
- 计划、区域时段使用**运行当天 Asia/Shanghai**。普通场景遵守页面时间；“超出计划时段”按选择的提前/延后及分钟数，将该目标配套计划定位到本批次开始前后，实际生效时刻可从系统计划回读。
- 一条编辑航线可为不同无人机生成各自绑定序列号的计划；鸟群关联的计划用于航线风险，不伪造鸟群飞行计划匹配。
- 暂停可能使系统判设备离线，停止不代表风险解除。发送失败或 PUBACK 超时会停止任务，结果未知不自动重发。服务重启恢复上次批次记录，**不自动续发**。新运行使用新批次。
- 这不是平台规则引擎；不通过前端定时器生成系统告警、通知成功或反制成功。实际状态、合法性判定和告警均以系统回读为准。
- 2026-09-23：可视地图已替换为系统共用的真实底图，复用 `offlineMap.js`、`mapTheme.js` 与地图 tokens。旧 version=1 场景的内部 x/y 保留原 WGS84 换算，渲染时使用地图投影，因此原已发送位置不漂移；新选点不再受旧示意画布范围限制。重载已保存的草稿时，已完成批次不会覆盖草稿；运行中的批次仍显示其冻结快照。

## 当前协议边界

### 速度上报修正（2026-09-28）

- 目标报文现在携带 `objects[].speed`（米/秒），按当前轨迹段计算；雷达和 5G-A 同时携带 `extension.speedX/speedY/speedZ`（东、北、上）。当前轨迹为等高运动，Z 轴为 0；TDOA 不套用雷达的三轴扩展。
- 位置与速度共用 `target_motion()`：转弯改变方向，到终点、单点轨迹或设定速度为 0 时上报 0。通知触发撤离后使用撤离轨迹及撤离速度；停止目标上报时仍不发送目标报文。
- 修复仅影响加载新代码后的新报文，不回填已完成批次。服务需重启才加载 Python 修改，重启后重新登录，历史批次保留且不会自动续发。
- 设备上报、设备指令接收、外部接口输入与通知输出的完整核对见 [模拟器收发完整性梳理](../../docs/模拟器收发完整性梳理-2026-09-28.md)。清单区分已修复、待补能力及既有只读约定；不代表真实设备能力全部通过验收。

| 类型 / 场景 | 当前能力 |
| --- | --- |
| 雷达、5G-A、TDOA | 注册、心跳、工参、无人机/鸟类轨迹、离线与故障调度 |
| 光电 | 注册、心跳与离线；具体故障码与跟踪任务回执未接入，阻止伪造 |
| 气象设备 | 保留地图布设；现有系统没有相应设备 MQTT 契约，明确跳过发送；不伪造温度、风速字段 |
| 无计划、偏离、限飞区、时间风险 | 发送实际观测及配套资料，结果由现有引擎判断；选中场景不保证产生某个结论 |
| 超高 | 上报协议原始高度；当前后端将其基准视为未知，不能保证触发超高告警 |
| 气球 | 当前协议码表无气球分类；选中时阻止启动，不冒充鸟类或其他类别 |

## 文件与验证

- `engine.py`：冻结与校验场景、几何距离、运动插值、异常时间窗和 A/C 报文。
- `platform_client.py`：系统登录/回读、设备注册、本机配套事务。
- `server.py`：同源本地服务、任务线程、生命周期、日志、结果回读；仅绑定 127.0.0.1。
- `web/`：沿用确认的页面；`runtime.js` 接入实际运行、配置与导入导出。
- `map-entry.js` / `build-map.mjs`：共用系统地图加载器和主题，真实坐标投影、平移缩放及构建；`web/map-runtime/` 为自动生成资源，不提交。
- `tests/test_engine.py`：定速转弯、离线停报及恢复、故障恢复、数据校验、输入快照与不支持的协议阻断。

```sh

node --check tools/device-simulator/web/app.js
node --check tools/device-simulator/web/runtime.js
```

最初 MQTT 接入轮次未运行业务前台 build/scan/admin-migration；2026-09-23 地图替换轮次单独执行这些检查。真实现场设备、短信和电话通道未验收。

- 当天计划/区域有效时间为北京时间 00:00—23:59；停止发送不撤销资料或删除历史。每日新运行创建新批次，跨天需重新运行。

## 地图输入与通知收件箱（2026-09-24）

- 打开 `http://127.0.0.1:8766/`，地图上方“计划与气象输入”中切换飞行计划、气象预报，右侧展开系统输入表单。切换页签或收起右侧时保留当前页面内草稿，页面刷新后重新生成；不会自动提交。地图侧栏通过布局分栏避让，切换时重新适配场景范围。
- 输入表单使用系统已有航线版本和计划；地图仍为当前本地 MQTT 场景，不把系统选择的航线或预报区域伪画成本地场景。计划样本按航线有效期裁剪；气象样本按计划时段生成，历史时段保持历史，不冒充当前有效。编号、JSON 修改与幂等语义保持原实现。
- 顶部“通知收件箱”打开 `/external.html`，分飞手短信、飞手电话、风险通知、处罚通知。显示实际保存的模拟内容、接收对象和时间；正文完整换行，原始记录按需展开。“已收到”仅计入有明确送达或模拟播放完成记录的消息；其他发送状态单独显示，签收不替代送达。
- 风险与处罚直接从现有 `/handoffs`、详情及各次 `/deliveries` 读取，不再需要前端绑定事件。每页分别读取最多 20 条 mock 和 20 条 replay 事项，保留每次发送记录并支持翻页；前端数量仅对应当前页。
