# 现有 Sentinel-2 离线地图显示增强

`enhance-sentinel2-map.py` 从原始、无损、带地理参考的四波段 RGBA TIFF 制作独立新包。只增强亮度边缘和对比度，不增加真实分辨率，不使用生成式补画。原版的坐标、范围、道路、字体、图标和业务数据保持。

依赖与原制作工具相同：GDAL、NumPy、Pillow。原包必须通过完整 SHA-256 校验，输入栅格须匹配原包的投影、像元网格、范围和有效像元数；拒绝对已优化包重复锐化。

```powershell
python tools/enhance-sentinel2-map.py --base <原地图包目录> --source-rgba <原始true-color-rgba.tif> --work-dir <新的工作目录> --out <新的地图包目录>
```

更强的清晰增强从同一批原始 B04/B03/B02 重新投影，避免在上一版已模糊的图上反复锐化：

```powershell
python tools/enhance-sentinel2-map.py --profile clarity --base <原地图包目录> --source-rgba <原始true-color-rgba.tif> --source-work <原下载工作目录> --work-dir <新的工作目录> --out <新的地图包目录>
```

`--source-work` 必须包含原来的 `catalog.json`、`raw/` 和下载校验凭据；工具重新核验源文件 SHA-256，并确认与原地图包的来源清单完全相同。没有这些文件时不能运行 `clarity`。账号密钥不需要提供，也不进入地图包。

脚本必须与 `build-sentinel2-map.py`、`webp_checked_encoder.py` 放在同一目录。清晰增强编码依赖当前 Windows GDAL Python 环境中的 `Library/bin/libwebp.dll`，启动时检查编码 ABI；地图部署运行不需要这些制作依赖。所有参数均为本机路径，不需要联网或下载密钥。工作目录、输出目录及同名 ZIP 必须尚不存在。

默认 `mild` 保留轻度优化：亮度锐化核 `[1,4,6,4,1]/16`，强度 0.5、阈值 1.5、锐化限幅 ±8/255，对比度 1.04；读取两像素边缘，输出 WebP 质量 85。

`clarity` 改用 Float32 Lanczos 重投影，再对亮度应用多尺度增强：细节强度 1.3、阈值 0.6、细节限幅 ±24；四次平滑后的局部对比强度 0.45、限幅 ±10；组合锐化限幅 ±28，对比度 1.07。读取八像素边缘，分块与整图结果一致。RGB 共用亮度增量并按通道余量限幅，避免彩边；先处理地理栅格再切瓦片，避免处理块接缝。透明度严格沿用原版，重采样边界不足时使用原版有效像元。

两种配置都输出 512×512 WebP、XYZ Z0–Z13，原始影像仍为 10 米；增强的是已有地物的边缘和对比度，不新增真实空间细节。放大级别不代表新的影像分辨率。

清晰增强先制作全级无损瓦片。若无法满足 512 MiB 上传限制，保留无损中间文件，优先采用 Z13 近无损 60、Z0–12 质量 100；仍超限则依次尝试 Z13 近无损 40、全级质量 100。近无损 60/40 的可见 RGB 通道误差分别不得超过 2/255、4/255，每张解码验证，超限或透明度变化的瓦片回退真正无损。不会把近无损称为完全无损。逐张编码审计留在工作目录；实际选中的编码写入包内来源记录。最终 ZIP 仍须低于原限制，不提高后台大小或文件数限制。

输出版本追加 `-mild1` 或 `-clarity2`；完整处理参数、实际编码方式、输入栅格 SHA-256、原版透明度参考和统计写入 `sources/sentinel2-provenance.json`，文件校验和重新生成。脚本只制作包，不修改运行指针。

执行 `node tools/check-map-package.cjs <新地图包目录>` 后，在后台地图管理上传 ZIP 并启用。原包保留，支持“回滚上一版”。前台、大屏、后台和模拟器继续读取同一个运行指针，不新增公网请求。最终验收需对同一位置和缩放级别对比原版、优化版，并检查缩放、平移、缺测透明边界与回滚。
