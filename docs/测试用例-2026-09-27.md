> 编制日期：2026-09-27
> 关联文档：[测试计划-2026-09-27.md](测试计划-2026-09-27.md)
> 用例编号：`TC-<组>-<序号>`，组与测试计划 2.4/2.5/2.6 对应（A=MQTT 全流程闭环、B=合法性、C=风险通知、D=飞行计划、E=移送处罚/证据/统计、F=模拟器外部接口、H=后台规则管理、I=权限迁移、V=界面视觉、S=数据一致性）
> 优先级：P0=发布阻断（必须通过）、P1=重要（默认通过）、P2=一般

## 0. 公共执行说明

**环境（与测试计划 2.2 一致）**：后端 `127.0.0.1:8081`（local + dev-seed）、业务前台 `localhost:5173`、管理端 `127.0.0.1:5175`、模拟器 `127.0.0.1:8766`、MQTT `1883`。

**账号**：`admin1`（系统管理员/处置账号，密码默认 changeme）、`reviewer1`（审批账号）。各账号需按用例赋予对应权限，权限变更须在管理端「角色管理」完成后重新登录生效。

**模拟器启动与批次管理**：
```sh
python3 tools/device-simulator/server.py --port 8766 --database houtaiguanli
```
1. 打开 `http://127.0.0.1:8766/` → 「登录系统」填 API 地址/账号/密码；
2. 地图编排设备组（气象/5G-A/光电/TDOA/雷达）、目标轨迹、计划航线、限飞区域；
3. 勾选本次发送的风险场景（或「加载演示样本」五组场景）；
4. 「启动 MQTT 模拟」→ 记录批次号 `sim-YYYYMMDDHHMMSS-xxxx`；
5. 每次新运行创建新批次，旧批次保留为历史；停止后不自动续发。

**API/数据库核对方式**：需要回读接口或数据库时，使用登录后的 Bearer 会话调用 `/api/v1/...`，或用数据库客户端核对 `houtaiguanli` 库对应表；核对只读，不修改业务数据。

**通用断言（适用于所有用例）**：页面无 console error、无未捕获异常；切换对象/页签后无上一事件残留状态；所有模拟数据带明确模拟标识；读取失败显示真实错误且不回退 Mock。

## A. MQTT 信号模拟器全流程闭环（P0）

### TC-A1 禁飞区闯入全闭环（P0）

| 项 | 内容 |
| --- | --- |
| 前置条件 | 五组样本中的「禁飞区闯入」场景已加载；admin1 已登录模拟器与业务前台；通知通道 MOCK 配置有效 |
| 测试数据 | 4 台设备（无人机雷达、身份 TDOA、鸟群雷达、独立故障雷达）、3 条计划、1 个禁飞区；运行时长 ≥60 秒 |
| 操作步骤 | 1. 模拟器地图「设备与目标」确认设备组就位，勾选「禁飞区闯入」场景；<br>2. 点击「启动 MQTT 模拟」，记录批次号；<br>3. 运行 30~60 秒后打开融合感知 `#/situation`，确认目标出现（北京时间当天范围）；<br>4. 打开告警事件 `#/alarms`，确认告警生成；<br>5. 打开合法性研判 `#/legality`，确认该目标研判生成；<br>6. 模拟器「运行记录」页核对 Broker PUBACK、后端目标报文、研判、告警 |
| 预期结果 | 1. Broker PUBACK 计数持续增长且无失败/超时中断；<br>2. 融合感知出现目标，来源标识 replay/mock 明确；<br>3. 告警生成，初始状态「待核实」；<br>4. 研判生成，结论按规则引擎实际输出（不得人为改成"告警成功"）；<br>5. 设备、目标、研判、告警的关联 ID 与模拟器记录一致 |

### TC-A2 自动通知链（主路径）（P0）

| 项 | 内容 |
| --- | --- |
| 前置条件 | 存在已核实属实的告警；该告警关联**已核验执行飞手**；短信与电话 MOCK 通道均可用；目标持续在告警空域内 |
