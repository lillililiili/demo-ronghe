# 甲方验收用例

**给谁看**：参加验收的业务方与监理。照着做就能把平台的主要功能走一遍，并且知道每一步"应该看到什么"。

**怎么用**：每条用例都写了前置数据、操作步骤、预期结果，以及**数据不足或没有权限时应该显示什么**。最后一列的文字是屏幕上的原话，验收时逐字对照即可。看不懂某条为什么这么设计，可向实施方索取内部依据清单。

**内部依据见 `docs/交付/内部依据/甲方验收用例.md`。**

**验收时间与环境**：本文所有用例在 2026-09-09 的本地演示库上实际走过一遍。演示库里的业务编号（如"告警-0906-306"）会随重新播种而变化，**验收当天以页面上实际列出的第一条为准**，编号只是示例。

---

## 一、验收环境与两个账号

平台按"谁能看什么、谁能做什么"分角色。验收需要**两个账号**，因为处置授权和处罚复核都要求两个人参与。

| 账号 | 角色 | 能进的菜单 | 能做的关键动作 |
| --- | --- | --- | --- |
| admin1 | 超级管理员 | 全部十五项（含大屏） | 全部：核实告警、核验风险、申请处置、立案、拟定裁量、出决定书、结案、提交交接 |
| reviewer1 | 演示复核员 | 我的工作台、融合感知、飞行计划、告警事件、处置与处罚、设备实时监测 | **只**：批准/执行/停止处置授权、提交处罚复核结论；其余只读 |

两条硬规则（系统会拦，不是靠人自觉）：

- **处置授权：批准人不能是申请人。** admin1 申请、reviewer1 批准；同一个人两头做会被拒绝。
- **处罚案件：复核人不能是承办人。** 承办人拟定裁量后，必须换一个人提交复核结论。

> 验收提示：reviewer1 登录后，左侧菜单只有六项，**没有**"运行统计""证据管理""设备管理""设备接入调测""用户管理""角色管理""审计日志"。这不是漏做，是按角色收起来的。直接在地址里敲这些页面，会看到"无法访问『页面名』——如需访问，请联系系统管理员调整角色权限。"和一个"返回我的工作台"按钮。

## 二、A 组：三条业务闭环

会议纪要要求的三条闭环，全部从"我的工作台"进入。工作台把三类待办放在一起：顶部五个方块是"全部事项""高等级事项""无人机告警""飞行计划风险""设备告警"，点哪个就按哪类筛；方块下面还有一排按类切换的按钮。

每条事项卡片底部有一行"**下一步：xxx**"，直接告诉值班员该干什么；没有权限时按钮是灰的，旁边写明原因。

### A1 无人机事件闭环（告警 → 核实 → 处置 → 处罚）

**前置数据**：一条待核实的无人机事件，示例"告警-0906-306"，状态"待核实"。

| 步骤 | 操作 | 预期结果 | 数据不足/无权限时 |
| --- | --- | --- | --- |
| A1-1 | admin1 进"我的工作台"，点顶部"无人机告警" | 只剩无人机事件；每张卡片有编号、等级、状态、接收时间和"下一步" | 三类计数任何一类读不到，该类显示"无读取权限"或"设备归属映射未配置"，不显示 0 |
| A1-2 | 选中"告警-0906-306"，看右侧流程条 | 四步：告警接收（已完成）→ 人工核实（当前）→ 联动反制 → 通知处罚部门 | 反制那一步读不到授权时写"尚未接入"；没有授权时写"尚无授权"——两者不是一回事 |
| A1-3 | 点"人工核实"，选结论并提交 | 提示核实成功；状态变为"已核实，待处置"；核实历史多出一条 | reviewer1 做这一步：按钮是灰的，提示"当前账号只能查看，不能提交核实结论。" |
| A1-4 | 卡片"下一步"变成"联动反制"，点它 | 弹出申请窗，可选"联动反制"或"信号干扰"，填申请事由 | 处置服务读不到时，整块显示"处置授权服务尚未接入" |
| A1-5 | 提交申请 | 提示申请已提交、待审批；处置与处罚页的"处置授权"区出现这条，状态"待审批" | admin1 自己不能批自己的申请（见 A1-6） |
| A1-6 | **换 reviewer1 登录**，进"处置与处罚"，找到这条授权，点"审批" | 弹窗标题是"审批 · 授权编号"，默认结论"批准"，可填审批意见；提交后提示"审批完成：已批准"，该行原地变成"已批准"，按钮变成"执行""停止" | 按钮由服务端逐条下发：状态不允许或本人无权限时**根本不显示**，不会出现点了才报错的按钮 |
| A1-7 | reviewer1 点"执行" | 凌云协议设备走下发指令，等设备回执；人工执行的通道改为"登记执行结果" | 设备未登记连接时不会假装成功，显示执行受阻的原因 |
| A1-8 | 换回 admin1，在告警事件页选中该告警，点"提交处罚交接" | 选接收方后提交；处置与处罚页出现一条待投递的交接 | 提交成功只表示材料入库，**不等于对方已收到** |
| A1-9 | 进"处置与处罚"，对该交接点"立案" | 生成案件编号；状态"已立案" | 案件只在本平台内流转：外部处罚系统与文书报送渠道尚未接入 |
| A1-10 | 依次"指派承办人""拟定裁量""确认裁量" | 每步状态推进，页面显示当前裁量档次与依据 | 缺少档位数据时如实说读不到，不会拿别的档位顶替 |
| A1-11 | **换 reviewer1**，点"提交复核结论" | 复核意见入库，状态进入已复核 | 承办人本人提交会被拒——复核人不能是承办人 |
| A1-12 | 换回 admin1，点"生成决定书"，再"结案" | 决定书可"预览全文""复制全文"；结案后状态"已结案" | 文书报送渠道未接入，只能在平台内查看与复制 |

### A2 飞行风险闭环（发现 → 核验 → 通知上级）

**前置数据**：一条待核验或待通知的飞行风险，示例"风险-0907-209"，状态"待通知"。

| 步骤 | 操作 | 预期结果 | 数据不足/无权限时 |
| --- | --- | --- | --- |
| A2-1 | 工作台点"飞行计划风险"，选中一条 | 流程条三步：风险发现 → 人工核验 → 通知上级 | — |
| A2-2 | 点"人工核验"，提交结论 | 核验通过后状态进入"待通知"；**核验通过只表示已核验，不表示已通知上级** | reviewer1 做这一步按钮是灰的，提示"当前账号只能查看，不能提交核验结论。" |
| A2-3 | 点"通知上级" | 填写并提交交接材料 | 无交接权限时按钮灰显并写明原因 |
| A2-4 | 提交后回看该风险 | 风险仍显示"待通知"；提示明确写着：**提交成功只表示材料入库，不等于已发送或已送达** | 这是刻意的——平台没有对上级系统的真实投递通道 |
| A2-5 | 若核验结论是"已排除" | 流程条直接走到"已排除"，注明"核验后判定无需通报" | — |

### A3 设备异常闭环（发现 → 重启 → 回执 → 恢复校验）

**前置数据**：一条待处理的设备异常，示例"INC-0908-003"，设备"设备-0908-012 利津县反制02号"，状态"待处理"。

| 步骤 | 操作 | 预期结果 | 数据不足/无权限时 |
| --- | --- | --- | --- |
| A3-1 | 工作台点"设备告警"，选中一条 | 流程条四步：原因与确认 → 下发重启 → 等待回执 → 恢复校验与关闭 | 无监测操作权限时提示"当前账号只能查看，不能下发重启。" |
| A3-2 | 点"远程重启"，填写重启原因（必填） | 弹窗写明：提交后等待适配器回执；**模拟回执不代表真实设备已重启**；协议未声明重启能力或设备离线时会失败，异常保持待处理 | 设备离线或协议不支持时如实报失败，异常不会被"当成已处理" |
| A3-3 | 提交后观察 | 提示"重启指令已受理，等待回执"；流程条停在"等待回执" | 一直没有回执就停在这一步，不会自动跳到成功 |
| A3-4 | 收到回执后点"恢复校验" | 按当前设备状态快照校验；通过提示"恢复校验通过，异常已关闭" | 未通过时提示"恢复校验未通过，异常仍待验证"并给出原因，异常不关闭 |

页面清单取自会议纪要第十一节。登录、修改密码、低空安全监控大屏是三个独立入口，不计入业务页面。

## 四、C 组：数据不足、没有权限、读不到时应该看到什么

这一组是验收的重点。平台的原则是：**三种情况必须分开说，不能都写成 0 或"暂无"。**

| 情况 | 屏幕上的原话 | 在哪能看到 |
| --- | --- | --- |
| 功能还没接入 | "尚未接入" | 告警页与飞行计划页的指标、合法性页的起降点与飞手单位 |
| 服务读不到 | "处置授权服务尚未接入" / "处罚案件服务尚未接入" | 告警页处置指标、处置与处罚页 |
| 当前账号没有权限 | "无读取权限" | 工作台三类计数 |
| 设备归属没配 | "设备归属映射未配置" | 工作台设备异常计数 |
| 没有该页权限 | "无法访问『页面名』——如需访问，请联系系统管理员调整角色权限。" | 直接敲无权页面的地址 |
| 有权限但没有数据 | 空列表 | 各列表页 |
| 判不出来 | "不可判定" | 合法性结论、设备调测判据 |
| 字典读不到 | 下拉里只剩"不可用"，鼠标停上去说明原因 | 告警页与风险页的"区域"筛选 |
| 有授权但读不到 vs 没有授权 | "尚未接入" vs "尚无授权" | 工作台无人机事件流程条的反制环节 |

**验收建议**：用 reviewer1 把 A1、A2、A3 各走一遍，专门看灰按钮旁边写的原因是不是人话、是不是准确。

## 五、D 组：纪要要求但本期未接入

以下能力在会议纪要里提过，本期**没有**接入。页面保留了入口但禁用，并在按钮上写明原因——这是刻意的，避免让人以为点了就生效。

| 纪要要求 | 页面上的原话 | 位置 | 卡在哪 |
| --- | --- | --- | --- |
| 光电实时视频 | "实时视频（未接入）" | 融合感知页目标悬浮卡 | 视频通道与取证接口待设备方提供 |
| 通知机场/周边 | "通知机场/周边（未接入）" | 融合感知页目标悬浮卡 | 无对外通报通道 |
| 驱鸟处置 | "驱鸟处置（尚未接入）"，提示"设备指令与作业参数待设备方确认" | 空间安全风险详情 | 设备指令与作业参数未确认 |
| 合法性研判转处置 | "转入处置（尚未接入）" | 合法性研判页 | 待确认 |
| 起降点、飞手/单位 | "尚未接入" | 合法性研判页详情 | 外部管服平台身份数据未接入 |
| 计划审批事实 | "尚未接入审批事实读取。" | 飞行计划页详情 | 外部审批系统未接入 |
| 飞行计划导出 | "导出（尚未接入）" | 飞行计划页 | 目前只提供告警与风险两个导出 |
| 告警的实时视频、轨迹回放、通知处罚 | "「实时视频 / 轨迹回放 / 通知处罚」尚未接入，按钮保留但禁用。" | 告警事件页说明区 | 同上 |
| 外部处罚系统与文书报送 | "案件只在本平台内流转：外部处罚系统与文书报送渠道尚未接入" | 处置与处罚页 | 无对外报送通道 |
| 上级通报的真实投递 | "提交成功只表示材料入库，不等于已发送或已送达" | 风险通知上级 | 无对上级系统的投递通道 |
| 设备重启的真实回执 | "模拟回执不代表真实设备已重启" | 工作台设备异常 | 真实设备协议联调未完成 |

另有两处会议纪要与系统现状不一致，**请甲方确认口径**：

1. 纪要"最终决策摘要"第 9 条写"十个既定页面范围保持不变"，而第十一节列的是十四个业务页面。本文按第十一节的十四页组织。
2. 纪要要求的"公安局信号干扰联动：授权编号、联动单位、设备、作用范围、执行时长、启停和审计"，平台已有授权编号、设备、启停与审计，**"联动单位""作用范围""执行时长"三项是否已满足，待确认**。
