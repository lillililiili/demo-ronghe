# 自动研判与快速响应优化评估

> 2026-09-17 需求与实现补充：合法性判定的人工复核分流以[合法性自动判定 Spec](superpowers/specs/2026-09-17-legality-auto-decision-design.md)为准。算法能够可靠明确判为合法或非法时，右侧均不显示“核对信息缺口”；依据不足时才显示该人工复核功能。本轮已实现规则计算与证据充分性分流，统计准确率仍未验证；运行环境生效状态见[本轮交付记录](交付/合法性自动判定与复核分流-20260917.md)。下文 9 月 16 日按既有合法性状态安排人工入口的内容保留为历史实现记录。

> 2026-09-16 状态补充：本文主体是 9 月 15 日的源码评估和优化建议。此后融合感知已切换多域 API、接入同事件处置入口及自动短信状态，本地策略支持自动模拟短信；不能再把“首页仅有独立模拟目标”或“首次短信必须手动点击”作为当前整体结论。连续自动现场观察等未落地项仍保留为建议。当前边界见[劝离处置](backend-stage19/uav-advisory-workflow.md)、[业务流程](flow-map.md)及[对话文档核对](项目对话与文档核对-2026-09-16.md)。

评估基线：2026-09-15 工作区当前代码（含已有未提交改动）。本次为源码与文档分析，未运行设备、短信、业务写入或浏览器性能实测。本文中的模块编号仅用于分析，不是新增业务 ID。

**已确认的产品方向：无人机经过监测区域的时间可能很短，系统应持续自动研判、按条件自动推进，减少常规事件中的人工操作。** 自动判定不等于自动处罚，识别置信度也不等于反制授权。

## 1. 页面定位与审查范围

审查现有业务导航的八个页面及关键共享组件：融合感知、飞行计划、合法性研判、空域管理、告警事件、处置与处罚、运行统计、证据管理。聚焦影响实时响应的业务模块；不涉及所有样式、表单字段和后台菜单的逐项验收。

主要角色沿用值班人员、授权人员、处罚办理人员、分析/证据查看人员。核心对象沿用目标、研判、告警事件、风险事件、授权、交接、案件和证据；不新造统一对象替换现有主键。

成功终点应分别表达实时风险已解除、移送已完成、案件已办结，不能合成一个“完成”。

## 2. 上下游与生命周期

建议主链：探测更新 → 目标关联与告警聚合 → 自动研判 → 按策略分流 → 持续监测结果 → 实时处置完成；证据记录全程并行，移送和案件办理独立继续。

| 阶段 | 当前依据 | 优化方向（建议） |
| --- | --- | --- |
| 发现与关联 | 首页使用页面私有模拟源，进入处置要求明确的业务告警 ID | 首页目标、告警详情和授权绑定同一业务对象；模拟模式继续明确隔离 |
| 判定 | 后端已有规则引擎，正式模式的异常/非法结论可触发或合并告警 | 复用现有引擎，输出可自动办理/需复核的依据，不再要求人重复读取原始数据 |
| 处置 | 事件核实后才能写联系、观察记录；反制依赖观察和授权 | 常规动作依据策略自动推进；紧急与不确定分支单独处理 |
| 结果 | 观察由人工填写；通知、授权与案件有各自记录 | 持续消费目标、设备和外部回执，自动发现结果与失败 |

## 4. 逐模块优化逻辑卡

以下均为建议；沿用现有模块输入，新增自动化须由后端实现并验证。

- **S1**：收到目标更新即更新同一目标的结论、轨迹与时效；异常排序应综合风险和接近关键区域的趋势。无可靠位置时显示未知，不生成预计到达时间。验收：同一目标变化能传到 A1，地图与列表一致。
- **S2**：沿用明确关联的告警/事件主键，在当前上下文展示办理结果；无关联时保持“尚未关联”。验收：不会打开另一条看似相似的事件。不能用自动选择列表首项来减少点击。
- **L1**：消费正式规则结果，将数据冲突、证据不足或需人工裁定项送入例外队列；正常结果可查但不默认生成待办。验收：合法、不确定、异常三类均有明确去向。
- **L2**：自动整理规则命中、匹配计划、轨迹和未知原因；复核只要求填写机器无法确定的差异。复核不覆盖原始判定，更新后通知关联 A1；验收需证明没有把两种不同业务判断误合并成一次核实。
- **A1**：复用告警合并规则与事件状态，由服务端给出自动处理状态、需人工处理原因和可用动作。新判定到来后更新 A3/A4，过期结论不得继续用于执行。验收：多个入口读到同一版本，自动处理无需打开页面。
- **A2**：保留后端自动启停，人工补跟踪仅作为异常恢复；读取任务回执而非以按钮点击代表跟踪成功。验收：任务失败能够进入异常提示，不被显示为正常跟踪。
- **A3**：联系对象来自核实过的身份/计划关系，按配置模板与去重规则发送；观察消费连续航迹、空域关系和有效现场反馈。无联系人则转人工联系，目标失联则转未知。观察表单保留为纠正/补充入口；验收：发送、送达、观察结果分别有证据来源。
- **A4**：自动整理申请和交接材料。反制前复查目标是否仍适用、授权是否有效、设备是否可用；不能用纯前端“自动通过”。满足独立移送条件时进入 P2，不强制经过反制。验收：授权过期或目标已离场不使用旧申请继续执行。
- **P1**：页面首屏显示需决策的差异、方案与影响依据，标准材料自动填入；实际审批要求沿用有效策略。执行结果自动回读，急停保持可达。验收：指令受理、设备执行和现场风险解除分别展示。
- **P2**：材料汇集后按接收方配置自动准备，自动移送范围须明确；提交后持续查询或订阅送达及办理回执，超时/失败进入待办。验收：重试不重复移送，已移送不显示为已处罚。
- **F1**：计划开始、航迹出现/缺失、监测能力变化触发检查；检查正常时无需值班员逐次点击，有缺口则向配置的责任单位请求反馈。验收：没看到航迹不能直接断言未起飞。
- **F2**：对规则明确且数据有效的风险自动准备并按策略通知，对未知/冲突结果安排核验。验收：F2/R1 共享记录、发送去重，通知成功不等于风险解除。
- **R1**：监测更新与风险结论同步显示时间，持续重新评估空域关系。数据过期时保留历史并撤下“当前仍在场”的确定表述。验收：页面展示窗口不充当风险时效阈值。
- **E1**：上游判定、联系、观察、授权、回执关联证据引用；人工只处理缺失或额外现场材料。验收：从 P2 能追到正确证据，无材料则明确缺失，不伪造证据包完整。
- **T1**：消费过程时间戳与执行主体，生成响应耗时和人工介入统计；支持回查构成样本。验收：模拟/真实分开、无法测量值不填零。

## 8. 按钮与命令副作用

| 当前动作 | 当前生效与输出 | 建议变化 |
| --- | --- | --- |
| 人工核实 | 写核实记录、推进事件版本和状态 | 符合明确自动规则的情况由后端推进，人工核实用于例外 |
| 短信劝离 | 当前仅模拟发送，记录模拟送达 | 接真实联系人与通道后按策略自动发送，人工处理缺失与失败 |
| 记录观察结果 | 写人工目标情况、危险度与说明，影响反制条件 | 持续自动观察；人工纠正需说明差异依据 |
| 申请反制 | 新增授权申请；不等于执行设备 | 自动备齐申请材料，授权门禁在后端保留 |
| 移送处罚 | 冻结材料、创建交接；不等于罚款 | 条件满足后自动准备/按策略提交，失败保留记录 |
| 刷新记录 | 读接口，没有业务写入 | 自动订阅/增量回读为常态，保留手工重试 |

所有自动命令继续要求有效动作身份、数据范围、幂等、防并发、审计和失败处理，不能复用某个值班员的会话模拟“自动办理”。

## 9. 状态机与传播

当前无人机事件、研判复核、现场观察、授权、交接和案件分别有独立状态，不应全部揉进一个 state。

建议给用户提供派生进度：系统研判中、系统处理中、需要人工、处置受阻、实时风险已解除、后续办理中。它们是展示语义建议，最终字段/枚举待契约设计，不在本轮写入代码。

自动结论发生变化 → 追加判定记录 → 更新动作适用条件 → 同步列表/详情/地图 → 取消过期人工待办或生成异常待办。设备执行必须另有回执；飞离或失联时重新评估适用条件，不能沿用旧风险分数。

## 10. 自动研判与人工边界

| 场景 | 系统优先负责 | 人工介入条件 |
| --- | --- | --- |
| 身份与计划比对 | 按有效规则比对、给依据和未知项 | 身份冲突、数据不足、纠正结论 |
| 常规监测与证据 | 自动跟踪、规则评估、记录与汇集 | 设备失败、证据冲突、现场补证 |
| 常规通知 | 有明确联系人、模板、触发条件时按策略办理 | 无接收方、通道失败、需自定义沟通 |
| 反制/干扰 | 自动准备、校验、监测执行 | 授权策略要求审批、超出授权范围、异常接管 |
| 处罚 | 自动整理事实与移送材料、跟踪回执 | 责任认定、处罚决定及其办理程序 |

模型识别结果和规则结论分别记录，不能把“识别为无人机的概率”当作“违法概率”或“可以启动反制”。正式规则、模拟规则和人工改判均需可区分。用户要求的自动判定优先落实于数据充分、策略明确的环节，不强制对每份系统结果逐条人工确认。

## 11. 权限与范围

当前联系/观察写入同时要求 ALARM_VERIFY 与 HANDOFF_CREATE：这会让缺少移交权限的值班员无法只补一条现场观察。建议核对岗位需求后拆分动作权限，作为减少人工流转的配套优化；不直接取消服务端校验。

自动化使用明确的服务端执行身份和策略权限；值班员只处理可见范围内的例外；授权人员处理有效权限内申请；处罚办理沿用案件权限。策略配置位于同级后台仓库，业务前台仅显示状态与有权操作的动作。

## 12. 页面状态与异常

- 加载/空态：没有研判或没有记录不代表合法、无风险或已完成。
- 无权限/只读：保留可见结论和阻断原因，不能因隐藏菜单阻断已授权的设备业务动作。
- 数据过期/部分数据：明确最后有效时间与未知原因；保留历史，不据此断言目标飞离。
- 判定冲突/模型失败：持续采集已有可用数据，转例外核验，不能随机选一个结论继续。
- 处理中：保持同一事件与动作标识，避免刷新时重复提交。
- 并发/版本过期：回读最新结果，旧表单不得覆盖；自动任务也遵守版本规则。
- 超时/接口失败：保留同一幂等键并核查真实结果；显示待确认，不提示成功。
- 下游失败：交接、设备、短信分别标识失败；进入重试或人工处置，不回滚已真实发生的事实。

## 13. 接口与实施边界

复用已有 legality-evaluations、uav-events、advisory、disposal、handoff、risk 与 evidence 相关服务职责。自动判定/动作策略、持续观察及状态推送需前后端共同设计，本轮不指定未核对的新接口路径。

后端负责触发、判定、调度、持久化、去重、授权及回执；前端负责展示最新状态与人工介入。浏览器关闭后自动流程仍应运行。公共契约变动须同时核对业务前台和同级后台消费者。

## 14. 端到端验收建议

1. 正常报备目标进入：自动匹配并持续观察，不生成无必要人工核实待办；异常出现后能转正确分支。
2. 符合常规自动策略的目标：从探测到判定、通知、结果监测无需值班员逐步点击；全过程能追溯。
3. 目标劝离后离场：依据有效连续数据更新结果；目标数据中断时进入未知，二者不能混同。
4. 高风险但缺少有效授权：可自动备齐材料并通知授权岗，不执行超出授权的动作；授权后执行前再次核对适用条件。
5. 多设备/多次上报同一目标：沿用聚合规则，通知与移送不重复；首页、告警与授权保持同一关联对象。
6. 人工纠正自动判定：记录原结论、差异与最终值，后续页面读取最新有效判定；已发生动作不被抹去。
7. 浏览器关闭、接口超时、并发更新：后端流程可继续，回到页面可恢复；重试不重复产生业务命令。
8. 无反制但需移送：材料按条件移送；案件办结前不会显示处罚完成。
9. 同一风险从飞行计划与空域详情操作：共用核验、通知和回执，不因两处入口重复办理。
10. 效率统计：实测发现→判定→首个有效动作的 P50/P95、每事件人工操作次数、异常接管比例；同时看误判、误通知和漏报样本。未采集完整时间戳前不宣称达到秒级指标。

## 15. 优先级与待确认项

| 优先级 | 优化项 | 原因/依赖 |
| --- | --- | --- |
| P0 | 同一目标的数据与事件关联 | 首页当前是独立模拟源，生产闭环需要先打通 |
| P0 | 连续自动观察与数据时效 | 当前“飞离/危险度”人工填写是关键瓶颈，须接有效航迹与规则 |
| P0 | 自动分流与人工例外队列 | 当前事件处置以 CONFIRMED 为前提，须调整后端状态转换与记录来源 |
| P0 | 关键状态自动更新 | 本轮检查的告警/研判页以进入、筛选及写后回读为主；空域监测为 10 秒轮询，不能据此证明端到端实时性能 |
| P1 | 常规通知、计划到时检查与回执跟进 | 真实联系人、短信/通知渠道、触发与频控策略待接通或确认 |
| P1 | 授权准备、处罚移送与证据并行 | 复用现有授权/交接边界，减少事中填表和跨页办理 |
| P1 | 动作权限解耦 | 现场观察写入不宜无条件依赖移交权限，需核对岗位配置 |
| P2 | 自动化与响应效率统计 | 当前主要统计目标、飞行、风险和处置分布，需补过程指标 |

待确认：哪些通知可自动发送；哪些场景适用预先配置的授权、哪些仍逐次审批；观察结论的有效期和数据充分性；目标关联与真实通道的接入范围；各阶段响应时间预算。以上影响动作策略与契约，本轮不擅自填写阈值。
