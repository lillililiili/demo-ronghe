## 1. 结论

系统目前已经不是纯前端 Demo：认证权限、系统管理、设备运维、目标轨迹、飞行计划、航线、空域和已保存合法性研判均已有后端数据模型、权限控制、REST API、自动化测试及部分前端接线。

但系统仍不能按“生产可上线平台”验收。真实设备和业务数据源、生产规则、反制与通知渠道、证据保管、跨域工作台、统计大屏等关键能力尚未闭环；当前阶段 4 的告警/风险后端已形成较完整草稿，但前端存在保留原页面结构的阻断问题，且尚未完成真实 PostgreSQL、浏览器和全量集成验收。

按两个维度估算当前程度：

| 维度 | 估算 | 含义 |
| --- | ---: | --- |
| 本地开发/演示闭环 | 约 60%–65% | 已具备多个真实后端读取切片，可在 local/test 固定数据下演示主要查询；部分后续页面仍依赖 Mock |
| 生产上线准备度 | 约 30% | 安全与数据底座已形成，但真实来源、外部系统、规则、证据、运维和全链路验收明显不足 |

以上百分比是按业务模块和上线门槛综合估算，不是按代码行数或测试数量计算。

## 3. 已提交并可依赖的能力

### 3.1 工程与交付底座

- 前端：Vue 3、JavaScript、Vite、Naive UI、原生 CSS。
- 后端：Java 17 编译目标、Spring Boot 3.4.5、MyBatis、Flyway、Maven Wrapper。
- 数据库：PostgreSQL 16/PostGIS 3.5 设计与部署样例；H2 只承担快速测试。
- 已有 GitHub Actions：前端执行 `npm ci`、源码扫描、反向校验和构建；后端执行测试、身份系统定向测试和打包。
- 已有 Docker Compose、Nginx 和 integration 数据库示例。
- local/test 合成数据受 profile 与显式开关双门禁；生产环境不应自动生成演示数据。

限制：本地 `main` 尚有 22 个提交未推到 `origin/main`，所以远端 CI 不一定覆盖当前本地完整基线；阶段 4 工作区草稿更没有进入远端 CI。

### 3.2 身份、权限与系统管理

已具备：

- 登录、退出、当前用户、会话过期与强制改密。
- 用户、角色、菜单、动作权限、组织、行政区域和数据范围管理。
- 动作权限与菜单可见性分离，服务端不根据角色名推断业务权限。
- `NONE/ASSIGNED/ALL` 范围模型；业务读取使用组织与区域的精确元组，越权详情按 404 隐藏。
- 权限版本变化使旧会话失效，用户重新登录后获得新权限版本。
- 成功/失败审计和写请求幂等基础组件。

仍缺：生产账号、组织、区域、岗位矩阵和身份接入方式的正式资料。

### 3.3 设备运维

已具备：

- 设备列表、详情、监测总览、设备树、最新状态、历史曲线和事件增量查询。
- 重启命令、命令状态、调测任务、回执与超时处理的开发闭环。
- 持久化 Outbox Worker，支持领取、退避重试、超时与服务重启后的继续扫描。
- `MockAdapter` 与 live 适配器注册机制；已有 T02/兼容机扫雷达 TCP v3.0.0、固定式四通道网络控制器 v2.0 的只读接入代码。

仍缺：设备方正式协议原件核验、现场网络与凭据、真实设备联调、真实控制回执、恢复判据、停止/急停和生产授权条件。因此当前“重启成功/调测通过”主要是隔离模拟证据，不能当成真实设备验收。

### 3.4 目标、轨迹与态势

已具备标准接口：

```text
GET /api/v1/targets
GET /api/v1/targets/{target_id}
GET /api/v1/targets/{target_id}/tracks
GET /api/v1/tracks/{track_id}/points
```

目标、详情、轨迹、轨迹点和 `total` 使用同一权限范围；未知位置不补 `(0,0)`。态势页已从标准 API 读取目标和轨迹，不在失败时回退 Mock。

仍缺：生产来源持续摄取、多源关联/融合算法、真实时间基准、坐标和高度资料，以及目标合并规则。

### 3.5 飞行计划、航线、空域与合法性依据

已提交接口覆盖：

- 飞行计划列表/详情。
- 航线列表/详情/版本。
- 空域列表/详情/版本。
- 飞行计划与空域的时间、空间和高度冲突事实。
- 已保存合法性研判列表/详情。

数据按版本保存，历史计划引用精确航线版本；未知边界策略或 AGL/AMSL 换算依据时保持 `UNDETERMINED`。前端计划页和合法性页已接标准 API。

仍缺：权威计划/航线/空域同步，生产维护入口，正式规则版本和自动研判。当前能力是“读取已保存事实与结论”，不是“平台已经能对生产飞行自动判合法”。

2. 告警事务回滚、双用户并发的阻断测试。
3. 最终独立审查清零 P0/P1。
4. 真实 PostgreSQL 16/PostGIS 迁移、约束和并发验证。
5. 全量 Maven test/package、前端完整检查和真实浏览器验收。
6. 顶栏未处理告警数字改读标准 API。
7. 阶段 4 验收报告与领导统一提交。

## 7. 生产上线前的关键缺口

1. **真实数据与协议**：设备、目标、计划、空域、告警和风险的权威来源、脱敏样例、字段/时间/坐标/高度定义。
2. **真实设备联调**：网络、凭据、白名单、状态和错误码、控制限制、回执、恢复与急停。
3. **生产权限资料**：真实组织、区域、岗位、敏感字段和跨区规则。
4. **正式业务规则**：告警合并、合法性、风险、调测阈值、统计指标及规则版本管理。
5. **外部交接渠道**：上级、处罚、视频和其他系统接口；发送受理、送达、回执与失败标准。
6. **证据体系**：真实文件来源、哈希、下载权限、访问审计、冻结、保留和销毁制度。
7. **统计一致性**：同权限、同时间窗、同数据库快照的指标与明细。
8. **生产运维**：容量、备份恢复、监控告警、密钥管理、网络隔离、发布回退和验收环境。
9. **最终全链路验收**：PostgreSQL/PostGIS、并发、故障注入、浏览器、角色矩阵、断后端、刷新恢复和真实外部适配。

## 8. 恢复开发时的建议顺序

1. 先修阶段 4 两个前端页面的结构回归，只做渐进式 API 接线。
2. 补齐告警审计失败回滚和双用户并发测试。
3. 由只读审查者复核阶段 4，清零 P0/P1。
4. 领导完成顶栏告警数、真实 PostgreSQL、全量后端、前端和浏览器验收。
5. 写阶段 4 验收报告并由领导在 `main` 统一提交。
6. 再开始阶段 5 工作台/交接，之后开始阶段 6 统计/大屏。

- 登录、改密、用户/角色/菜单权限和退出。
